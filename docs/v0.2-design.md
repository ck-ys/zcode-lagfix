# zcode-lagfix 设计（v0.2 起，2026-11-11 v0.3.0 修订）

## 一、为什么做

实测基线（用户机器，07:51 那段）：静止时帧 P95 36ms、长任务 0~1 次/5s；流式输出时
帧 P95 115~133ms、单帧最长 788ms、**每 5 秒 24~34 次长任务（最长 736ms）**。
病根是宿主每 ~30ms 提交一次投影并通知所有订阅者，React 在
`useSyncExternalStore` 回调里整树重渲染，把主线程切碎。

## 二、目标 / 非目标

- 目标：把流式期间的通知频率降下来，减少长任务；进入大历史会话时避免一次性全量补拉；任何时刻可逐项关掉回到 v0.2 行为。
- 非目标：不改宿主数据、不改模型上下文、不改持久化、不拦正常上翻分页（`loadOlder`）。

## 三、功能清单与开关（全部可在面板里开关）

| 功能 | 默认 | 开关 | 状态所有者 |
|---|---|---|---|
| 观测（rAF 帧、longtask、投影提交） | 开 | `settings.observe` | renderer |
| 角标文字显示 | 开 | `settings.badgeText` | renderer |
| 角标整体显隐 | 开 | `settings.badgeVisible`；隐藏后 `Ctrl+Alt+L`（Mac `Cmd+Alt+L`）或 `__lagfixSettings()` 重新开设置 | renderer |
| 黄/红阈值（帧 P95 ms） | 50 / 100 | `settings.warnMs/badMs`（约束差 >=1） | renderer |
| 采集间隔（主进程拉取） | 5s；可选 1/3/5/10/30s | `settings.collectSec`（1–120s）→ 随样本回传 | main（重建定时器） |
| **修复：订阅通知节流** | **开 120ms** | `settings.throttleOn/throttleMs` | renderer（包装 store 的 subscribe） |
| **v0.3 自适应窗口** | **开** | `settings.adaptiveOn` | renderer（帧 P95 ≥80/≥150ms → 200/300ms，1s 缓存） |
| **v0.3 切会话冷静期** | **开** | `settings.switchGuardOn` | renderer（切会话后 10s 内窗口 ≥250ms） |
| **v0.3 后台降频** | **开** | `settings.hiddenSkipOn` | renderer（`document.hidden` 时最多 1s/次，回前台补一次） |
| **v0.3 大会话保护** | **开** | `settings.bigSessionOn` | renderer（包装 `loadAllOlder`，行数 ≥800 且未全载时拦截） |
| 角标位置 | 只在主页面：浮在输入框卡片上方（不压输入区与工具行）；设置页/被遮挡/无可用输入框时隐藏 | fixed 定位，每秒按 `.chat-composer-input-surface` 的 rect 同步；`closest(settings-page…)` + `elementFromPoint` + 取最靠下 | renderer |
| 日志预算 | 50MB | `settings.logMaxMB`（20/50/100/200）→ 随 collect 回传 | main（`sweepByBudget`） |
| 重启 ZCode | —（一次性动作） | 面板按钮（二次确认） | renderer 置内存标记 → main `app.relaunch()` |
| 检查更新 | 无 | **禁用**（尚无更新源） | — |

设置存 `localStorage["lagfix.settings.v1"]`（只此一个键，不碰宿主键），多窗口靠
`storage` 事件收敛（否则两个窗口各报一个 collectSec，主进程每轮重建采集泵 →
永久抖动）。主进程需要的 `collectSec` / `fix` / `restart` 随
`__lagfixCollect()` 的 payload 回传，loader 落盘 `~/.zcode/zcode-lagfix/settings.json`
（原子写，写成功才记为"已落盘"）供排查。

## 四、节流的实现与边界（v0.2.1 按三审结论修正）

```
findStoreFrom(anchor)
  └─ fiber 向上 50 层
       ├─ memoizedProps：按 store/lease/binding/... 字段名做 depth<=3 搜索
       └─ memoizedState：hook 链表逐节点（{memoizedState,next}），
            实测真实链路 = binding.lease.store；zustand create() 返回 function
            也要认（只认 object 会漏掉主 store）
  命中后：store 自有 subscribe 就包实例，否则包原型；只包这一处。
          真实宿主 ConversationProjectionStore 的 subscribe 是**原型方法**，
          所有会话实例共享同一个被包方法 —— 所以 wrapper 内必须用调用者的
          `this` 登记监听者（`origSubscribe.call(this, wrapped)`），
          绝不能捕获某个实例：否则切会话后 B 的监听者会注册进 A，
          B 的对话区永远不刷新（GLM-5.3 终审 P0）。

subscribe(cb, ...)
  ├─ 只接管 arguments.length === 1 且 cb 是函数
  │    （带 selector 的 subscribeWithSelector 必须原样放行）
  └─ trailing 必达节流：
       窗口时间戳 win.last 按**实例**分（WeakMap 键 = subscribe 的 this），
       不是按订阅，也不是全类共享：
         · 按订阅计时 → React 19 每次 commit 用新的内联箭头重订阅，窗口被清零；
         · 全类共享   → 分屏时一个 pane 的通知会把另一个 pane 推迟 120ms
       距上次回调 >= throttleMs → 立即
       否则最多挂一个定时器，到期必须补发一次（不是 debounce）
```

- 找不到 store → 面板显示"待生效（未找到 store）"，每 3s 重试，最多 20 次后停；
  不报错、不伪造。
- 宿主换代**换了原型**（新 class/新 store 实现）→ 看门狗每 5s 重新核对目标：
  旧目标还原、新目标重新包装。同一原型上的新实例不需要换绑——它们继承的
  就是被包后的方法，且监听者按 `this` 落到各自实例。
- 关闭：`releaseThrottle()` 把 `target.subscribe` 还原为保存的原函数；
  已订阅出去的 wrapper 每次回调都读 `settings.throttleOn`，关掉后立即恢复即时通知。
- 自禁用：`settings.throttleOn = false`（仅内存，不落盘）+ `releaseThrottle()`，
  且 `applyThrottle`/`reloadSettings` 一律 `state.dead` 短路——storage 事件也不能
  把节流装回去（那时角标已移除，用户看不见也关不掉）。
- 一键还原：控制台 `window.__lagfixOff()`。
- 同一实例有多个订阅者（SessionPane / PlanDetail / Subagent 目录）时，一次通知里
  首个立即触发、其余并入同一个 120ms 尾沿，之后同拍收敛；稳态不饥饿。

## 四之二、v0.3 性能增强（四项，全部可关）

```
通知路径（per store 实例）
  store.emit() → wrapper
    ├─ throttleOff        → 直通（回到 v0.2 前行为）
    ├─ document.hidden    且 hiddenSkipOn → 最多 1s 合并一次，回前台补发
    └─ 窗口 = throttleMs
         ├─ adaptiveOn 且 帧P95≥80/≥150 → max(窗口, 200/300)   [1s 缓存]
         └─ switchGuardOn 且 切会话<10s   → max(窗口, 250)
      距上次通知 < 窗口 → 合并到唯一定时器；到期必达

补拉路径（per store 原型/实例）
  loadAllOlder()
    ├─ bigSessionOn 且有分享意图/分享弹层 → 放行
    ├─ bigSessionOn 且 totalCount≥800 且 window.length<totalCount
    │     → bigBlocked++；返回 {status:"not-enough-queries"}（宿主视为终态，不重试）
    └─ 其他 → 调用原实现
```

- 唯一所有者：设置值在 renderer（`lagfix.settings.v1`），主进程只读 collect payload 里的
  `logMaxMB`；补拉守卫只包一层，`releaseLoadAllGuard()` 按保存的 `orig` 还原，重复包装幂等
  （`__lagfixLoadAll` 记录原始引用）。
- 分享放行有两道：分享入口点击后 15s 意图位（弹层还没挂载时也不误拦），以及
  `share-popover/selection-dock/confirmation-dock/permission-picker` 的 DOM 标记。
- 角标可见性：`composerUsable()` 依次判 `isConnected` → `closest(settings-page 等)` →
  `closest([data-root-workspace-surface="inert"],[inert])`（宿主设置页是把 workspace 整体标 inert 盖上去的）→
  rect 在视口内 → 顶层命中测试。命中测试必须**跳过自家浮层**（探测点可能落在
  角标/统计卡/设置遮罩上），用 `elementsFromPoint` 取第一个非自家节点；多个可用时取
  `rect.top` 最大（聊天输入框总在视口下半部）。一个都没有 → `positionBadge()` 返回 false →
  角标 `display:none`，不再有"退回右上角"的分支。
- 不挡排队：`positionBadge()` 每次都查 `[data-testid="v4-queue"]`；角标现在浮在输入框
  顶边上方（`surface.top - 26 - 6`），若与排队面板竖向相交，就整体让到队列上沿
  （`queue.top - 26 - 6`）；若上方连 8px 余量都没有，直接不显示。队列的
  「立即发送/编辑/删除」与输入区工具行永远不被覆盖。
- 日志预算：主进程 `sweepByBudget()` 在**收到首个 renderer 样本（含真实 logMaxMB）后**
  开始检查，之后每 60s 一次；启动时只按天龄清 14 天前的观测日志，不按默认 50MB 删，
  避免用户设了 200MB 却在重启瞬间被默认值误删。按 mtime 从旧到新删，跳过当天的
  活动 `observe-YYYYMMDD.jsonl`；上限变化时立即执行一次。

## 五、重启 ZCode 的时序

```
用户点「重启 ZCode」→ 5s 内再点一次确认
  → state.restartRequested = true（**不写 localStorage**）
  → 下一个采集周期 payload.restart = 1（最多 collectSec 秒）
  → main: honorRestart() → app.relaunch() → app.quit()
            （宿主 before-quit 要回收会话/扩展子进程树；15s 仍未退才 app.exit(0)）
  → 新进程：restartRequested 天然为 false（内存态已丢）
```

不落盘是为了从根上排除"重启后读到旧标记 → 无限重启"；`restartHandled` 只允许
一个进程生命周期内执行一次。等待时间 = 当前采集间隔（默认 5s，最长 120s）。

## 六、失败模式

| 情况 | 表现 | 兜底 |
|---|---|---|
| 找不到 store | 面板显示"待生效" | 不影响任何宿主行为；3s×20 次重试 |
| store 换实现（升级） | 找不到/签名不符 | 不包装；面板可见 |
| 节流导致渲染滞后 | 最多 120ms 延迟 | 关开关 / `__lagfixOff()` |
| 定时器泄漏 | 单个订阅最多 1 个 timer | unsubscribe 时清理 |
| renderer 自禁用 | 角标灰、移除面板 | 包装已还原，开关置 false |
| 重启请求丢失 | 按钮停在"已请求" | 下次采集重发（标记仍在内存） |
| 多窗口设置冲突 | storage 事件收敛到同一份 | 无抖动、无写回环 |

## 七、验收

1. 设置面板可开可关，刷新/重启后记住。
2. 角标浮在主页面输入框上方：设置页、被遮挡、没有可用输入框、上方无余量时隐藏；多个 composer 同时挂载时取最靠下的可见者。角标整体隐藏后，`Ctrl+Alt+L` 或 `__lagfixSettings()` 必须仍能打开设置。
3. 悬停/点击出统计浮层（档位图例 + 最近 18 轮柱状图）；只有齿轮打开居中分类设置。
4. 帧 P95 14ms 时配色必须是绿色（最近 30s 最差帧判定），不能因历史峰值长期报红。
5. 节流开：流式期间长任务次数与帧 P95 明显下降；关：回到基线。
6. 关掉节流后 `subscribe` 与原函数同一引用；`__lagfixOff()` 同时还原 `loadAllOlder`。
7. 同一 store 上反复 unsubscribe/subscribe（模拟 React 19 重订阅），窗口不归零。
8. 大会话保护：totalCount ≥800 且未全载时 `loadAllOlder()` 返回 `not-enough-queries`，原实现零调用；分享入口点击后放行。
9. v0.3 四项各自关掉后行为回到 v0.2（互不牵连）；切会话 10s 后窗口自动回到固定值。
10. 日志超过上限时从最旧文件删起，当天活动文件保留；面板显示实际路径与当前上限。
11. 面板「检查更新」为禁用态；「重启 ZCode」二次确认后 payload.restart=1。
12. 任何开关都不影响对话内容、搜索、复制、手机远控。
