00 · 一句话

最疼的一段不是 3000 行以上的滚动，而是切回长会话后从 120 行回填到 3000 行的补页潮：26 秒内 44 次 loadOlder、累计 4903ms，单次最高 575ms，期间还叠了一个 968ms 的 flush 长帧。v0.4.4 只做一件事：在切换后的 30 秒窗口内，把无参补页的每页 60 行提到 120 行，减少调用次数和中间提交次数；不跳过、不合并、不删数据、不隐藏内容，默认关闭，A/B 过线才考虑转默认。

1.3 为什么不是 O3 下探门槛

O3 当前门槛是「窗口 >3000 行 + 距滚动 ≤2s + 600ms 间隔」。22:18 的补页潮到 3003 行才刚过线，本轮 allowed=5 / skipped=0；22:20:26 的 651ms 发生在 840→900 行，远低于门槛。全天 1294 次放行 / 18 次跳过，说明大部分调用根本没进入降频区间。

把门槛直接下探到 1000 行会改变所有会话的普通上翻行为，而且 O3 的跳过是「不发这次请求」，用户在上翻停下时可能留下未加载缺口。它不该作为第一枪。

03 · 选定方案：B 的完整行为

3.1 设置与默认值

  • 新增设置键 switchBackfillPageOn，默认 false，面板放在「性能 → 实验」。
  • 用户语言：「切换后大页补页 · 实验」——切换会话后的 30 秒内，每次多取一点历史（60 → 120 行），减少来回次数。30 秒后自动恢复。
  • 关闭时行为与 v0.4.3 完全一致；不改变任何默认路径。

3.2 触发条件（全部满足才走 120）

  1. settings.switchBackfillPageOn === true，且 !state.dead；
  2. 调用方没有传参数（arguments.length === 0）；显式参数一律原样直通；
  3. 距离最近一次真实会话切换 ≤ SWITCH_BACKFILL_WINDOW_MS = 30000；首次打开/首次挂载不算；
  4. 切换前后的 sid 都是真实会话：非空、非 draft 占位。新建会话、草稿态、空白首屏不触发；
  5. readLoadedRows(this) 返回数字，且 ≤ 3000；行数不可读或已超过 3000 时直通，不猜；
  6. 当前调用的是当前主 store 实例的 loadOlder，不是共享原型，不是隐藏会话。

切换识别复用现有 attach / MutationObserver 的 sid 变化信号；因此需要观测处于开启状态（observe=true）才能发现新切换。它不依赖 switchDiagOn 或 scrollDiagOn：只要 observer 活着，时间戳就会写。暂停观测时不新开窗口（MO 已断开），已开的窗口继续走表并可自然过期，计数继续累加，样本暂停上报；恢复后按新的 attach 重新识别。

3.3 调用规则

// callOrig 内部，伪代码
if (!settings.switchBackfillPageOn || state.dead) return orig.apply(self, args);
if (args.length !== 0) return orig.apply(self, args);
if (!switchBackfillAt || performance.now() - switchBackfillAt > 30000) {
  countPassthrough(); return orig.apply(self, args);
}
var rows = readLoadedRows(self);
if (rows === null || rows > 3000) {
  countPassthrough(); return orig.apply(self, args);
}
countApplied();
return orig.call(self, 120);   // 宿主协议上限 200，默认 60
  • 不跳过任何一页：只是把这一页从 60 行变成 120 行；内容不会丢。
  • 不合并、不缓存、不删除、不改序；不写 store；不碰 loadingOlder/canLoadOlder。
  • 保留 this、返回的 Promise 引用、同步异常、显式参数；与未包装时的语义一致。
  • 与 O3 同时开时：O3 的跳过优先生效；被 O3 跳过时不调用原方法、不计 page 生效；放行的调用再走 120。
  • 暂停观测（observe=false）时，已开的窗口仍生效并继续计数（与 O3 的缓解语义一致），只是不写明细/不上报样本；暂停期间不新开窗口，恢复后继续。
  • scrollDiagOn=false 时仍生效：包装安装条件加 switchBackfillPageOn，不依赖观测。

3.4 切换窗口的记时

  • 在 recordSwitch() 入口、switchWatchActive() 门控之前写 switchBackfillAt = performance.now()；只写时间戳，不做 DOM 扫描。
  • 只有前后都是真实 sid（非空、非 draft）才写；首次挂载（from 为空）不写，避免把启动首屏算成切换；新建会话/草稿态也不写。
  • 同一会话重新挂载（sid 未变）不重置窗口。
  • 150ms 内 A→B→A 快速往返：窗口会按最后一次 sid 变化重置；不产生伪切换记录，但大页窗口按用户实际切回处理。
  • 暂停观测时 MO 已断开，不新开窗口；已开的 30s 窗口继续走表，过期后自然失效。恢复观测时若 sid 已变，按新的 attach 开新窗口。
  • 切换瞬间若新 store 还没找到：沿现有 sid 变化路径立即尝试 applyThrottle()（条件加入 switchBackfillPageOn），失败则由 5s 看门狗重试；窗口仍从切换时刻起算，不因晚安装而重新计时。

3.5 计数与样本

  • 新样本字段 switchPage，只在开关开时上报，关闭为 null：
字段含义
limit固定 120
applied真正用 120 调用原方法的次数
passthrough开关开、无参，但窗口过期/行数 >3000/行数不可读，按原样调用的次数
installed包装是否装上；false 时 applied/passthrough 不可用，不伪装成 0
  • switchPage 是健康检查/诊断，不是 A/B 的唯一口径；A/B 用切换记录的窗口指标（见 05）。
  • 切换记录新增 loadOlderRows30s：切换后 30s 内成功补页实际增加的行数合计。它和 loadOlderN30s / loadOlderMs30s 一起，支持「每 1000 行调用次数/耗时」的归一化比较，避免每次切换起始行数不同（120/300/840/900）污染 A/B。
  • 计数随包装器生命周期：关→开、换 store、自禁用、__lagfixOff() 清零；暂停观测不清零，计数继续累加，只是样本暂不上报。
  • 显式参数的调用不计入 applied/passthrough，避免污染 A/B。
  • 报告新增「切换回填页（实验）」段：显示 120 行、生效/放行次数、包装是否装上；关闭、旧样本、未装上分别明示，不回退旧计数。切换段同时打印 30s 内补页次数 / 行数 / 耗时。

08 · 拍板时的默认取舍（可改）

① 页大小 120 而不是 200：120 是 O8b 使用过、宿主协议内的参数，单页放大 2 倍；200 虽然能把 44 次压到 13 次，但单次帧和锚点风险更大。先 120，过线再讨论 200。
② 只限 ≤3000 行：超过 3000 行后交给 O3（如果用户开启）；不在本实验里继续放大页。
③ 首次挂载不算切换：启动首屏保持 60 行原行为；只优化用户主动切会话后的回填。
④ 暂停观测：已开的 30s 窗口仍生效并继续走表；暂停期间不新开窗口（MO 已断开），恢复后按新的 attach 识别。与 O3 的缓解语义一致；如果希望「暂停=全停」，拍板时改。
⑤ A/B 时关 O3：否则分不清是 120 行还是跳页带来的下降。

09 · 构建前已收口（builder check）

写规格前，把实现者最容易猜错的五个点固定下来；这些是设计决定，不是新需求：

  1. 与观测开关的关系：切换识别复用现有 attach/MO，因此需要 observe=true 才能发现新切换；不依赖 switchDiagOn/scrollDiagOn。暂停观测不新开窗口，已开窗口继续走表并过期，计数继续累加，样本暂停；恢复后按新的 attach 识别。不新增暂停期 sid 监听器。
  2. A/B 主口径：用切换记录的 loadOlderN30s、loadOlderMs30s，并新增 loadOlderRows30s 做「每 1000 行」归一化；switchPage.applied 只做健康检查。A/B 固定 observe/switchDiagOn/scrollDiagOn 全开，不暂停。
  3. 占位 sid：只有前后都是真实 sid（非空、非 draft）才开窗口；新建会话、草稿态、空白首屏都不触发。
  4. 晚安装：sid 变化时立即尝试 applyThrottle()（把 switchBackfillPageOn 加入条件），失败继续走 5s 看门狗；窗口仍从切换时刻起算。A/B 要求 installed=true 且 applied>0，否则该轮无效。
  5. 可复现性：不强制重启 ZCode；用每 1000 行归一化抵消起始行数差异，但必须同一会话、同一段历史、同一滚动路径。若宿主未来不再按 60 行分页或 rows.window 形状变化，实验停用并如实报告，不猜。
