1.3 【v2 新增】O3 失灵的真因：两套触发口径

现象：今早 08:41:08 样本里 O8b downgraded=4（窗口 >3000 且 600ms 内连续 → 降回 60 行），同一样本 O3 pace 0 放行 / 0 跳过——同样的调用，一个机制看见了，另一个完全没看见。

代码证据：两者用不同口径判定「滚动触发」——

  • 明细分类 classifyLoadOlderTrigger()：距 lastScrollAt 时间窗口内即记 scroll（时间口径，宽）；
  • O3 跳过门控（包装器入口）：要求 paceInScrollDispatch——只在 scroll 监听器同步派发的微任务窗口内为真（同步口径，窄）。

结论：3.18.2 上宿主的 loadOlder 已不在 scroll 事件同步派发里触发（虚拟化/rAF 异步化），O3 的同步门控永不命中。这不是「没触发」，是失灵。v1 只归因到「切换清零计数」，是第二层原因；两层都要修。

1.4 【v2 新增】既有 switchGuardOn 在场，通知下限杠杆被证伪

v0.2 起 switchGuardOn（默认开）已在做「切会话后 10s 内通知下限 250ms，避让首屏水合」。今早 530ms 切换帧发生时它一直开着——530ms 仍然发生，说明切换成本在挂载/布局/补页，不在通知密度。

推论：v1 提出的 P1「切换期保护（把通知下限提到 400ms + 关 mask + 跳角标）」与既有机制重叠，且主要杠杆已被实测证伪，不应在本版抢跑——先做 P0 归因，确认卡在哪一段（挂载？布局？补页潮？）再设计对应的保护，推到 v0.4.4。

1.5 两个被切换掩盖的观测缺陷

  • O8b 补页批量：两天实机 applied=0。连续上翻全部落在 600ms 窗口内被降回 60 行（今早 downgraded=9），唯一能生效的「单次慢速上翻」场景几乎不存在 → 按门槛应退役。
  • O3 计数清零：page.installed=false 的 6 个时间点与 sid 变化点逐一吻合——每次切换清零计数，A/B 证据在高频切换用户的日志里活不过一个切换周期。
