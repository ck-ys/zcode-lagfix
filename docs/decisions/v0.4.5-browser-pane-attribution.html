00 · 一句话

稳定打开内置浏览器时，宿主 UI 帧是平滑的（P50/P95 中位 6ms），但宿主主线程仍有 130–337ms 的 LoAF 长帧；LoAF 来自宿主 renderer，看不到 guest 内部，不能直接说成「页面自己有长帧」。200–267ms 的宿主尖峰集中在回前台/页面加载，不是浏览器常开态。当前样本只有 hidden、pane、refocus，分不清「选中的浏览器 guest」「窗口无焦点」「回前台」。v0.4.5 只做一件事：补两个只读字段并把宿主帧与宿主 LoAF 并列报告；不改任何行为、不新增开关、不声称已优化 guest。

注意：这里两条回前台样本的 sinceVisibleMs 分别是 115ms、2375ms 和约 2740ms。原先拍板页写的「2 秒窗口」会漏掉 2375ms 的 200–267ms 尖峰，把它算进稳定浏览器；实现时把归类窗口改为 3 秒，并在报告里对 3001ms 以上才回到稳定组。这个修正只改报告分组，不改采集与保护逻辑。默认采集间隔是 5 秒，回前台后第 3–5 秒的样本仍可能含尖峰；帧 P95 又是 30 秒窗口、LoAF 是本采集周期值，所以报告必须明示“3 秒排除不等于窗口内完全干净”，有切换记录时再排除同窗口切换后 30 秒内候选。归因启用且文档可见时，observer 以启用时刻作为可见起点，避免用户从不切出再切回时稳定组永久为空；启用后前 3 秒仍按回前台窗口排除。

1.3 当前口径缺什么

  • hidden 只说明页面是否隐藏；窗口被别的应用盖住、DevTools 抢焦点、或窗口未聚焦时，它仍是 false，但 rAF 可能被节流或帧间隔异常。
  • pane.open 只说明侧栏开着，分不清浏览器、预览、终端；报告把「面板开」的样本合成一个 P95，浏览器样本和普通侧栏混在一起。
  • 报告目前主要看 frameP95，没有并列 frameP50；稳定段 P50/P95 都是 6ms 时，单看 P95 容易被回前台尖峰带偏。
  • 没有「宿主 LoAF」与「宿主帧」的并列结论；laf.max=337ms 和 frameP95=6ms 同时出现时，当前报告不会告诉我们这是宿主主线程长帧，更容易误读成 guest 页面内部。

03 · 选定方案 A 的完整行为

3.1 新增样本字段（只读）

字段类型取值说明
focus boolean | null document.hasFocus()；异常/不支持为 null 窗口是否有前台焦点。它不等于 hidden：窗口可见但被其他应用盖住、DevTools 抢焦点时可能是 false。
webview 0 | 1 | null browser-use 选中 tab 查 [data-browser-use-tab-id]:not([aria-hidden="true"]) webview；人类浏览器选中 tab 查 [data-side-pane-content-slot] [data-slot="tabs-content"][data-state="active"] webview[data-testid="browser-webview"]；命中为 1；有 browser-use tab 但没有选中 guest 为 0；旧宿主无 tab 标记时只认浏览器专属 data-testid/partition 且有布局盒的 guest，不再裸查 document.querySelector("webview")；查询异常为 null 判断当前选中的浏览器 tab 里有没有 guest，不读 URL、标题、页面内容、历史。未选中的 tab 仍 forceMount；插件 UI、奖励页、预览也是 <webview>，裸查会把它们误算成浏览器，因此两条浏览器路径都要用专属标记。
frameP50 number | null 已有字段，不改采集 本版只让报告把它和 frameP95 并列显示，避免只看 P95。

不新增设置键，不新增 DOM 属性，不新增监听器。正常样本每采集周期读一次 document.hasFocus() 和浏览器 tab/guest 结构；按当前约 5 秒一个样本，成本可忽略。暂停、自禁用、异常兜底样本带 focus:null, webview:null，保持 schema 稳定；旧样本没有这两个字段。`__lagfixOff()` 不等同于暂停/自禁用，仍按正常采集写入字段。

3.2 采集规则

  • 只在正常采集路径读取；state.dead、!settings.observe、异常兜底路径不读 DOM，直接写 null。
  • focus：typeof document.hasFocus === "function" 时调用，异常按 null，不抛给宿主。
  • webview：先查选中的浏览器 tab 内 guest，异常按 null；有 tab 标记但没有选中的 guest 返回 0；不遍历全部 DOM，不读 src。
  • 不根据 webview=1 自动认定「宿主或 guest 一定在忙」；报告必须同时看 pane.open、focus 和宿主 LoAF。
  • 不改变任何开关默认值，不改变样本间隔，不新增 setTimeout/setInterval。

3.3 报告规则

新增 print_browser_diag(rows)，放在 print_pane_diag(rows) 之后。它只做分组统计，不下「已优化」结论。

分组条件输出
稳定浏览器 webview==1 且 paneOpen===true 且 focus===true 且 !hidden 且 !miss，refocus.sinceVisibleMs 是数字且 >3000，该样本自己的 paneDiagOn 不是 false；有切换记录时再排除同窗口切换后 30 秒内候选（按 win 分桶，A 窗口不误伤 B） 样本数；frameP50 / frameP95 中位；长任务中位/最多；宿主 LoAF 最长。例：宿主帧 P50/P95 中位 6/6ms；长任务中位 8；宿主 LoAF 最长帧 337ms
回前台窗口 focus===true 且 refocus.sinceVisibleMs 是数字且 ≤3000 样本数；P50/P95 中位；长任务；与稳定浏览器分开，不混算。2375ms 的实测尖峰也归到这里。
无焦点 focus===false 且 !hidden 样本数；P50/P95 中位。明确写「窗口无焦点，不计入浏览器性能结论」。
没有选中的 guest webview===0 且 paneOpen===true 中性说明「预览/终端等普通面板也会如此」，不推断为「没有卡顿」，也不说成宿主结构变化。
旧样本 没有 webview 字段 提示「本版本未记录浏览器标记（v0.4.5 前的旧样本）」，不回退成 0。
  • 给 print_pane_diag 的 open/closed 分组补 frameP50 中位，和现有 P95 并列；旧样本没有 P50 时显示 -。
  • 结论句只在证据齐全时打印：稳定浏览器 frameP95≤16ms 且 laf.max≥100ms → 「宿主 UI 帧平滑，但宿主主线程仍有 ≥100ms 长帧；来源未分（guest 合成/宿主定时器/样式），不能据此认定是 guest 页面内部」；稳定浏览器 frameP95>50ms 且 laf.max≥100ms → 「宿主也被拖慢，需继续分回前台/切换/浏览器面板」。
  • 不把 webview=1 直接写成「浏览器页面卡」，也不把宿主 LoAF 写成 guest 内部长帧。
  • 不改现有滚动、补页、切换、回前台段落；本段是新增，不替换旧结论。

05 · 验收

本版验收的是「归因正确」，不是「变快」。不设性能过线门槛；只要字段、分组、旧样本兼容和清理路径正确，即可发布。
层必须验证
observer 冒烟 focus=true/false 两种夹具；webview 存在/不存在/查询抛错；正常、暂停、自禁用、异常兜底四条路径字段为 null 或正确值；旧样本无字段不报错。
报告 稳定浏览器分组、回前台 3 秒分组（含 2375ms/3001ms 边界，且不输出 LoAF）、sinceVisibleMs=null 时窗口不可判断且不进入稳定组、归因启用且可见时 sinceVisibleMs 为数值、无焦点分组、guest 存在但文档无焦点、webview=0 且侧栏开、只在 hidden/miss 中检测到 guest、侧栏标记未知、旧样本路径；frameP50 缺失显示 -；P50 只覆盖部分样本时样本数仍按全部行计；同窗口切换后 30 秒内候选排除、切换排除按 win 隔离、全部候选被切换排除时的专用提示、无切换记录时的限制提示；最新样本 paneDiagOn=false 不丢弃历史稳定样本；不把无焦点样本算进浏览器结论。
实机 同一会话分别用 browser-use 与人类浏览器 tab 各打开 10 分钟，确认报告出现稳定浏览器样本；12:15/12:16 类回前台样本被分到回前台组；关闭面板后 paneOpen=false，不混入稳定浏览器；打开插件 UI/奖励页/预览时 webview=0。
开销 样本体积增加不超过约 50 字节；无新增 ≥50ms 长任务；每样本只多一次 hasFocus()、最多两次选中 tab 查询与一次浏览器专属列表查询。
回归 现有全部测试通过；__lagfixOff()、暂停、自禁用、换 store、诊断关→开行为不变。
