# v0.3.0

首个公开发布版本。观测 + 订阅通知节流 + 四项可逐项关闭的性能增强。节流只改变渲染通知的时机；大会话保护只决定是否执行一次性的 `loadAllOlder` 全量补拉。两者都不修改消息、会话数据或工具执行，不读写 `db.sqlite`，不联网上报。

## 新增

- **状态条浮在输入框上方**：显示判定结论（极流畅/流畅/正常/轻微/卡/很卡）、帧 P95 与齿轮入口；只在主页面显示，设置页/弹窗/被遮挡时隐藏；同时挂多个 composer 时取最靠下的可见者。
- **不压输入区与上方横幅**：位置改为输入框顶边上方；与排队面板、额度横幅、待恢复提示、回到最新按钮相交时整体上移，绝不覆盖「立即发送 / 编辑 / 删除」；上方没有余量时暂时隐藏。
- **黄/红阈值真正生效**：面板里的阈值现在直接控制状态条主色（低于黄阈值绿色、达到黄阈值黄色、达到红阈值红色），不再出现"设置改了颜色不变"。
- **悬停/点击统计浮层**：大号帧 P95、六档颜色图例、最近 18 个采集周期柱状图、峰值/最低/最新、提交速率与长任务。
- **居中分类设置**（左侧：状态条 / 观测 / 修复 / 维护）：角标显隐与简洁/详细、黄红阈值、观测开关、采集间隔 1/3/5/10/30s、节流开关与窗口、四项性能增强、日志路径与上限、重启 ZCode。
- **修复页每项「!」说明**：点开写明该项影响什么、不影响什么；关掉「订阅通知节流」后，依赖它的窗口/自适应/冷静期/后台降频四行变灰且不可操作，大会话保护保持独立。
- **自适应窗口**：帧 P95 ≥80ms / ≥150ms 时窗口至少 200 / 300ms（以面板值为下限），帧恢复后回落，1s 缓存。
- **切会话冷静期**：切会话后 10s 内窗口至少 250ms，避免新会话首屏被高频通知打碎。
- **后台降频**：`document.hidden` 时最多 1s 合并一次，回前台立即补发。
- **大会话保护**：行数 ≥800 且未全载时拦截一次性全量补拉，分享入口/分享弹层放行；关闭时自动补拉一次。
- **日志预算**：观测与运行日志共享总预算（默认 50MB，可设 20/50/100/200MB），超了从最旧文件删起，当天活动文件保留；维护页显示实际路径、当前日志量与文件数（不足 1MB 按 KB）。
- **一键还原**：控制台 `__lagfixOff()`；角标隐藏后 `Ctrl+Alt+L`（Mac `Cmd+Alt+L`）或 `__lagfixSettings()` 仍能打开设置。
- **零安装探针**：`tools/lagfix-probe.py --overlay`，不改 app.asar、不用退出 ZCode，先看到卡顿数字再决定装不装。

## 修复

- **卸载与收尾的竞态**：`install()` / `finalize_pending()` 在文件锁内复查 `.lagfix-optout` 与 pending 文件，避免卸载完成后后台收尾把注入行重新写回；`uninstall` 改为先写豁免标记、失败撤回，堵住并发钩子重装的窗口。
- **补拉目标**：关闭大会话保护时只补"当初被拦的那个会话"，不再用当前会话顶替；`stale` / `retryable-failure` 退避重试（最多 6 次）。
- **阈值配色**：`卡死` / `刚卡过` 也走面板黄红阈值，不再硬编码红色。
- **多窗口 dead 样本**按窗口去重；日志预算纳入 `elevated-finalize.log`，无权限删除的文件跳过并继续清理其它文件；14 天保留改为启动时 + 每小时检查。

## 安装 / 升级注意

- 安装会修改 ZCode 的 `app.asar`；首次注入成功后必须**完全退出 ZCode（含托盘）再重开**，只关窗口或重开会话不算。
- 需要 ZCode 桌面版 + Python 3.8+；不用装 Node，也不用装第三方 Python 包。
- ZCode 升级会覆盖注入，保持插件启用并在新会话触发 `SessionStart` 钩子即可自动修复；也可以执行 `/lagfix install`。
- 权限不足（如装在 `Program Files`）时注入会失败，失败原因写到 `~/.zcode/zcode-lagfix/hook-error.log`。
- 卸载先完全退出 ZCode，市场安装执行 `python ~/.zcode/zcode-lagfix/patch_install.py uninstall`（剥注入 + 写豁免一次完成，失败不会写豁免），再去 设置 → 插件 里卸载；源码安装执行 `python install.py remove`。即使先卸载了插件，运行时目录里的 `patch_install.py` 仍可完成清理。

## 验证

- `node tests/observe_smoke.mjs`：105 项全部 PASS（角标可见性/位置/队列与横幅让位、阈值配色含"卡死/刚卡过"分支、节流合并与尾沿、跨重订阅窗口、四项增强、大会话保护与"只补被拦会话"、日志上限与当前日志量、一键还原、隐藏角标后的设置入口）。
- `node --check` 主进程与渲染脚本；`python -m py_compile` 全部 Python 文件。
- `python tests/line_regex.py`（与 zusage 注入行互不误伤）、`python tests/peer_gate.py`（多插件收尾礼让）、`python tests/smoke_asar.py`（合成 asar 夹具，byte 级重打包 + busy/锁内 optout 竞态，46 项，不碰真实安装目录）、`python tests/install_remove.py`（卸载异常边界，8 项）全部 PASS。
- 自动化测试不等同于所有 Windows/macOS 环境的实机验收；首次安装后请按 README 完全重启确认状态条出现。

## 已知边界

- 面板「检查更新」仍置灰：当前通过重新执行安装口令升级，不提供“已是最新”这类假结论。
- 打开子智能体（Subagent）面板时的卡顿已记录，计划在 v0.3.x 先量清 DOM 规模/订阅通知/面板挂载哪一项为主，再决定是否加独立开关。
- 多会话同时运行时的叠加卡顿已记录：当前窗口按 store 实例计时，N 个会话仍是 N 倍通知；下个版本先验证跨 store 共享调度器/全局预算/按可见性分级，再决定默认策略。
- 状态条依赖宿主 `.chat-composer-input-surface` 与投影 store 的内部形状；ZCode 大版本改版可能需要适配。
