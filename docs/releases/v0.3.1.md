# v0.3.1

滚动卡顿的观测与绘制层缓解版本。新增滚动窗口、`loadOlder` 与输入延迟三项只读诊断，滚动期间临时隐藏消息层遮罩；角标改为常驻，设置面板按「状态条 / 观测 / 性能 / 维护」重排；「检查更新」可用。

仍然保持原有边界：不改消息与会话数据、不写 store、不读写 `db.sqlite`、不开 CDP、不联网上报。唯一的网络请求是用户手动点击「检查更新」时发往 `api.github.com` 的一次 GitHub Releases 查询（无 token，不自动下载/安装）。

## 新增

- **滚动诊断（只读）**：只统计滚动后 200ms 内的帧（P95/max）、时间线 `scroll` 事件数、`loadOlder` 次数/耗时 P95/最长/失败、挂载 turn 数、DOM 峰值、浏览器支持时的 `long-animation-frame`。`loadOlder` 只观测，不拦截、不延迟、不改参数与返回值，保留原 `this` 与原 promise 引用。
- **选择器失配告警**：`scroll.mismatch=true`（任意元素有滚动事件，但 `event.target` 没命中 `[data-v4-timeline-scroll="true"]`）时，说明宿主 DOM 可能改版，`/lagfix report` 会直接打印提示。
- **输入延迟诊断（只读）**：只统计 `.chat-composer-input-surface` 子树内 `keydown` 到下一帧的间隔（P95/max/样本数），复用现有 rAF 循环。它只回答"按键后多久才出帧"，**不修复**按键卡顿。尚未 attach 到会话、采样循环没启动时不记按键；超过 60s 的待处理按键按无效丢弃，避免启动期/页面冻结污染最大值。
- **滚动期隐藏消息层遮罩**：时间线滚动时给 `document.documentElement` 加 `data-lagfix-scroll="1"`，停滚 180ms 后移除；CSS 只覆盖消息层的 `mask-image`（不覆盖 `mask` 简写），避免每帧同步重算整层遮罩。可在性能页单独关闭。
- **角标常驻（A8）**：删除「显示角标」开关与 `badgeVisible` 字段；旧 `localStorage` 里的 `badgeVisible:false` 直接忽略。设置页/弹窗内、被浮层遮挡、没有可用输入框时仍会自动隐藏——这是布局避让，不是用户开关；插件自己的设置弹窗打开时角标也会真正隐藏到遮罩后。
- **设置面板重排（A9）**：分类改为 状态条 / 观测 / 性能 / 维护；行名改为「显示文字 / 信息量 / 警告阈值 / 严重阈值 / 渲染节流 / 最短刷新间隔 / 卡顿时自动放宽 / 切换会话保护 / 后台限制刷新 / 大历史会话保护 / 滚动期隐藏遮罩」；滚动诊断与输入延迟放在观测页。维护页新增正式「版本」行（`v0.3.1` + 本机只读说明），底栏改为「设置修改后自动保存」，不再在面板里显示 `__lagfixOff()` 这类控制台命令。
- **检查更新（手动）**：维护页按钮 → 渲染端只置内存标记 → 随采集样本回传 → 主进程请求一次 `https://api.github.com/repos/ck-ys/zcode-lagfix/releases`。仅允许 https + `api.github.com`（重定向逐跳重新校验，最多 2 跳）、10 秒超时、2MB 响应上限、过滤 draft/prerelease、按数值比较 semver；结果注入面板状态行。无 token、不缓存、不自动安装。

## 修复 / 调整

- **选择器失配判定收紧**：非时间线滚动只在会话 pane（`[data-session-id]` 子树）或 document 级目标上计入 `anyScrollEvents`；宿主设置页、侧栏和本插件面板内的滚动不再产生 `mismatch` 误报。
- **`loadOlder` 最长耗时改为窗口口径**：`loadOlderMax` 与 `loadOlderP95` 都取最近 30s 的环形窗口，不再混入启动以来的历史峰值，滚动 A/B 对比不会被旧峰值干扰。
- **日志预算删除失败不再错误扣减**：删除失败的文件仍占磁盘，不能从 `total` 里扣掉；否则「不可删文件 > 上限」时循环会误以为已达标，后面的可删日志一个都不会动。现在失败只记一次日志并继续删后面的文件。
- **输入延迟启动期防污染**：采样循环未启动时忽略 keydown；超过 60s 的待处理按键视为无效样本丢弃。
- **rAF 单链保证**：暂停/恢复用 generation 让挂起的旧回调失效，隐藏窗口下不会出现两条自续的 rAF 链。
- **环形窗口上限提高**：`SCROLL_RING_MAX`/`INPUT_RING_MAX` 改为 3600（30s × 120Hz），高刷屏与高频输入下仍保留完整 30s 窗口。
- **检查更新等待期不再闪回「尚未检查」**：请求标记随样本发出后，面板保持「正在检查…」，直到主进程注入新结果或 15s 超时。
- **面板「修复」分类更名为「性能」**：页内按 渲染 / 历史 / 滚动 三组排列；依赖节流的四行仍在节流关闭时整行变灰，「大历史会话保护」与「滚动期隐藏遮罩」保持独立。
- **「大会话保护」统一改称「大历史会话保护」**：面板、报告、README 与市场描述口径一致。
- **`__lagfixOff()` / 关闭开关 / observer 自禁用**：同步释放 `loadOlder` 包装、移除 `data-lagfix-scroll`、清定时器与三个环形窗口；scroll/keydown 监听改为具名函数并按开关装卸，`pagehide`/`beforeunload` 也会移除属性。
- **观测器自禁用与暂停样本**：`dead` / `paused` 的廉价 payload 固定带 `scroll: null` 与 `input: null`，保持 schema 稳定；暂停期间不累计滚动/长动画帧计数。
- **`/lagfix report` 的滚动段不再被「活跃采样」门槛吞掉**：纯滚动（没有投影提交、`frames=0`）也会打印滚动/输入诊断与 mismatch 提示；报告里的「修复开关 / 大会话保护」同步改称「性能开关 / 大历史会话保护」。
- **DOM 峰值降频不再冻结**：`domPeak` 用独立采样时间戳，单次全量计数 >5ms 后退回 60s，不会因为旧 DOM 计数块共用时间戳而永远不再更新。
- **检查更新增加总时限**：10 秒硬截止覆盖连接/重定向/慢速滴流，非 443 端口一律拒绝；不再可能因半开连接让按钮永久卡在「检查中」。
- **在途 `loadOlder` 回写**：关闭诊断/一键还原后，旧 promise 的回调按 generation 丢弃，不会出现 `calls=0` 但 `p95/max` 有值的样本。

## 安装 / 升级注意

- 从 v0.3.0 升级会替换 `app.asar` 注入；首次注入成功后必须**完全退出 ZCode（含托盘）再重开**，只关窗口或重开会话不算。
- 设置 key 仍是 `localStorage["lagfix.settings.v1"]`；新增 `scrollDiagOn` / `inputLagOn` / `maskOffOnScroll` 三个字段，默认均为 `true`。旧设置里没有这些键时按默认值处理，不需要手动迁移。
- 不需要新依赖；仍然是 ZCode 桌面版 + Python 3.8+。
- 若仓库还没有创建 GitHub Release 页面，「检查更新」会明确提示"还没有正式发布版本"，不会谎报"已是最新"。

## 已知边界

- **O2 依赖宿主写法**：当前宿主用内联 `style.maskImage`（无 `!important`），作者样式表的 `!important` 规则才能覆盖。若宿主改成带 `!important` 的内联声明，本项会静默失效；不加兜底分支，靠 `scroll.p95` 与人工 A/B 发现。
- **`scroll.p95` 不等于整段会话帧率**：它只代表滚动后 200ms 内的帧；要与 `frameP95` 分开看。
- **`input.p95` 不能定责**：它包含浏览器自身输入延迟与主线程排队，无法区分二者；插件只能测量，不能修复。
- **DOM 采样有成本**：`mountedTurns` 与 DOM 计数每周期各一次全树遍历；单次超过 5ms 时 `domPeak` 退回 60 秒采样。
- **检查更新只认 GitHub Release**：只有 tag、没有 Release 页面时查不到版本；不自动下载、不自动安装、不写任何凭据。
- **状态条仍依赖宿主内部标记**：`.chat-composer-input-surface`、`[data-v4-timeline-scroll="true"]`、`[data-v4-timeline-message-layer="true"]`、`[data-v4-turn-unit="true"]` 等；ZCode 大版本改版可能需要适配，先跑 `/lagfix report` 判断。
- **多会话互相拖累不在本版范围**：节流按 store 实例计时，N 个会话仍是 N 倍通知；切到超长会话再切回普通会话后，隐藏 pane 的 DOM/提交仍可能拖慢当前会话。v0.3.1 的 `domPeak`/`mountedTurns` 是整窗口径，不能按会话归因；计划 v0.3.4（O7）先补 per-sid 观测再改策略。
