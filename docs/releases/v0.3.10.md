# v0.3.10

发布时间：2026-11-12
主题：修复「发现新版本但看不到红点」

## 背景

用户在维护页手动点「检查更新」，状态行已经显示「发现新版本 v0.3.9（当前 v0.3.8）」，但返回会话页后角标右侧没有红点，维护页「检查更新」行也不明显。

根因不是检查逻辑，而是红点的显示值：

- v0.3.7 给两个红点加了默认样式 `display:none`；
- `syncUpdateDot()` 需要显示时写 `el.style.display = ""`；
- 空字符串会删除内联声明，浏览器回落到样式表的 `display:none`，所以红点永远不会出现；
- 旧测试的假 DOM 不计算样式，只比较 `style.display === ""`，因此没有发现。

## 变更

- `syncUpdateDot()` 显示红点时改为写显式 `inline-block`，隐藏时仍写 `none`。
- 同时作用于角标右侧红点（`lagfix-overlay-badge-update-dot`）与维护页「检查更新」行红点（`lagfix-settings-panel-updatedot`）。
- 显示条件保持不变：`newer === true`、缓存 `current === VERSION`、`latest` 非空且 `latest !== VERSION`。
- 红点位置、大小、颜色、点击行为、检查更新请求与缓存结构均不变。

## 明确不做

- 不改变「检查更新」的网络请求、24 小时自动检查、缓存 key 或红点判定条件。
- 不新增设置项、DOM 属性或日志字段。
- 不改注入链、composer、消息/会话数据或其它缓解项。

## 安装注意

- 本版仍会修改 `app.asar`。安装/更新后请**完全退出并重新打开 ZCode**（仅关闭窗口不算）。
- 安装 v0.3.10 后，GitHub 最新 Release 也是 v0.3.10，正常会显示「已是最新」；要验证红点，需要等下一个更高版本发布，或仅在本地用测试缓存验证。

## 验证

- `node --check plugins/zcode-lagfix/lagfix-main.cjs`、`node --check plugins/zcode-lagfix/lagfix-observe.js`：通过。
- `python -m py_compile install.py plugins/zcode-lagfix/*.py plugins/zcode-lagfix/hooks/*.py`：通过。
- `node tests/observe_smoke.mjs`：**498 项全部 PASS**。其中红点相关断言从「`display === ""` 即视为显示」改为「必须等于 `inline-block`」，覆盖默认隐藏、有新版本显示、跨窗口缓存、`current > latest` 不显示、`__lagfixOff` 清理五条路径。
- 其余套件（`line_regex`、`peer_gate`、`smoke_asar`、`install_remove`、`report_session_diag`、`update_check`、`log_budget`）按发布前全量结果为准。
- 实机复核需要下一个更高版本发布后观察两处红点；本次自动化已验证脚本写入的显示值能覆盖样式默认值。

## 已知边界

- 红点只是提示，不自动下载或安装；升级仍走「复制安装口令」。
- 如果缓存里的 `current` 与当前运行版本不一致（例如刚升级、旧缓存未刷新），红点仍按既有规则隐藏，下一次检查后重新判断。
- 维护页「检查更新」行的说明文字不变；本版只保证红点实际可见。
