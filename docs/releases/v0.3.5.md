# v0.3.5

发布时间：2026-11-11
主题：长帧上下文归因（P0，默认开、只读）+ 面板常开时进一步合并（O5，实验、默认关）+ 右侧预览链路的上游证据整理（U1，只出文档）

## 新增

- **长帧上下文归因（`lafCtxOn`，默认开，只读）**：每条 ≥100ms 长帧除原有的时长、强制布局占比、脚本 top5 外，再记录 `sinceNotify / sinceFlush / sinceScroll / sinceCommit` 四个滞后值（信号在帧开始前 = 距帧起点的时间；发生在帧内 = 0；不属于这一帧 = null），并归类为 `flush（节流补发）/ notify（通知到达）/ scroll（滚动）/ other（其它）`。用来回答「这次卡顿到底是插件合并刷新造成的，还是滚动/宿主渲染造成的」。
  - 取样上限仍为最近 10 条；来源分布 `laf.ctx` 按采集周期统计。
  - 只有 `lafDiagOn`（卡顿来源定位）也开启时才工作；关闭后样本 `ctx=null`，明细不再带上下文字段。
- **样本新增 `paneOpen` / `panelQuiet`**：前者是侧栏当前是否打开（未检测到为 `null`），后者表示 O5 是否正在生效（0/1）。两者只用于判读，不参与任何宿主行为。
- **面板常开时进一步合并（`panelQuietOn`，默认关，实验）**：侧栏打开期间，通知节流下限从 300ms 抬到 400ms，角标定位上限从 1.8s 放宽到 3s；面板关闭后，之后的通知立即回到基础间隔（默认 120ms），已经在等待中的一次通知最多按原窗口送达。只改插件侧时序，不碰面板内容、消息数据或工具执行。
- **报告升级**：`/lagfix report` 的卡顿段新增当前面板状态、本周期来源分布、每条长帧的来源与四个时间差；`other` 且距消息提交 ≤50ms 时标注「紧跟宿主提交」，便于把宿主渲染成本与插件成本分开。

## 修复

- 长帧来源展示名在 `sourceURL` 为空时回退到 `invoker`（v0.3.4 实机 449/449 条为空，旧逻辑会把明细整片塌成 `?`）。
- 长帧上下文使用独立的滚动时间戳，避免与滚动诊断的 `lastScrollAt` 互相污染；关闭滚动诊断时不会再把旧滚动误判成 `loadOlder` 的滚动触发。

## 设置面板

- 「观测」→「诊断」新增一行：**卡顿来源细分**（默认开）。
- 「性能」→「实验（默认关闭）」新增一行：**面板常开时进一步合并 · 实验**（默认关）。
- 两项都只改记录或通知时机，`__lagfixOff()`、自禁用、暂停三条路径都会清理对应时间戳、计数与状态。

## 已知边界

- **O5 只是实验**：默认关闭，需要用户在长会话 + 面板打开 + 高频滑动的同一路径上做开/关 A/B；长帧数或 `frameP95` 下降 ≥20% 才考虑进默认路径，未过线就保持关闭并在文档如实标注。
- **P0 是窗口级归因**：LoAF 与帧指标都是整个渲染窗口的，`sinceCommit` 只跟踪活动 pane 的投影序号；多 pane 同时提交时，来源分布仍是窗口汇总，不能精确到某个 pane；`lastCommitAt` 在 attach/切会话时清零，不跨会话。
- **右侧预览是 Electron `<webview>` guest**：面板内滑动的主线程/合成成本落在宿主 renderer，插件无法接管；U1 只把这条链路与实测数据整理给上游，不声称插件已解决。
- **`notify`/`flush` 上下文依赖「合并刷新」开启**：关闭合并刷新时没有插件侧通知时间戳，这两类差值会是 `null`，来源会落到 `scroll` 或 `other`。
- 仍不读消息正文、不写 store、不碰 `db.sqlite`、不开 CDP、不联网上报。
