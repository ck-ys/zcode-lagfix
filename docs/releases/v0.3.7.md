# v0.3.7

发布时间：2026-11-12
主题：更新提醒——有新版本时角标与维护页出现小红点，自动检查默认关闭

## 新增

- **有新版本小红点**：检查结果缓存在本机 `localStorage["lagfix.update.v1"]`，跨窗口与重启保留。仅当缓存 `newer=true`、缓存版本等于当前运行版本、且最新版本与当前不同时，在以下两处显示红点：
  - 角标内、指标文字与齿轮之间；
  - 维护页「检查更新」行标题右侧。
  - `newer=false`、最新版本与当前相同、缓存版本与当前不一致（例如刚升级后旧缓存未刷新）时都不显示。
- **自动检查更新（`autoUpdateCheckOn`，默认关）**：开启后，ZCode 启动或窗口打开时最多自动检查一次，本机 `checkedAt` 在 24 小时内不重复请求。只请求公开 GitHub Releases：
  - 不自动下载、不自动安装、不自动重启；
  - 不带 token、不上报任何本机数据；
  - 检查失败只影响维护页那一行提示，不影响观测与其他开关。
- **主进程 24 小时去重**：多窗口同时到期只发一次网络请求；24 小时内已有成功结果时直接回放缓存；自动检查失败后 24 小时内静默跳过，不重复联网、不重复注入错误。手动检查成功后同样刷新 24 小时计时并写入缓存。
- **样本新增 `updateAuto`**：`1` 表示本次检查由自动检查触发，`0` 表示手动或未请求；设置快照新增 `autoUpdateCheckOn`，便于报告排查。
- **反馈入口**：维护页新增「反馈问题」按钮，优先通过宿主 `openExternal` 打开 GitHub 问题页，失败时退回 `window.open`；README 同步新增「遇到问题」章节与 GitHub issue 模板，引导用户附上 `/lagfix report` 输出、`main.log` 与最近一个 `observe-YYYYMMDD.jsonl`。插件不自动上传任何内容。

## 设置面板

- 「维护」页新增「自动检查更新」开关与「会做什么 / 不会做什么 / 代价」说明，默认关闭。
- 「检查更新」行增加红点与自动检查状态文案；「复制安装口令」保持原样。
- 手动检查行为不变：点击后随下一个采集样本请求一次；15 秒无结果恢复按钮，避免永久停在「检查中」。
- `__lagfixOff()` 会关闭自动检查、删除更新缓存、清空在途标记并隐藏两处红点；手动检查按钮仍可用。

## 安装注意

- 本次升级仍会修改 `app.asar`。安装/更新后请**完全退出并重新打开 ZCode**，让新的 `lagfix-main.cjs` 与 `lagfix-observe.js` 生效。
- 自动检查默认关闭，升级后不会自行联网；需要时在「维护」页打开，或继续手动点击「检查更新」。

## 已知边界

- 红点只表示「检查到新版本」，不表示已下载或已安装；升级仍由用户执行安装口令并完全重开 ZCode，插件不替用户重启。
- 自动检查依赖用户显式开启；默认关闭时唯一网络请求仍是手动点击「检查更新」。暂停观测不撤销自动检查的开启，关闭开关或 `__lagfixOff()` 才会停止。
- 本机缓存只含版本号、`newer`、release 链接与时间戳；不含会话、消息或工具数据。缓存版本与当前版本不一致时红点隐藏，下一次检查完成后重新判断。
- 一次临时检查失败不会清掉已知的「有新版本」缓存，红点会保留；维护页会显示失败原因。
- 主进程缓存随进程存活；主进程重启后缓存丢失，但渲染端 `checkedAt` 仍会阻止 24 小时内的自动重发；手动检查不受此限制。
- 自动检查不做后台常驻轮询，也不会在 ZCode 不打开时联网；频率上限为 24 小时一次，不是实时更新提醒。
- 与 v0.3.6 补页批量、v0.3.5 面板期合并等行为项完全独立；本版不改注入链、不新增宿主包装或 DOM 属性。
