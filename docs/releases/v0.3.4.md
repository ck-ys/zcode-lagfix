# v0.3.4

卡顿归因与补页/渲染实验版本。按 v0.3.3 实机数据（超长会话上翻：单次补页最长 2262ms、DOM 峰值 8691、3 秒内长任务 32 次）拍板的路线：先补「卡的时候到底在忙什么」的只读归因（P0 LoAF），再上两项**默认关闭**的实验缓解——O3 大会话翻页降频（按源码复核重定义：不是合并请求，是触发降频）与 O4 turn 内行级 `content-visibility`。`/lagfix report` 新增「卡顿来源定位」「翻页降频」两段。

仍然保持原有边界：不改消息与会话数据、不写 store、不读写 `db.sqlite`、不开 CDP、不联网上报。唯一的网络请求仍是用户手动点击「检查更新」时查询一次 GitHub Releases。宿主后端每次补页的全量过滤是 ZCode 自身成本，插件只减少触发次数、不降低单次成本，文档如实写明。

## 新增

- **P0 卡顿来源定位（`lafDiagOn`，默认开，只读）**：时长 ≥100ms 的长动画帧记录最近 10 条：总时长、**该帧所有脚本的**强制同步布局/样式时长之和（`forcedStyleAndLayoutDuration` 在脚本条目上，帧对象没有该字段）、耗时前 5 的脚本。`sourceURL` 只保留去查询串后的文件名（如 `index-a1b2.js`），`invoker` 截断 120 字符；不含路径、函数源码位置或任何会话内容。与 v0.3.1 的 `lafCount`/`lafMax` 共用同一个 `PerformanceObserver`：安装条件放宽为 `(scrollDiagOn || lafDiagOn) && observe`；关闭 `lafDiagOn` 清空归因环，两个诊断开关都关才断开观察器。一次性支持探测把「浏览器不支持」与「开关没开」区分开。归因环是窗口级口径，不随会话切换清空（帧指标同为窗口级），报告端如实标注。
- **O3 大会话翻页降频（`loadOlderPaceOn`，默认关，实验）**：窗口行数 > 3000 时，两次 `loadOlder` 触发至少间隔 600ms。**只对滚动触发的调用降频**（以「调用发生在时间线 scroll 派发栈内」判定：宿主前插锚定后会补发合成 scroll，用时间窗会被它污染；宿主 `SessionPane` 对首 turn 缺 header 的自动补拉用 cursor 去重、跳过不会重试，绝不能碰）；跳过的调用不执行原方法、不进任何观测环/明细、不计 `loadOlderCalls`，返回已结算 promise；不碰 `loadingOlder`/`canLoadOlder`，宿主状态机视角本次触发从未发生，下一次滚动事件带更新的锚点自然重试。行数读不到时不做降频、只放行。降频与观测开关独立：`scrollDiagOn` 关、`loadOlderPaceOn` 开时包装保留且继续降频；两者同关时包装卸载，行为回到 v0.3.3。样本新增 `pace` 字段（`minRows/intervalMs/allowed/skipped`，随包装实例累计，换主 store 归零）。
- **O4 长回合渲染减负（`turnContentVisOn`，默认关，实验）**：开关开启时给 `documentElement` 加 `data-lagfix-cv="1"`，CSS 只作用于 turn 单元内部的行级块（`[data-v4-turn-unit]:not([data-v4-running-live-tail]) [data-row-id]`）：`content-visibility:auto` + `contain-intrinsic-size:auto 160px`。三重防线：不碰被 virtualizer 测高的 turn wrapper；正在生成的 live tail 整轮排除；`auto` 关键字让浏览器记住每块上次真实高度，已渲染过的块屏外跳过绘制时对测高无扰动。无新增监听器/Observer，纯 CSS；暂停、自禁用、`__lagfixOff()` 都移除属性。
- **面板三行新开关**：观测页「卡顿来源定位」（默认开）；性能页新增「实验（默认关闭）」组：「大会话翻页降频 · 实验」「长回合渲染减负 · 实验」，说明按「会做什么 / 不会做什么 / 代价」组织。
- **`/lagfix report` 两段新输出**：卡顿来源定位（本周期长帧计数/最长值、最近 ≥100ms 长帧明细含强制布局占比与脚本 top3、窗口内脚本耗时聚合、`supported=0`/关闭/旧样本分别提示）；翻页降频（参数与累计放行/跳过、开启但未触发提示）。

## 调整

- `loadOlder` 包装的安装条件从「`scrollDiagOn`」放宽为「`scrollDiagOn || loadOlderPaceOn`」；看门狗与 attach 的三处 OR 条件同步。观测语义不变：被 O3 跳过的调用不会被记成成功或失败。
- **`lafMax` 改为每采集周期清零**（终审对齐）：v0.3.1–v0.3.3 里 `scroll.lafMax` 跨周期保留，与同段落每周期清零的 `lafCount` 混用会让报告「本周期长帧 N 次（最长 Xms）」拿到很久以前的旧值。本版起 `lafMax` 与 `lafCount` 同口径；想看更长时间维度的最大值用 `frameMax`/`maxLongTask`。
- 暂停样本的 schema 补齐 `laf/pace`（`laf: null`、`pace` 照实上报——降频是缓解项，与观测开关独立）。
- `__lagfixOff()` 同时关掉三个新开关、移除 `data-lagfix-cv`、清空归因环；`pagehide/beforeunload` 清单加入 `data-lagfix-cv`。
- 设置 key 不变：新增 `lafDiagOn / loadOlderPaceOn / turnContentVisOn` 三个布尔键，旧设置缺键按默认（开/关/关）。

## 安装 / 升级注意

- 从 v0.3.3 升级会替换 `app.asar` 注入；首次注入成功后必须**完全退出 ZCode（含托盘）再重开**。
- 升级后默认行为与 v0.3.3 一致（两项实验默认关）；想试实验项去「性能 → 实验（默认关闭）」手动开启。
- 翻页降频开启后，如果快速上翻感觉历史出现变慢，属预期代价；关掉开关立即恢复。渲染减负开启后，个别没绘制过的长消息第一次滚到时可能有轻微跳动。

## 已知边界

- 后端全量过滤（`getRowsRange` 每次先扫全会话投影再取 60 行）是宿主侧 O(全会话行数) 成本，插件无法降低单次耗时；O3 只减少触发次数。
- O3 停在触发区不再滚动时，被跳过的补页需再滚动一次才补上；实机 A/B 用「顶部空白时间」指标衡量。
- O4 长 turn 首次滚入时，没渲染过的行块会按 160px 占位校正到真实高度（与 virtualizer 自身初始估算同性质），可能表现为一次较明显的跳动；锚点漂移验收沿用 48px 底线，并需抽查 turn 导航跳转。
- 两项实验的保留门槛：同场景 A/B 滚动 P95 或长任务下降 ≥20%（或长任务下降 ≥30%），否则保持默认关闭并如实标注「未达门槛」。
- 卡顿来源定位是窗口级口径，样本 `sid` 只代表采集时刻的活动会话；归因到具体会话要用多会话归因段交叉看时间。
