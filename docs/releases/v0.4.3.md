# v0.4.3

日期：2026-11-13
主题：会话切换归因（只读，默认开）+ 修复失灵的翻页降频 + 补页批量退役。

## 新增

- **切换会话归因（`switchDiagOn`，默认开，只读）**：复用已有的 sid 变化信号，每次切换会话记一条记录：
  - `afterMax2s` / `afterP95`：切换后 2 秒内最重的一帧与 P95（帧切片在 `rafTick` 里 live 累加，结算时才算）；
  - `lafN2s` / `styleMs2s`、`lafN30s` / `styleMs30s`：切换后 2 秒 / 30 秒内 ≥100ms 长帧次数与强制布局合计；
  - `loadOlderN30s` / `loadOlderMs30s`：切换后 30 秒内成功补页次数与耗时合计（覆盖实机里切换后约 20 秒才出现的补页潮）；
  - `domBefore/After`、`turnsBefore/After`、`blockedLoadAll`：取 60 秒/每周期缓存值，**不在切换瞬间做 O(DOM) 扫描**；`blockedLoadAll` 为冻结时相对记录时刻的大历史拦截增量。
  - 环上限 10 条；`from/to` 只留 sid 前 8 字符，被淘汰的会话桶不影响记录；150ms 内 attach/MO 双信号去重；30 秒后冻结并补齐 after 值；内容未变化时样本 `items=[]`。
  - 窗口内又切换时，上一条冻结并标 `settledEarly=1`（报告标注「窗口被下一次切换截断」），避免第二次切换的补页/长帧算到第一条头上；冻结只取缓存，不在切换瞬间扫描 DOM。已经满 30 秒、只是采样没跑到的记录按自然到期处理。
  - after 值的新鲜度容差按采集间隔放大（`max(10s, collectSec + 5s)`），采集间隔调到 30/60/120 秒时不会静默丢 after 值。
  - DOM/回合数缓存由滚动诊断周期刷新；关掉滚动诊断时这两列按「未测量」记空，不再拿上一次开启时的跨会话旧值冒充。
  - 重挂同一会话（sid 未变）不算切换；只有 sid 真的变化才记一条；150ms 内 A→B→A 快速往返丢弃这条记录，不留 `from===to` 伪切换。
- `/lagfix report` 新增「会话切换」段：最近 10 次切换逐条打印两个窗口的数据、DOM/turn 差值、是否已满 30 秒，并标出最重一次；关闭、旧样本、空记录分别如实提示。

## 修复

- **「大会话翻页降频」在 ZCode 3.18.2 上永不生效**。旧实现要求「正在同步派发时间线 scroll 事件」，但宿主把阈值检查放在 React `onScroll` 回调里（`Xt → PDn → onLoadOlder`），插件 capture 监听器与它之间隔着 microtask checkpoint，标志已被清掉；宿主还会在测量/补页后经 rAF 异步重派生合成 scroll。实机佐证：同一样本「补页批量」`downgraded=4`（时间口径）而 pace `0 放行 / 0 跳过`（同步口径）。
  - 触发判定改为与补页明细分类一致的时间窗：距最近一次时间线滚动 ≤2000ms 视为滚动触发。
  - 首调与挂载 5 秒内的调用一律放行，保护 SessionPane 冷快照首 turn 的修复补拉（cursor 去重，跳过不会重试）。
  - 所有真正放行的调用都计入 `allowed`（含首调豁免、非滚动触发、小窗口），避免 A/B 里放行次数系统性偏低。
  - 调用计数在包装器入口无条件递增：只开降频、关掉滚动诊断时首调豁免不会永久生效（否则降频会再次静默失效）。
  - 本轮计数只在真正「关→开」时清零（由面板/跨窗口入口显式传入），不再维护「上次状态」镜像；启动时持久化的开关或任何无关开关都不会误清零。
- 降频计数新增**全天累计口径**：`pace.allowed/skipped` 仍是当前 store 生命周期，新增 `totalAllowed/totalSkipped`，只在 observer 自禁用 / `__lagfixOff()` 清零；换 store、暂停观测、关→开实验开关都不清。报告两口径并列，旧样本无累计字段时标注「旧样本没有全天累计口径」。

## 退役

- **补页批量（O8b，`loadOlderPageLimitOn`）退役**。两天实机 `applied=0`：连续上翻全部落在 600ms 窗口内被降回 60 行，唯一能生效的「单次慢速上翻」场景几乎不存在。
  - 移除行为实现、常量、面板「补页批量 · 实验」行与 `page` 样本字段；`loadOlder` 包装安装条件收敛为 `scrollDiagOn || loadOlderPaceOn`。
  - 旧设置键读取时忽略（不报错、不迁移，下次保存自然消失）；`__lagfixOff()` 不再触碰该键。
  - 报告保留历史兼容：旧日志里的 `page` 计数照常显示，统一标注「已退役（v0.4.3 起移除；以下是退役前的历史计数）」；新日志没有该字段时打印「补页批量已于 v0.4.3 退役」。

## 安装注意

- 本版新增设置键 `switchDiagOn`（默认开，只读）；不改变任何缓解项的默认值——`loadOlderPaceOn` 仍默认关闭，需实机 A/B 达门槛才考虑转默认。
- 仍需通过源码安装器或插件市场安装；安装会修改 `app.asar`，成功后必须**完全退出**并重新打开 ZCode（仅关闭窗口不算）。
- 不读写 `~/.zcode/cli/db.sqlite`，不读会话正文，不打开 CDP，不联网上报；网络请求仍只有用户手动或可选自动检查公开 GitHub Releases。

## 已知边界

- 自动化测试使用合成 DOM/store 与假定时器，不等同于 Windows/macOS 实机验收；首次安装后仍需实机确认观测与开关。
- 切换归因只回答「切换后卡了多久、之后补了多少历史」，**不改变切换行为、不让切换变快**；切换期保护（通知下限/关 mask/跳角标）已推迟到 v0.4.4，等本版数据指出卡点后再设计。
- O3 修复只是让降频重新可用：`loadOlderPaceOn` 仍默认关闭。宿主后端全量过滤是 O(会话行数)/次的成本，插件只减少调用次数，不是消除补页成本。
- 补页批量的旧实现与历史计数保留在 git 与旧日志里，未来宿主补页协议变化再凭新数据重立实验，不复活旧实现。
