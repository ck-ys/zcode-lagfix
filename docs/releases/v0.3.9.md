# v0.3.9

发布时间：2026-11-12
主题：设置面板滚动/焦点修复，以及还原边界与更新状态文案

## 背景

v0.3.8 之后集中排查了四个用户反馈：

1. 维护页「检查更新」看起来不生效；
2. 点设置面板里的开关，面板会跳回顶部；
3. 输入框有内容时，左侧栏加载导致输入被清空；
4. 发送消息后文字仍留在输入框。

审计结论：

- 第 1 项是发布通道数据问题，不是检查逻辑错误：安装版已是 v0.3.8，但 GitHub 最新 Release 仍是 v0.3.4，所以 `newer=false`，旧文案只会说「已是最新」。本版增加「当前版本高于最新发布」的如实说明，并继续由发布流程补 Release。
- 第 2 项是插件自身的确定缺陷：`rebuildPanel()` 销毁并重建整个 `.dlg-content`，滚动位置归零；开关一改就跳顶。
- 第 3、4 项在宿主 `ConversationComposer.tsx` 的草稿/发送事务里：作用域切换会先清空草稿，发送结算又有 revision 门禁；插件不写 composer、不碰会话数据，只可能通过 120–400ms 的通知合并放大竞态窗口。本版不改宿主行为，也不声称已修复这两项。

## 变更

### 面板重建保留滚动位置

- `.dlg-content` 固定 id `lagfix-panel-content`，是面板唯一滚动容器。
- `rebuildPanel()` 重建前读取旧内容区 `scrollTop`，重建后写回；旧内容区不存在按 0 处理，新内容区不存在不抛错。
- 只影响重建，不改变当前分区（状态条/观测/性能/维护）与任何开关值。

### 打开/关闭面板的焦点管理

- 首次打开（`panelOpen` false → true）时记录当前焦点元素，并把焦点移到面板容器；容器 `tabindex="-1"`，不显示焦点框。
- 面板打开期间 Tab/Shift+Tab 在面板内循环：焦点在最后一个控件时 Tab 回到第一个，在第一个时 Shift+Tab 回到最后一个；焦点不在面板内时拉回面板；没有可聚焦控件时保持面板焦点并吞掉 Tab。
- 关闭面板时，如果记录的原焦点元素仍在文档中，焦点还给它；原元素已断开或就是 `body` 时不强制聚焦。
- `rebuildPanel()` 重建时优先按序号恢复同一可聚焦控件；恢复不了则聚焦面板容器，避免焦点掉回宿主输入框。

### `restoreTarget` 只还原自己那一层

- `subscribe` 包装记录 `{ orig, wrapped }`；还原时只有 `target.subscribe === wrapped` 才写回 `orig`。
- 宿主在插件运行期间替换了 `subscribe` 时，插件不再覆盖宿主的新实现；`__lagfixThrottle` 标记仍会删除。
- `__lagfixOff()`、关闭「合并刷新」、observer 自禁用三条路径共用该规则。

### 订阅回调异常留痕

- 合并刷新包装调用宿主 listener 抛错时仍不向 React 冒泡，但每个页面生命周期最多打印一次 `console.error`，避免完全静默。
- 不把异常写入 `observe-*.jsonl`，不改变采样与开关状态。

### 更新状态文案

- 检查成功且 `newer=false`，但当前版本高于最新 Release 时，维护页显示「当前 vX 高于最新发布 vY（发布通道尚未更新）」。
- 当前版本等于最新 Release 时保持「已是最新（vX）」。
- 只影响维护页展示，不改变红点判定。

## 明确不做

- 不把 `__lagfixOff()` 改成完全卸载：保留观测、角标、rAF 与 Ctrl+Alt+L/storage/resize 入口是 v0.3.0–v0.3.2 已拍板行为。
- 不改 composer、不拦截发送、不重写草稿，也不把宿主侧草稿/发送竞态包装成插件已修复。
- 不改消息、会话、工具结果，不读写 `db.sqlite`，不开 CDP，不联网上报。
- 不改注入链、观测字段、日志内容或任何缓解项默认值。
- 不新增网络请求；自动检查更新仍默认关闭。

## 安装注意

- 本版仍会修改 `app.asar`。安装/更新后请**完全退出并重新打开 ZCode**（仅关闭窗口不算），让新的 `lagfix-main.cjs` 与 observer 生效。
- 「检查更新」显示「发布通道尚未更新」时，说明本机版本已经高于 GitHub 最新 Release，不是检查失败；需要发布侧补 Release 页面。

## 已知边界

- 面板滚动位置按像素恢复；如果重建前后内容高度变化很大（例如切换分组后内容变短），浏览器会把 `scrollTop` 夹到新内容的最大值。
- 焦点恢复只在原元素仍连接时进行；原元素被宿主卸载时不会强行找一个替代输入框。
- `console.error` 只保留每个页面第一条订阅回调异常；后续同类异常仍被吞掉，不重复打印。
- 「发布通道尚未更新」只说明版本比较结果，不代表确实没有更新；以 GitHub Releases 页面为准。
- 宿主草稿/发送事务的竞态不在本版范围，若仍出现输入被清空或发送后文字残留，需要按宿主源码单独定位。
