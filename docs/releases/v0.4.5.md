# v0.4.5

日期：2026-11-15
主题：浏览器面板与回前台归因（只读，不改行为）。

## 新增

- **浏览器面板归因（只读）**：正常采集样本新增两个字段：
  - `focus`：`document.hasFocus()` 的布尔结果，表示文档是否有前台焦点；窗口被其他应用遮挡或 DevTools 抢焦点时可能为 `false`，它不等于 `document.hidden`。
  - `webview`：当前选中的内置浏览器 tab（`browser-use` 或人类浏览器）里是否有 guest；有选中的 guest 为 `1`，没有为 `0`，查询异常为 `null`。未选中的浏览器 tab 即使仍挂载 guest 也不算；插件 UI、奖励页、预览等普通 `<webview>` 也不再算。只读 DOM 结构，不读 `src`、标题、URL、页面内容或历史。
  - 暂停、自禁用、异常兜底样本带 `focus:null, webview:null`，保持 schema 稳定；暂停与自禁用不读 DOM。
  - 不新增设置项、DOM 属性、全局监听器或定时器；每采集周期只多一次 `hasFocus()`、最多两次选中 tab 查询与一次浏览器专属列表查询。
- **报告新增「浏览器面板归因」段**：`/lagfix report` 在「侧栏开合」之后输出，按以下分组统计：
  - **稳定浏览器**：`webview=1`、面板打开、文档有焦点，不在回前台 3 秒窗口，且该样本自己的 `paneDiagOn` 不是关闭；有切换记录时再排除**同窗口**切换后 30 秒内的候选。并列宿主帧 P50/P95 中位、长任务中位/最多、宿主 LoAF 最长帧。
  - **回前台 3 秒**：文档有焦点且距回到前台不超过 3 秒，不限浏览器；用于把采样时刻落在该窗口内的回前台尖峰从常开态里分出来。实机 12:16:02 的尖峰出现在 2375ms，2 秒窗口会漏，故取 3 秒；3 秒外的样本仍可能含更早尖峰，报告会明示；该组不输出宿主 LoAF。
  - **无焦点**：明示「不计入浏览器性能结论」；检测到 guest 但文档无焦点时单独提示可能 guest 抢焦点或窗口失焦。
  - **没有选中的 guest**：侧栏打开但 `webview=0` 时中性说明「预览/终端等普通面板也会如此」，不推断宿主结构变化，也不能据此说「没有卡顿」；只在隐藏/丢锚点样本检测到 guest 时单独说明，不说成「本文件没有 guest」。
  - **旧样本 / 全为 null**：分别提示「v0.4.5 前的旧样本」与「暂停/自禁用/查询异常」，不回退成 0。
  - 结论句只在证据齐全时打印：稳定浏览器宿主 P95≤16ms 且宿主 LoAF 最长帧≥100ms → 「宿主 UI 帧平滑，但宿主主线程仍有 ≥100ms 长帧；来源未分（guest 合成/宿主定时器/样式），不能据此认定是 guest 页面内部」；宿主 P95>50ms 且宿主 LoAF 最长帧≥100ms → 「宿主也被拖慢，需继续分回前台/切换/浏览器面板」。
  - 统计范围行显示样本数与窗口 id；多窗口明示「跨窗口汇总，中位数可能混合窗口」；最新样本为暂停/自禁用时明示「以下为历史有效样本汇总」。最新样本 `paneDiagOn=false` 时只说明最新样本关闭归因，历史有效稳定样本仍保留。
  - 稳定组有数据时明示：帧 P50/P95 为最近 30 秒窗口、宿主 LoAF 为本采集周期值，3 秒窗口外的样本仍可能含更早的回前台/加载尖峰；没有切换记录时明示「无法排除切换后尖峰」。
- **「侧栏开合」段补 P50**：面板打开/关闭两组在原有帧 P95、长任务、DOM 中位后追加 `P50 中位`；旧样本没有 `frameP50` 时显示 `-`；P50 只覆盖部分样本时样本数仍按全部有效行计。

新增/更新断言覆盖（本机最终结果：observer 634 项、报告 165 项，全部 PASS）：

- 正常样本 `focus=true/false`；选中的 browser-use tab 有 guest 为 `webview=1`，未选中 tab 仍挂载为 `0`；人类浏览器选中 tab 为 `1`，存在未选中 browser-use tab 时仍能识别；可见的插件 UI/奖励页/预览 `<webview>` 为 `0`，且不再裸查 `document.querySelector("webview")`；旧宿主只认浏览器专属 `data-testid`/`partition` 且有布局盒的 guest；
- `document.hasFocus()`、选中 tab 查询、浏览器 guest 列表查询各自抛异常时返回 `null`，不向宿主冒泡；
- 暂停样本 `focus=null, webview=null`，恢复后重新读取；
- 自禁用样本 `focus=null, webview=null`；`__lagfixOff()` 后仍按正常采集写入 `focus/webview`（本版不新增清理），既有还原路径不变；
- 报告覆盖稳定浏览器、回前台 3 秒（含 2375ms/3001ms 边界）、`sinceVisibleMs=null` 时窗口不可判断且不进入稳定组、无焦点、guest 存在但文档无焦点、没有选中的 guest、只在 hidden/miss 中检测到 guest、侧栏关闭、侧栏标记未知、旧样本、全 null、空日志；归因启用且文档可见时 `sinceVisibleMs` 为数值，不会因从未切出而永久缺失；
- 稳定浏览器组不混入回前台 3 秒样本与无焦点样本；同窗口切换后 30 秒内候选被排除，切换时间按窗口隔离（A 窗口切换不误伤 B 窗口），全部候选都被切换排除时输出专用提示；无切换记录时明确提示无法排除切换后尖峰；`paneDiagOn=false` 时按样本判断，最新样本关闭归因不丢弃历史稳定样本，也不输出矛盾的侧栏计数；
- 宿主 P95>50ms 的结论分支、样本少于 3 条提示、LoAF 缺失时不输出、回前台组不输出 LoAF、跨窗口汇总标注；
- `print_pane_diag` 的 P50 正常与缺失显示；P50 只覆盖部分样本时样本数仍按全部有效行计；
- 版本摘要更新为 v0.4.5。

## 已知边界

- 自动化测试使用合成 DOM/store，不等同于 Windows/macOS 实机验收；首次安装后仍需实机确认 `/lagfix report` 出现浏览器标记。
- `focus` 只表示文档是否有前台焦点，不表示窗口是否被其他应用遮挡；`webview=1` 只表示当前选中的浏览器 tab（browser-use 或人类浏览器）里有 guest，不证明页面内部一定在忙。未选中的 tab 即使仍挂载 guest 也不计入；关闭侧栏但浏览器 tab 仍处于选中态时仍可能为 `1`，报告会用「侧栏标记为关闭」单独提示。插件 UI、奖励页、预览等其他 `<webview>` 不计入。
- 若宿主把浏览器改成 iframe/其他标签或放进 shadow root，`webview` 会返回 `0` 或 `null`；报告会明示「未检测到选中的 guest」，不能推断「没有卡顿」或「宿主结构变化」。
- 本版只做归因，不优化 `<webview>` guest 内部 JS，也不处理切换瞬间的秒级帧或卡顿时的画面跳动。实机证据显示稳定打开浏览器时宿主帧 P50/P95 中位为 6ms，但宿主主线程 LoAF 仍有 130–337ms 长帧；LoAF 来自宿主 renderer，看不到 guest 内部，不能证明是 guest 页面自己的主线程成本。下一步要结合第三方定时器归因/上游证据再分来源，不能直接把长帧推给 guest。
- 稳定组只按采样时刻排除回前台 3 秒，且默认采集间隔是 5 秒；回前台后第 3–5 秒的样本仍可能包含回前台尖峰。帧 P50/P95 是最近 30 秒窗口，宿主 LoAF 是本采集周期值，也不等同于“最近 3 秒干净”。报告会明示这一点；有切换记录时会额外排除**同窗口**切换后 30 秒内候选，没有记录时明示无法排除。`refocus.sinceVisibleMs=null` 只出现在启用归因时文档隐藏、探针尚未启用或旧样本，回前台窗口不可判断，这类样本不进入稳定组，报告单独说明；归因启用且文档可见时 observer 会以启用时刻作为可见起点，因此从不切出再切回的会话在 3 秒后也能进入稳定组。
- 用户反馈卡顿时会出现「画面跳动」；当前样本没有滚动偏移/锚点漂移字段，本版不把它归因到浏览器或补页。需要单独设计只读的滚动位置跳变观测（例如记录滚动容器 `scrollTop` 的异常跳变与 `loadOlder` 前后锚点差），再决定是否做行为缓解。
- 多窗口同时打开时，报告把各窗口样本汇总统计，并在标题行列出窗口 id、提示「跨窗口汇总，中位数可能混合窗口」；本版不按窗口拆分中位数。若需要窗口级结论，先按窗口重跑或后续版本再加分组。
- `focus`/`webview` 与 `paneOpen` 都是文档级信号：如果隐藏的会话 pane 仍挂载着选中的浏览器、而当前可见 pane 是预览/终端，`webview` 可能仍为 `1`，`paneOpen` 也可能来自第一个侧栏外框。报告按汇总解读，不承诺按会话 pane 归因；多 pane 场景不要把稳定组当成当前可见 pane 的精确状态。
- `document.hasFocus()` 在点击/滚动 `<webview>` guest 时是否仍为 `true` 尚未实机验证。Electron 上游曾记录 guest 抢焦点时顶层文档 `hasFocus()` 可能为 `false`（electron/electron#26497，Electron 11–13）；ZCode 使用的 44.7.0 未在本版复核。若确认如此，真实使用浏览器的样本会进入「无焦点」组，报告会单独提示「guest 存在但文档无焦点」；此时看该提示与回前台组，不能把稳定组当成浏览器使用全貌。后续如需精确区分，再加只读的窗口焦点字段。
- `paneDiagOn` 按每条样本自己的设置判断；如果用户在中途关闭归因，最新样本会提示最新状态，历史有效样本仍保留。不同窗口的 `paneOpen`/`refocus` 不保证同时可用，跨窗口结论仍只做汇总。
- v0.4.4 曾把「切换瞬间微批」列为 v0.4.5 候选；实机数据显示切换后的主要成本是目标会话的补页潮，不是微批，因此本版按拍板改为只读归因，微批与补页节流留待后续单独拍板与 A/B。
