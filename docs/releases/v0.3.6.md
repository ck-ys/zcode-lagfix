# v0.3.6

发布时间：2026-11-12
主题：补页批量（O8，实验、默认关）——减少同一段历史需要的补页次数，不改消息与顺序

## 新增

- **补页批量（`loadOlderPageLimitOn`，默认关，实验）**：ZCode 的 `loadOlder` 默认每页 60 行，协议上限 200 行。开启本项后，插件只对**无参**调用把页大小替换为 200：
  - 无参调用 → `orig.call(this, 200)`；
  - 显式传参、开关关闭、观察器自禁用 → `orig.apply(this, arguments)`，一个字节都不改。
  - 必须保留 `this`、Promise、异常、`loadingOlder`/`canLoadOlder` 状态与返回内容；不跳过、不合并、不缓存、不写 store。
- **独立包装条件**：`scrollDiagOn || loadOlderPaceOn || loadOlderPageLimitOn` 任一开启就包装当前主 store 实例的 `loadOlder`；只开 O8 也能生效，三项全关才卸载并回到原始实现。
- **样本新增 `page`**：`{ "limit": 200, "installed": true, "applied": N, "passthrough": M }`。`applied` 统计真正替换为 200 的无参调用，`passthrough` 统计调用方显式传参、原样放行的次数；`installed=false` 表示开关开着但包装尚未装上（计数不可用）。只在开关开时上报，关闭为 `null`；从关到开 / 换 store / 自禁用 / `__lagfixOff()` 清零，暂停观测不重置（替换仍生效）。
- **报告升级**：`/lagfix report` 的补页段显示页大小、生效次数与显式参数放行次数；开关开着但 `applied=0` 时明确提示「还没有无参补页调用或包装尚未装上」。

## 设置面板

- 「性能」→「实验（默认关闭）」新增一行：**补页批量 · 实验**。
- 文案按「会做什么 / 不会做什么 / 代价」组织：只改加载更早消息时的单次页大小；不跳过、不删除、不改变顺序；单次内容更多，个别情况下滚动到更早历史时位置可能轻微调整。
- `__lagfixOff()`、自禁用会关闭替换并清零计数；暂停观测只停采集，替换仍生效、计数继续累计。`__lagfixOff()` 同时把开关置为 `false`。

## 安装注意

- 本次升级仍会修改 `app.asar`。安装/更新后请**完全退出并重新打开 ZCode**，让新的 `lagfix-main.cjs` 与 `lagfix-observe.js` 生效。
- 本项默认关闭，升级后不会自动改变补页行为；需要在面板「性能」页手动开启，或只用于 A/B 对照。

## 已知边界

- 本项只减少补页**次数**，不降低单次补页耗时。后端每次补页仍要过滤整个会话投影并整窗拷贝，这是 ZCode 自身成本；不能写成「补页卡顿已解决」。
- 页大小依赖宿主契约：ZCode v3.17.2 源码与安装版 v3.18.1 `app.asar` 均核对到 `loadOlder(limit = 60)` 与 `rowsRangeMaxLimit = 200`，宿主调用点为无参。实现不自动探测契约变化；若未来宿主移除参数或降低上限，传 200 会被忽略或截断，行为自然退回默认，需要按报告中的补页次数与宿主版本人工复核。
- 一次加载 200 行，单次返回内容更多；个别情况下滚到更早历史时位置可能轻微调整。顶部空白、锚点漂移与 DOM 峰值都列入 A/B 门槛。
- 暂停观测时替换仍生效，计数继续累计；若暂停期间宿主重建 projection store，替换要等恢复观测或下一次设置变更/切会话才装到新 store。这是暂停不跑看门狗的取舍，不是静默保证。
- 包装只装在主 store 实例上；如果宿主把 store 冻结或不允许写自有属性，会降级为不装，不改变宿主行为。`installed=false` 时报告会明确提示计数不可用。
- 与「大会话翻页降频」独立：降频先决定是否调用，本项只决定调用时的页大小；两项都关时包装器按原条件卸载。
- 默认关闭；需实机 A/B（同一会话、同一段历史、同一滚动路径，关→开→关至少 3 轮）。未过线保持默认关闭，不用「少发请求」代替「不卡了」。
