# v0.4.2

日期：2026-11-12
主题：观测口径与包装器生命周期加固，不新增缓解项。

## 新增

- 帧统计改为真正的最近 30 秒窗口：`frameRing` 上限从 300 提高到 3600（120Hz × 30s）。旧上限在 120Hz 下只有约 2.5 秒，会让 P95 与角标漏掉 5–30 秒内的尖峰。
- 样本新增 `frameMaxWindow`（最近 30 秒内最长帧）与 `frameMaxAll`（attach/切会话以来最长帧）；旧字段 `frameMax` 保留为历史值，旧报告/消费端不受影响。角标与悬停统计只看窗口值。
- `/lagfix report` 的「真实帧间隔」段分别显示「单帧最长（30s 窗口）」与「历史最长（attach/切会话以来）」；旧样本没有窗口字段时标注为历史值，不再把两个口径混成一个数。

## 修复

- 宿主在运行期替换 `subscribe` 或 `loadAllOlder` 时，插件不再把旧包装记录当作仍然生效：marker 记录 `{orig, wrapped}`，只有当前方法仍指向本插件包装时才复用；关闭「合并刷新」「大历史会话保护」、`__lagfixOff()` 或 observer 自禁用时只还原自己那一层，不覆盖宿主新实现。
- 「大会话翻页降频」的旧 `loadOlder` 包装增加代际门控：换 store、释放包装后，宿主缓存的旧引用直接调用原方法，不再跳过、不计数、不写补页明细。
- 「第三方定时器归因」在 `setTimeout`/`setInterval` 被宿主替换或包裹后，会如实上报 `supported=0`、`lost=1`，旧 wrapper 不再继续抓栈/计数；重新开启时以当前全局实现为 original 重新安装，关闭时只还原自己那一层。
- 报告一致性：
  - 最新样本已关闭滚动诊断/输入观测时明确打印「已关闭」，不再向前回退旧数据；暂停/dead 时回退会标注「（最近一次有效样本）」。
  - 补页、长帧、定时器明细带 `epoch`；跨代际停止回退，避免关→快速重开后把上一轮明细贴到当前轮。
  - 时间戳只接受 2000–2100 年；`t=1e300` 等结构合法但语义越界的值显示 `-`，报告不抛异常。

## 安装注意

- 本版不新增设置项、不改变任何默认开关，也不把实验项转为默认。
- 仍需通过源码安装器或插件市场安装；安装会修改 `app.asar`，成功后必须**完全退出**并重新打开 ZCode（仅关闭窗口不算）。
- 不读写 `~/.zcode/cli/db.sqlite`，不读会话正文，不打开 CDP，不联网上报；网络请求仍只有用户手动或可选自动检查公开 GitHub Releases。

新增断言覆盖：

- 120Hz 下保留超过 300 帧；窗口最大值只取最近 30 秒，历史最大值保留窗口外尖峰；
- 宿主替换 `subscribe` / `loadAllOlder` 后重新包装新实现，关闭后宿主实现保留；
- T1 失配 `supported=0/lost=1`，旧 wrapper 不计数，关闭不覆盖宿主，重开包当前实现；
- 报告关闭态、回退后缀、三类明细 epoch 跨代断点、越界时间戳。

## 已知边界

- 自动化测试使用合成 DOM/store 与假定时器，不等同于 Windows/macOS 实机验收；首次安装后仍需实机确认观测与开关。
- 本版只修观测口径与还原边界，不降低 ZCode 自身补页/渲染成本，也不改变空闲期长帧的来源；下一步（v0.4.3）候选是插件自身开销微优化与安装器/日志清理独立 chore，均需先量后改。
- `frameRing` 扩容只增加固定大小数组开销（3600 项），不改变采集频率、日志字段语义或宿主数据。
