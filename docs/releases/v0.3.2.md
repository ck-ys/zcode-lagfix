# v0.3.2

多会话归因与补页明细版本。只补证据，不改宿主行为：按 `sid` 记录每个会话的提交/帧、DOM、挂载 turn、滚动 P95 与可见性；`loadOlder` 记录最近 10 次调用的耗时、行数变化与触发来源。设置面板新增「多会话归因」开关，`/lagfix report` 新增对应两段。

仍然保持原有边界：不改消息与会话数据、不写 store、不读写 `db.sqlite`、不开 CDP、不联网上报。唯一的网络请求仍是用户手动点击「检查更新」时查询一次 GitHub Releases。

## 新增

- **多会话归因（只读，默认开）**：遍历宿主已有的 `[data-session-id]` pane，按 sid 建桶（最多 5 个，按最近活跃排序）。每个桶记录 `sid / visible / lastActive / frames / commitRate / mountedTurns / dom / scrollP95`；隐藏 pane 也记录并标 `visible=false`。提交次数来自 `data-projection-seq` 的属性值变化，同值重写不计数；不读消息正文、不写 store。
- **会话滚动 P95**：时间线滚动时按 `pane.closest("[data-session-id]")` 归到对应桶，只统计该 pane 滚动后 200ms 内的帧；没有滚动的会话为 `null`。滚动手势仍由现有捕获监听处理，不新增第二个 rAF 循环。
- **`loadOlder` 最近 10 次明细（随滚动诊断）**：每条记录 `t / ms / ok / rowsBefore / rowsAfter / trigger`；`rowsBefore/rowsAfter` 只读 `this.state.snapshot.rows.window.length`，不读分页内容。`trigger` 为 `scroll`（调用前 2s 内有时间线滚动）、`initial`（本次包装后首次调用，或距最近 attach ≤5s）、`unknown`。
- **面板「多会话归因」**：观测页诊断组新增一行，默认开；「!」说明写清影响/不影响。关闭后 `sessions` 为 `null`，不再遍历会话 pane，并断开会话 MutationObserver。
- **`/lagfix report` 两段新输出**：多会话桶逐项打印（含 `draft`/空 sid）、`loadOlder` 最近 10 次明细、Top 慢补页与 `scroll/initial/unknown` 计数；旧样本没有字段时给提示。

## 调整

- **`loadOlder` 只包主 store 实例**：宿主 `loadOlder` 定义在 `ConversationProjectionStore` 原型上，但调用点是 `lease.store.loadOlder()`。本版不再修改共享原型，隐藏会话的补页不会进入主会话明细；释放时删除实例上的包装属性，恢复原型查找。
- **5 桶上限不再周期性轮换**：发现阶段满 5 个后，额外 pane 只观察不建桶；只有它出现真实提交/滚动时，才淘汰最久未活跃的旧桶。新桶 `lastActive=0`，空闲 pane 不会伪装成“刚活跃”而挤掉真正有数据的会话；`MutationObserver` 目标集合不变时不再每轮 `disconnect/reobserve`。
- **暂停语义**：暂停期间 `sessions`/`loadOlderDetail` 为 `null`，`loadOlder` 原样放行、不累计明细/calls；不再把暂停时刻写成所有桶的 `lastActive`；恢复时重新同步 pane 并从当前时刻起算 `commitRate`，分母不包含暂停时长。
- **占位 sid**：宿主未分配会话 id 时写 `"draft"`（`sessionId ?? "draft"`），过渡态也可能是空字符串；两者都按占位处理，pane 切成真实 sid 后删除占位桶，不占 5 个名额。
- **切会话不冒充活跃**：`data-session-id` 变化本身不更新 `lastActive`；已跟踪的真实会话切到另一个真实会话时正常换桶（当前主 pane 不缺席），draft/空 sid 与额外 pane 不借切换抢名额；同值 SID 重写直接忽略。
- **探针生命周期**：store 暂时取不到或锚点丢失时释放 `loadOlder` 实例包装，避免旧实例继续记账；主 store 切换时清空上一个会话的明细环；pane 从卸载状态重新挂回时立即补采 DOM/turn，不等下一个 60s 窗口。
- **角标避让宿主浮层**：上下文容量、模型/工具菜单等 Radix portal 不在 composer 兄弟链里，角标现在会单独扫描并与它们相交时让到浮层上沿；浮层顶到视口顶端时隐藏角标，不再压住面板内容或截走点击。
- **DOM 采样固定 60s**：每会话 `mountedTurns/dom` 每 60s 遍历一次，新桶立即采一次；不再跟随 5s 采集周期遍历 pane 子树。
- **明细按变化发送**：`loadOlderDetail` 只在变化时携带完整数组，未变化的样本发 `[]`，避免每 5s 重复最多 10 条记录；报告端向前找最近一次非空数组。
- **payload schema**：正常样本新增 `sessions` 与 `loadOlderDetail`；dead/paused/异常样本固定带 `sessions: null` 与 `loadOlderDetail: null`，消费端不必判 `undefined`。
- **日志清理安全闸**：只删 `~/.zcode/zcode-lagfix/` 直接子项里命中白名单的普通文件；`lstat` 复核非符号链接/非目录/路径未越界，活动 `observe-*.jsonl` 与未轮转日志不删，`settings.json`、用户文件一律不碰。任何异常都跳过，宁可超预算也不误删。
- **报告口径**：`ok` 显示为「正常/异常」而不是「成功/失败」——宿主 `loadOlder` 内部 `rowsRange` 失败会打日志后正常 resolve；`rowsBefore==rowsAfter` 标「无变化」。`_fmt_ts(0/None)` 不再显示成 1970 年；非 dict 的 JSONL 行、坏 `trigger` 值不再导致报告崩溃。

## 安装 / 升级注意

- 从 v0.3.1 升级会替换 `app.asar` 注入；首次注入成功后必须**完全退出 ZCode（含托盘）再重开**，只关窗口或重开会话不算。
- 设置 key 仍是 `localStorage["lagfix.settings.v1"]`；新增 `sessionDiagOn`，默认 `true`。旧设置里没有该键时按默认值处理，不需要手动迁移。
- 不需要新依赖；仍然是 ZCode 桌面版 + Python 3.8+。

## 已知边界

- **最多 5 个桶**：发现阶段第 6 个及以后只观察不建桶，等它有真实提交/滚动才淘汰最久未活跃的旧桶，历史数字随之丢失；多个会话同时活跃且超过 5 个时仍可能发生名额竞争。
- **`visible` 只代表 CSS/几何可见**，不代表“最前台”；分屏时两个 pane 可以同时为 `true`，被别的 pane 盖住但仍有布局的 pane 也算可见。
- **`frames`/`commitRate` 依赖宿主继续更新 `data-projection-seq`**：隐藏 pane 若被宿主停止渲染，会如实显示 0，这不等于“隐藏 pane 不耗资源”。
- **`mountedTurns`/`dom` 是 pane 子树口径**；`scroll.mountedTurns`/`domPeak` 仍是整窗口径，两者不能直接相加对比。每 60s 采样一次，大会话首采仍可能产生一次 >5ms 成本。
- **`loadOlderDetail` 只覆盖当前主 store 实例**，不是所有会话 store；`trigger` 是时间启发式，不能证明宿主内部调用原因。
- **`ok=true` 只表示 promise 正常结算**；宿主内部失败会被吞掉并 resolve，需要结合 `rowsBefore/rowsAfter` 判断 no-op。
- **日志量增加**：多会话归因每个样本约 0.4–0.6KB（5 个桶），`loadOlderDetail` 只在变化时发完整数组。默认 50MB 预算下如需更长历史，可在面板调大 `logMaxMB`。
- **本版不改变任何渲染/补页行为**，不应期待帧率变化；它的价值是让 v0.3.3 的缓解项（O3 补页合并 / O4 `content-visibility`）有数据依据。
