# v0.3.1 行为规格：滚动观测、输入延迟、遮罩抑制、面板重排

状态：已拍板（2026-11-11），实现前先于代码。
对应拍板页：`docs/decisions/v0.3.1-scroll-lag.html`（第 05、08、09、10、11、12 节）。

## 0. 范围

| 项 | 设置字段 | 默认 | 性质 |
| --- | --- | --- | --- |
| O1 滚动诊断 | `scrollDiagOn` | `true` | 只读观测 |
| O1b 输入延迟 | `inputLagOn` | `true` | 只读观测 |
| O2 滚动期隐藏消息层遮罩 | `maskOffOnScroll` | `true` | 可 A/B 的缓解 |
| A8 角标常驻 | 无字段（删除 `badgeVisible`） | — | 行为约束 |
| A9 面板信息架构重排 | 无字段 | — | 文案与分组 |

明确不做：O3 补页合并、O4 turn 内 `content-visibility`、O5 轻量模式、O6 turn 内再虚拟化、O7 多会话调度。
不改消息、会话、工具卡内容；不写 store；不读写 `db.sqlite`；不开 CDP；不联网。

## 1. 产品规则

### 1.1 O1 滚动诊断

1. 只统计**最近 200ms 内发生过时间线滚动**的帧；空闲帧不计入 `scroll.p95`，避免被稀释。
2. 滚动事件只认 `[data-v4-timeline-scroll="true"]` 作为 `event.target` 的事件；不向上 `closest()`，不监听 `window`。
3. `loadOlder` **只观测**：不拦截、不延迟、不改参数、不改页大小、不改返回值、不吞异常。
4. 观测不得新增第二个 rAF 循环；滚动帧采样复用现有 `rafTick`。
5. `scrollDiagOn=false` 时：`scroll` 为 `null`，不包装 `loadOlder`，不做 `mountedTurns` 查询，不做额外 DOM 计数。
6. 样本说明：`scroll.frames < 20` 时 P95 仅供参考，不做平滑、不填默认值。

### 1.2 O1b 输入延迟

1. 只统计落在 `.chat-composer-input-surface` 子树内的 `keydown`（capture 阶段，一次 `closest()`）。
2. 同一个待处理按键只记第一次时间；下一帧到来时计算 `帧时间戳 − 按键时间`，推进 30s 环形窗口。
3. 复用现有 rAF 循环，不新增循环，不 `preventDefault`、不改事件传播。
4. 只测量，不修复：规格与发布说明都必须写明这一点。
5. `inputLagOn=false`、观测暂停、observer 自禁用时 `input` 为 `null`。

### 1.3 O2 滚动期隐藏消息层遮罩

1. 时间线滚动时给 `document.documentElement` 加 `data-lagfix-scroll="1"`，**第一次滚动立即生效**（不做 debounce 到停滚）。
2. 停止滚动 180ms 后移除属性。用「deadline + 单定时器自重排」实现，不在每个 scroll 事件里 `clearTimeout` + `setTimeout`。
3. CSS 只覆盖消息层的 `mask-image`：

   ```css
   [data-lagfix-scroll="1"] [data-v4-timeline-message-layer="true"] {
     -webkit-mask-image: none !important;
     mask-image: none !important;
   }
   ```

   不覆盖 `mask` 简写，避免重置宿主其它 mask 属性；不改 `[data-v4-timeline-scroll]` 容器本身。
4. 前提（重要）：宿主现状是**内联** `style.maskImage`（无 `!important`）。作者的 `!important` 样式表规则优先于普通内联声明，所以有效。**若宿主改为带 `!important` 的内联写法，本项会静默失效**——不加兜底分支，靠 O1 的 `scroll.p95` 与人工 A/B 发现。
5. `maskOffOnScroll=false` 时：不添加属性；若已添加则立即移除并清定时器。

### 1.4 A8 角标常驻

1. 删除设置项与 `badgeVisible` 字段；角标不再提供用户可关闭的入口。
2. 布局性隐藏保留：设置页/弹窗内、被浮层遮挡、无可用输入框、上方无余量时仍自动隐藏（这不是用户开关）。
3. 旧 `localStorage` 中的 `badgeVisible:false` 直接忽略，不迁移、不删除该键（下次保存时自然消失）。
4. `Ctrl+Alt+L`（mac `Cmd+Alt+L`）与 `__lagfixSettings()` 保留为兜底入口。

### 1.5 A9 面板信息架构

分类改为：**状态条 / 观测 / 性能 / 维护**（原「修复」改为「性能」）。

| 页 | 行名（新） | 原行名 |
| --- | --- | --- |
| 状态条 | 显示文字 | 角标文字 |
| 状态条 | 信息量 | 角标内容 |
| 状态条 | 警告阈值 | 变黄阈值 |
| 状态条 | 严重阈值 | 变红阈值 |
| 观测 | 滚动诊断 | （新增） |
| 观测 | 输入延迟 | （新增） |
| 性能·渲染 | 渲染节流 | 订阅通知节流 |
| 性能·渲染 | 最短刷新间隔 | 节流窗口 |
| 性能·渲染 | 卡顿时自动放宽 | 自适应窗口 |

1. 状态条页顶部增加常驻说明：角标常驻显示，在设置页/弹窗中自动隐藏。

4. 每行「!」影响说明保留，文案随新名字调整，仍分「影响 / 不影响」两段。
5. 面板底部版本行改为 `v0.3.1`。

## 2. 状态所有者

| 状态 | 所有者 | 生命周期 |
| --- | --- | --- |
| 开关（5 个新/改字段） | `localStorage["lagfix.settings.v1"]` | 跨窗口/重启持久 |
| `scrollRing` / `loadOlderRing` / `inputRing` | observer 内存 | 30s 时间窗滚动 |
| `scrollEvents` / `anyScrollEvents` / `lafCount` | observer 内存 | 每采集周期清零 |
| `loadOlderCalls` / `loadOlderErrors` | observer 内存 | 自 observer 启动累计 |
| `domPeak` | observer 内存 | 30s 窗口内采样最大值 |
| `data-lagfix-scroll` | `document.documentElement` 属性 | 滚动开始 → 停滚 180ms |
| `loadOlder` 包装 | 目标对象（实例或原型）上的 `__lagfixLoadOlder` | 开关/自禁用/`__lagfixOff()` 时还原 |

不写入宿主 store、不写会话数据、不碰 `db.sqlite`。

## 3. 接口

### 3.1 设置字段

```js
DEFAULTS = {
  // ...原有字段
  scrollDiagOn: true,
  inputLagOn: true,
  maskOffOnScroll: true,
  // badgeVisible 已删除
}
```

`mergeStored` 只接受布尔值：非布尔（含 `"false"` 字符串）不覆盖默认。

### 3.2 `settingsSnapshot()`

新增 `scrollDiagOn`、`inputLagOn`、`maskOffOnScroll`；移除 `badgeVisible`。

### 3.3 `__lagfixCollect()` payload

正常样本新增两个字段：

```json
{
  "scroll": {
    "p95": 18, "max": 42, "events": 37, "anyEvents": 41,
    "frames": 210, "mismatch": false,
    "loadOlderCalls": 6, "loadOlderP95": 210, "loadOlderMax": 480, "loadOlderErrors": 0,
    "mountedTurns": 34, "domPeak": 9230,
    "lafCount": 4, "lafMax": 180
  },
  "input": { "p95": 32, "max": 210, "samples": 41 }
}
```

- `scroll`：`scrollDiagOn=false` 时为 `null`；`lafCount`/`lafMax` 在不支持 `long-animation-frame` 的浏览器为 `0`/`null`。
- `input`：`inputLagOn=false` 时为 `null`。
- `mismatch`：本周期 `anyEvents > 0 && events === 0`，用于区分「没人滚」与「选择器失配」。
- dead / paused 的廉价 payload 同时带 `scroll: null` 与 `input: null`，保持 schema 稳定。

### 3.4 控制台入口

`window.__lagfixCollect()`、`window.__lagfixOff()`、`window.__lagfixDiag()` 保留；`__lagfixDiag()` 增补滚动/输入环形窗口长度，便于手查。

## 4. 事件顺序

### 4.1 滚动采样

```
scroll (capture, target 命中时间线容器)
  → lastScrollAt = now
  → scrollEvents++ / anyScrollEvents++
  → setScrollMaskActive(true)      // 仅 maskOffOnScroll 开启
rafTick(下一帧)
  → 帧间隔 d 正常记录
  → 若 scrollDiagOn && now - lastScrollAt <= 200：scrollRing.push({t, ms:d})
collect
  → scroll.p95/max/frames 取 30s 窗口
  → events/anyEvents/lafCount 输出后清零
```

### 4.2 遮罩属性生命周期

```
第一次 scroll → setAttribute("data-lagfix-scroll","1") → deadline = now + 180
             → 若尚无定时器：setTimeout(check, 180)
后续 scroll   → 只刷新 deadline（不重建定时器）
check()      → 未到 deadline：按剩余时间重排；已到：removeAttribute，清句柄
```

### 4.3 输入延迟采样

```
keydown (capture, target 在 .chat-composer-input-surface 内)
  → 若 inputPendingAt 为 0：inputPendingAt = now
rafTick(下一帧)
  → 若 inputPendingAt：inputRing.push({t, ms: t - inputPendingAt})；inputPendingAt = 0
```

### 4.4 `loadOlder` 观测

```
attach/看门狗找到 store
  → applyLoadOlderProbe(store)（scrollDiagOn=false 或已包装则跳过）
调用 loadOlder
  → loadOlderCalls++
  → orig.apply(this, arguments)
  → 同步抛错：loadOlderErrors++ 并原样抛出
  → 返回 thenable：挂上 then(记录耗时, 记录错误+耗时)，**返回原 promise**
  → 返回其它：记录耗时后原样返回
```

## 5. 关闭与清理路径

| 触发 | 必须完成 |
| --- | --- |
| 面板关闭 `scrollDiagOn` | 释放 `loadOlder` 包装；清空 `scrollRing`/`loadOlderRing`/计数；`scroll` 变 `null` |
| 面板关闭 `inputLagOn` | 清空 `inputRing` 与 `inputPendingAt`；`input` 变 `null` |
| 面板关闭 `maskOffOnScroll` | 立即 `removeAttribute` + 清定时器 |
| 面板「恢复默认」 | 三个字段回到默认并重新应用（包装/属性/环形窗口一致） |
| `__lagfixOff()` | 三个字段置 `false` 并保存；释放包装；移除属性；清定时器与环形窗口 |
| observer 自禁用（`state.dead`） | 同上全部清理；`scroll`/`input` 为 `null` |
| `pagehide` / `beforeunload` | 移除 `data-lagfix-scroll`、清定时器 |
| 跨窗口 `storage` 事件 | 与面板同一套应用逻辑，行为一致 |

`__lagfixOff()` 之后不得再添加 `data-lagfix-scroll`，也不得重新包装 `loadOlder`。

## 6. 宿主契约与前提

| 用途 | 选择器/接口 | 失效表现 |
| --- | --- | --- |
| 时间线滚动容器 | `[data-v4-timeline-scroll="true"]` | `scroll.events=0` 且 `anyEvents>0`（`mismatch:true`） |
| 消息层遮罩 | `[data-v4-timeline-message-layer="true"]` + 内联 `mask-image` | 滚动期仍看到渐隐 |
| turn 单元 | `[data-v4-turn-unit="true"]` | `mountedTurns=0` |
| 输入框 | `.chat-composer-input-surface` | `input.samples=0` |
| 补页方法 | store 实例或原型上的 `loadOlder` | `loadOlderCalls` 恒为 0 |

如果 `mismatch:true` 持续出现，先跑 `/lagfix report` 判断是宿主改版还是选择器不匹配，不要凭猜改代码。

## 8. 已知边界与非目标

- 观测器本身有成本：`mountedTurns` 与 DOM 计数每周期各一次全树遍历；单次 >5ms 时 `domPeak` 退回 60s 采样。
- `scroll.p95` 只代表「滚动后 200ms 内的帧」，不等于整段会话的帧率；要与 `frameP95` 分开看。
- `input.p95` 只代表「按键到下一帧」，包含浏览器自身的输入延迟与主线程排队，不能区分二者。
- O2 只影响绘制，不改布局与 DOM；若收益 <10%，说明遮罩不是主因，按第 12 节走 O3/O4。
- 不做事件级归因（哪个 turn、哪个 Markdown 块最贵），那需要宿主配合。
