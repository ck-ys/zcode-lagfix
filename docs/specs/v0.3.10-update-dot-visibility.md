# v0.3.10 行为规格：更新红点必须实际可见

- 版本：0.3.10
- 日期：2026-11-12
- 范围：角标右侧与维护页「检查更新」行的更新红点显示逻辑
- 拍板：用户反馈「检查到新版本，但角标旁没有红点，设置页也不明显」；本版只修红点可见性

## 1. 根因

v0.3.7 起两个红点使用 `lg-update-dot` / `lg-update-dot-inline` 样式，样式里默认写了 `display:none`。`syncUpdateDot()` 在需要显示时写的是：

```js
el.style.display = on ? "" : "none";
```

空字符串会删除内联声明，浏览器回落到样式表里的 `display:none`，因此红点在任何情况下都不会显示。测试用的假 DOM 不计算样式，只比较 `style.display === ""`，所以 v0.3.7–v0.3.9 的自动化用例没有发现。

## 2. 产品规则

- 红点默认隐藏。
- 当且仅当以下条件全部满足时，两处红点都显示：
  - 缓存或本次结果 `newer === true`；
  - 缓存 `current === VERSION`；
  - `latest` 非空且 `latest !== VERSION`。
- 显示时脚本必须给显式 `display` 值（`inline-block`），不能写空串依赖样式表默认值。
- 任一条不满足或结果为 `newer=false` 时，两处都写 `display:none`。
- 不改变红点位置、大小、颜色、点击行为、检查更新请求或缓存结构。

## 3. 状态与接口

- 只改 `syncUpdateDot()` 的两行显示值。
- 不新增设置项、DOM 属性、网络请求或日志字段。
- 角标红点 id：`lagfix-overlay-badge-update-dot`；维护页红点 id：`lagfix-settings-panel-updatedot`。

## 4. 验收场景

`tests/observe_smoke.mjs` 必须覆盖：

1. 默认（无新版本）两处红点 `display === "none"`。
2. 有新版本（`newer=true`、`current===VERSION`、`latest!==VERSION`）时两处红点 `display === "inline-block"`。
3. 跨窗口 storage 更新缓存后，红点仍按上述规则显示/隐藏。
4. `current > latest`（发布通道未更新）时不显示红点。
5. `__lagfixOff()` 清缓存后两处红点隐藏。

实机复核：

6. 安装 v0.3.10 后完全重启；在维护页点「检查更新」，若确有更高版本，角标右侧与「检查更新」行同时出现红点；返回会话页红点仍在。
7. 关掉自动检查或清缓存后红点消失；`current` 等于最新发布时红点不出现。
