# v0.3.3 行为规格：侧栏开合、面板常开期与回前台保护

状态：已拍板（2026-11-11，路线 A），实现前先于代码。
对应拍板页：`docs/decisions/v0.3.3-pane-lag.html`（第 03、04、05、06 节）。

## 0. 范围

| 项 | 设置字段 | 默认 | 性质 |
| --- | --- | --- | --- |
| P0 侧栏 + 回前台归因 | `paneDiagOn` | `true` | 只读观测 |
| P1 开合过渡保护 | `paneSwitchGuardOn` | `true` | 宿主行为缓解（420ms） |
| P2 面板常开期保护 | `paneHoldOn` | `true` | 宿主行为缓解（常开期） |
| P3 回前台保护 | `refocusGuardOn` | `true` | 宿主行为缓解（700ms） |
| P4 面板开关与说明 | 无新字段 | — | 「性能」页新增一组四行 |
| P5 报告展示 | 无新字段 | — | `/lagfix report` 新增两段 |

明确不做：O3 补页合并、O4 turn 内 `content-visibility`、O7 多会话调度策略、预览 HTML 自身绘制优化。
不隐藏/折叠/卸载对话或预览内容；不改 `loadOlder`/补页/返回值；不写 store；不碰 `db.sqlite`；不开 CDP；不联网。

## 1. 产品规则

### 1.1 P0 侧栏 + 回前台归因

1. 只读，不改宿主。用宿主已有标记定位：
   - `frame = document.querySelector('[data-workspace-side-frame="true"]')`
   - `panel = frame.closest('[data-panel]')`
   - `open = frame.getAttribute('aria-hidden') !== 'true'`
2. `detected=false` 表示宿主改版或该布局没有桌面侧栏（如移动端 overlay），不猜、不报错、不加保护属性。
3. 观察 `frame` 的 `aria-hidden` 与 `panel` 的 `class`：
   - `aria-hidden` 变化是开合的主信号；
   - `panel` 的 class 新增 `transition-[flex-grow]` 是宿主显式开合的最早信号。
   - 同一轮开合两个信号都出现时按 150ms 去重，只记一次。
4. 每次开合：
   - `switches++`（仅 `paneDiagOn=true` 时计入样本）；
   - 清空并重开一个 800ms 的帧窗口；窗口内 `rafTick` 的帧间隔进入 `paneSwitchRing`；
   - 采集时算 `switchP95` / `switchMax`，保留最近一次开合窗口的结果，直到下一次开合。
5. `panelPx` 每次采集读一次 frame 的 `getBoundingClientRect().width`；读不到时为 `null`。
6. 回前台同时监听 `visibilitychange` 与 `window.focus/blur`（Alt-Tab 不一定改 `document.hidden`）：
   - `hidden→visible`：记录 `hiddenMs = 本次 visible 时刻 - 上次 hidden 时刻`；
   - `blur→focus`：仅当 `document.hidden === false` 且确实发生过 blur 时算一次回前台；
   - 两种信号 500ms 内去重；首次加载的 `window.focus` 没有前置 blur，不记。
7. 每次回前台：
   - `sinceVisibleMs` 从本次回前台时刻起算；
   - 清空并重开一个 800ms 的帧窗口，采集 `p95` / `max`；
   - `flushes` 记录本次合并补发中**确实有 pending 通知**的订阅数；
   - `guardHits` 记录 P3 实际生效次数。
8. 只记布尔、宽度、时长、计数与帧统计；不记面板内容、标题、HTML、消息 id、会话正文。
9. `paneDiagOn=false`、观测暂停、observer 自禁用时 `pane`/`refocus` 为 `null`，并清空两个帧窗口与计数。若 P1/P2 仍然开启，保留最小的 `aria-hidden`/class 检测用于保护，但不输出样本字段。

### 1.2 P1 开合过渡保护

1. 仅 420ms（200ms 过渡 + 220ms 重内容 settle）。
2. 开合信号出现时给 `documentElement` 加 `data-lagfix-pane-switch="1"`，并启动/重置 420ms 定时器；重复开合会延长窗口。
3. CSS 只做两件事：
   ```css
   [data-lagfix-pane-switch="1"] [data-panel] { transition-duration: 0s !important; }
   [data-lagfix-pane-switch="1"] [data-v4-timeline-message-layer="true"] {
     -webkit-mask-image: none !important;
     mask-image: none !important;
   }
   ```
   不改布局、DOM、滚动位置与面板宽度；不覆盖 `mask` 简写。
4. `positionBadge()` 在保护窗口内顶部 early-return：不能再让 `surfaceRO` 在动画中间每帧跑 `composerSurface()` / `elementsFromPoint()` / 多次 `getBoundingClientRect()`。角标位置最多旧 0.4 秒。
5. 420ms 后移除属性，宿主下一轮开合恢复原过渡；关开关、暂停、`__lagfixOff()` 立即移除属性并清定时器。
6. `paneSwitchGuardOn=false` 时不加属性、不计数 `guardHits`，其它 P0 观测照常。

### 1.3 P2 面板常开期保护

1. `pane.open=true` 期间给 `documentElement` 加 `data-lagfix-pane-open="1"`。
2. 效果只三件：
   - 消息层 mask 关闭（CSS 同 P1，但只在面板打开期间）；
   - `effectiveThrottleMs` 至少 **300ms**；
   - 角标定位降到 **≤1 次 / 1.8s**。
3. 面板关闭立即移除 `data-lagfix-pane-open`，恢复原规则；不是永久关 mask。
4. `paneHoldOn=false` 时不加属性、不抬节流下限、不限制角标频率，P0 观测照常。

### 1.4 P3 回前台保护

1. 检测到 `hidden→visible` 或 `blur→focus` 后：
   - 把待补发的后台通知合并到一个 **120ms** 定时器，不再同步遍历全部 flusher；
   - **700ms** 内通知窗口至少 **400ms**；
   - 前 **300ms** 不定位角标。
2. 只延迟插件自己挂起的通知；宿主自己的回前台重绘不被拦截。
3. 多个 flusher 在同一个 120ms 定时器里调用，由 React 在同一任务内合并；不逐个错峰。
4. `window.focus` 首次加载也会触发，必须有 `lastBlurAt` 去重；同一轮 `visibilitychange` 与 `focus` 只算一次。
5. `refocusGuardOn=false` 时恢复原同步补发，`refocus` 仍按 P0 记录（若 P0 开），但 `guardHits=0`、不抬节流下限、不跳过角标定位。

### 1.5 P4 面板

1. 「性能」页滚动组之后新增一组「侧栏与回前台」，四行独立开关：
   - 侧栏与回前台统计（`paneDiagOn`）
   - 侧栏开合保护（`paneSwitchGuardOn`）
   - 面板常开保护（`paneHoldOn`）
   - 回前台保护（`refocusGuardOn`）
2. 每行说明统一写「会做什么 / 不会做什么 / 代价」，不写内部字段名；P0 关闭只影响样本输出，不伪装成“性能已改善”。
3. P1/P2/P3 关闭后立即移除对应属性/下限/定时器并恢复宿主原行为。

### 1.6 P5 报告

`/lagfix report` 在滚动/输入诊断之后新增：

1. **侧栏开合**：按 `pane.open=true/false` 分组打印 `frameP95` 中位数、长任务中位数、DOM 中位数；打印最近一次 `switches`、`switchP95`、`switchMax`、`guardHits`、`panelPx`。`detected=false` 时提示“宿主侧栏标记缺失或当前布局无桌面侧栏”。
2. **回前台**：打印最近一次 `hiddenMs`、`sinceVisibleMs`、`refocus.p95/max`、`flushes`、`guardHits`；按 `hiddenMs` 分桶（<1s、1–10s、10–60s、>60s）汇总。旧样本没有字段时打印 `[i]` 提示，不报错。
3. 开关关闭、暂停/dead 的 `null` 样本向前回退到最近一次有效样本，并标注“最近一次有效样本”。

## 2. 状态所有者

| 状态 | 所有者 | 生命周期 |
| --- | --- | --- |
| `paneDiagOn` / `paneSwitchGuardOn` / `paneHoldOn` / `refocusGuardOn` | `localStorage["lagfix.settings.v1"]` | 跨窗口/重启持久 |
| `paneFrame` / `panePanel` / `paneOpen` | observer 内存 | 检测到侧栏 → 关闭/自禁用 |
| `paneMO` | observer 内存（一个 MutationObserver，多目标） | `paneDiagOn || paneSwitchGuardOn || paneHoldOn` 且检测到 frame；目标不变时不重挂 |
| `paneSwitchRing` / `refocusRing` | observer 内存 | 最近一次开合/回前台后 800ms；下一次事件清空 |
| `paneGuardTimer` / `refocusFlushTimer` | observer 内存 | 420ms / 120ms 后自清 |
| `data-lagfix-pane-switch` | `documentElement` 属性 | 420ms；关闭/暂停/自禁用立即移除 |
| `data-lagfix-pane-open` | `documentElement` 属性 | 面板打开期间；关闭/暂停/自禁用立即移除 |
| `bgFlushers` 的 pending 通知 | 各订阅闭包 | 回前台后 120ms 内合并补发；卸载订阅时移除 |

不写入宿主 store、不写会话数据、不碰 `db.sqlite`。

## 3. 接口

### 3.1 设置字段

```js
DEFAULTS = {
  // ...原有字段
  paneDiagOn: true,
  paneSwitchGuardOn: true,
  paneHoldOn: true,
  refocusGuardOn: true,
}
```

`mergeStored` 只接受布尔值；非布尔不覆盖默认。

### 3.2 `settingsSnapshot()`

新增 `paneDiagOn`、`paneSwitchGuardOn`、`paneHoldOn`、`refocusGuardOn`。

### 3.3 `__lagfixCollect()` payload

```json
{
  "pane": {
    "detected": true,
    "open": true,
    "panelPx": 720,
    "switches": 3,
    "switchP95": 84,
    "switchMax": 190,
    "guardHits": 3
  },
  "refocus": {
    "hiddenMs": 8200,
    "sinceVisibleMs": 240,
    "p95": 96,
    "max": 210,
    "flushes": 2,
    "guardHits": 1
  }
}
```

- `paneDiagOn=false`、暂停、dead、错误 payload：`pane/refocus` 为 `null`，与 `scroll`/`sessions` 同口径。
- `pane.detected=false` 时 `open=false`、`panelPx=null`、`switches=0`、`switchP95/switchMax=null`、`guardHits=0`。
- 没有发生过回前台时 `hiddenMs=null`、`sinceVisibleMs=null`、`p95/max=null`、`flushes=0`。
- 数值一律四舍五入为整数；时长单位 ms。

### 3.4 `__lagfixDiag()`

新增只读字段，便于冒烟测试与现场排查：
`paneDetected`、`paneOpen`、`paneSwitches`、`paneGuardHits`、`paneGuardAttr`、`paneOpenAttr`、`paneSwitchFrames`、`refocusSamples`、`refocusFlushes`、`refocusGuardHits`、`hiddenMs`。

## 4. 事件顺序

### 4.1 打开右侧面板

```
宿主 isVisible: false → true
  ├─ React 提交：frame aria-hidden "true" → "false"
  ├─ panel class 新增 transition-[flex-grow]
  └─ MutationObserver 回调（同一批）
       ├─ 读 open=true
       ├─ 150ms 去重，只记一次 switch
       ├─ paneDiagOn: switches++，清空并重开 800ms 帧窗口
       ├─ paneSwitchGuardOn: 加 data-lagfix-pane-switch，420ms 后移除
       └─ paneHoldOn: 加 data-lagfix-pane-open，直到关闭
```

### 4.2 回前台

```
隐藏：visibilitychange(hidden=true) → hiddenAt=now，inputPendingAt=0
后台：订阅被 hiddenSkipOn 压到 1s，pending=true
回来：
  ├─ visibilitychange(hidden=false) → hiddenMs=now-hiddenAt，onRefocus("visible")
  ├─ 或 window.blur → lastBlurAt；window.focus → onRefocus("focus")
  └─ onRefocus（500ms 去重）
       ├─ refocusGuardOn: 120ms 后统一 flush pending
       ├─ refocusGuardOn: 700ms 内 eff >= 400ms
       ├─ refocusGuardOn: 300ms 内 positionBadge() early-return
       └─ paneDiagOn: 开 800ms 帧窗口，记录 flushes/guardHits
```

### 4.3 关闭面板 / 关闭开关 / 暂停 / 一键还原

```
关闭面板：aria-hidden "false" → "true"
  ├─ 记一次 switch（若在 150ms 去重窗口外）
  ├─ 420ms 保护重新计时
  └─ 立即移除 data-lagfix-pane-open

关 P1：立即移除 data-lagfix-pane-switch，清 420ms 定时器
关 P2：立即移除 data-lagfix-pane-open，effCache 失效
关 P3：立即清 120ms 定时器，恢复同步 flush，取消 400ms 下限/300ms 角标跳过
关 P0：pane/refocus=null，清空两个帧窗口与计数；P1/P2 仍开时保留最小检测
暂停/自禁用/__lagfixOff：移除两个属性、断开 paneMO、移除 visibility/focus/blur 监听、清定时器
```

## 5. 清理路径

以下四条路径必须做同一组清理：

1. 关闭对应开关（面板/storage/恢复默认/一键还原）。
2. 观测暂停（`observe=false`）。
3. observer 自禁用（`disable()`）。
4. `__lagfixOff()`。

清理内容：

- 移除 `data-lagfix-pane-switch`、`data-lagfix-pane-open`；
- `clearTimeout(paneGuardTimer)`、`clearTimeout(refocusFlushTimer)`；
- `paneMO.disconnect()`，清空 `paneFrame/panePanel/paneOpen`；
- `visibilitychange` 拆成两层：基线监听只要 `observe && !dead` 就保留（与 v0.3.2 一致，负责重置 `rafLast/inputPendingAt/lastTickAt` 并在 P3 关闭时同步补发）；P3 的 `window.focus/blur` 只在 `observe && (paneDiagOn || refocusGuardOn)` 时挂载。暂停/自禁用移除全部三个；`__lagfixOff()` 保留基线 `visibilitychange`，只移除 `focus/blur`；
- P0/P3 关闭时清空 `paneSwitchRing`、`refocusRing`、`paneSwitches`、`paneGuardHits`、`refocusFlushes`、`refocusGuardHits`、`hiddenMs`、`sinceVisibleAt`；暂停/自禁用/`__lagfixOff` 额外清空 `lastHiddenAt`、`lastBlurAt`、`lastRefocusAt`。P0 单独关闭不能清掉 P3 仍需要的 `lastHiddenAt/lastBlurAt` 与保护截止时间；
- `effCache.at = -1e9`，避免关闭后还沿用抬高的窗口。

## 6. 宿主契约

| 用途 | 选择器 / 接口 |
| --- | --- |
| 侧栏外框 | `[data-workspace-side-frame="true"]` |
| 侧栏开合状态 | frame 的 `aria-hidden`（`"true"` = 收起） |

## 7. 验收场景

### 7.1 P0

1. 默认设置四项均为 `true`。
2. 有 `[data-workspace-side-frame="true"]` 时 `pane.detected=true`；移除后下一次采集 `detected=false`。
3. `aria-hidden` 从 `"true"` 改 `"false"` 后 `pane.open=true`；改回后 `false`。
4. `panel` class 从空变 `transition-[flex-grow]` 时，即使 `aria-hidden` 未变，也记一次 switch；同一轮两个信号只记一次。
5. `switches` 随真实开合递增；同值重复 mutation 不递增。
6. `switchP95/switchMax` 来自最近一次开合后 800ms 的帧；下一次开合清空重算。
7. `panelPx` 是 frame 宽度；frame 缺失时为 `null`。
8. `paneDiagOn=false` 时 `pane/refocus=null`；重新开启后字段回来。
9. 只记宽度/布尔/计数，不读面板内容。

### 7.2 P1

10. 开合时 `documentElement` 出现 `data-lagfix-pane-switch="1"`，420ms 后移除。
11. 420ms 内再次开合会延长窗口，`guardHits` 递增。
12. 保护窗口内 `positionBadge()` 不更新角标位置（改 composer 矩形后角标不动）。
13. 窗口结束后角标位置恢复更新。
14. `paneSwitchGuardOn=false` 时不加属性，宿主过渡不被覆盖。
15. 关开关/暂停/`__lagfixOff()` 立即移除属性与定时器。

### 7.3 P2

16. `pane.open=true` 时出现 `data-lagfix-pane-open="1"`；关闭面板立即移除。
17. 面板常开时 `effectiveThrottleMs` 至少 300ms。
18. 面板常开时角标定位不超过 1 次 / 1.8s（第 2 次 1s 内的定位请求被跳过）。
19. `paneHoldOn=false` 时不加属性、不抬下限、不限制角标频率。
20. 面板关闭后 `eff` 回到原规则，mask 规则也回到原状。

### 7.4 P3

21. `hidden→visible` 后 `refocus.hiddenMs` 约等于后台时长，`sinceVisibleMs` 为数值。
22. 回前台后 pending 通知在 120ms 定时器里合并补发，`flushes` 只计有 pending 的订阅。
23. 700ms 内 `eff` 至少 400ms；700ms 后回落。
24. 前 300ms `positionBadge()` 不更新角标；300ms 后可更新。
25. 同一轮 `visibilitychange` + `focus` 只算一次；首次加载的 `focus` 不算。
26. `refocusGuardOn=false` 时同步补发、不抬 `eff`、不跳过角标，`guardHits=0`。
27. 旧样本没有 `refocus` 字段时报告不崩溃。
28. `window.blur` 后 `document.hidden` 仍为 false 时，`focus` 也能触发回前台。

### 7.5 清理

29. `__lagfixOff()` 后两个属性移除、`pane/refocus=null`、`paneMO` 断开、P3 的 `focus/blur` 移除、`visibilitychange` 基线保留（与 v0.3.2 一致）、定时器清空。
30. 重新开启后只挂一份监听/观察，属性生命周期正常。
31. 暂停观测时同样清理，恢复后重新挂回。
32. 自禁用（`disable()`）不留下半生效的属性和监听。

### 7.6 报告

33. `pane.detected=false` 时报告打印“标记缺失/无桌面侧栏”，不报错。
34. 有 open/closed 样本时按组输出帧 P95、长任务、DOM 中位数。
35. 有 refocus 样本时按 `hiddenMs` 分桶输出，并打印最近一次 p95/max。
36. 字段缺失/`null`/坏行时向前回退或提示，不崩溃。

## 8. 已知边界

- 面板常开期停 mask、把通知窗口抬到 300ms，聊天文字最多晚 300ms 刷新；Agent 收流、工具执行、消息落盘不受影响。
- 回前台后最多 120ms 才补发挂起通知，状态可能比宿主晚一拍；宿主自己的首帧重绘不被拦截。
- 开合动画变成瞬开/瞬收，是 P1 的明确代价；不想要就关 P1。
- 若卡顿来自预览 HTML 自身持续绘制或宿主其它长任务，这三段仍可能不够；那属于 O4/预览侧方案，v0.3.3 不算进验收。
- 自动化测试只覆盖合成 DOM 与计时逻辑，不等同于 Windows/macOS 实机验收；首次安装后仍需完全退出并重开 ZCode。
