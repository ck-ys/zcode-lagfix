# v0.4.2 行为规格：观测口径与包装器生命周期加固

日期：2026-11-12
状态：已实现（v0.4.2，2026-11-12）
关联拍板页：`docs/decisions/v0.4.2-observability-accuracy.html`

## 0. 一句话目标

不新增缓解项、不改默认开关、不改变宿主数据与布局；只把“插件怎么量、怎么还原、怎么报告”修准，让后续 T1 归因、O3/O4/O8b 的 A/B 与报告结论可信。

## 1. 范围

本版做：

- S1 帧统计口径：30 秒窗口、窗口最大值与历史最大值分离。
- S2 `loadAllOlder` 包装 marker 身份校验。
- S3 `subscribe` 包装 marker 复用身份校验。
- S4 `loadOlder`（O3）旧 wrapper 代际门控。
- S5 T1 定时器 probe 失配检测与 `lost` 标记。
- S6 报告一致性：关闭态、旧样本后缀、detail epoch、时间戳保护。
- 对应测试与版本文档。

本版不做：

- 不新增设置项、不改变任何默认值、不把实验项转默认。
- 不做自身开销微优化（更新状态缓存、环形统计合并、`mountedTurns` 降频、看门狗快速路径）——留到 v0.4.3，先量后改。
- 不做安装器/日志清理改动（per-pid 临时文件、流式 repack、`hook-error.log` 轮转）——独立 chore。
- 不启用 T1、不新增长帧上下文探针、不做 `driftPx`。
- 不折叠/隐藏内容，不修改消息、会话、工具结果，不读写 `db.sqlite`，不开 CDP，不联网上报。

## 2. S1 帧统计口径

### 2.1 环形窗口

- `frameRing` 上限从 300 提高到 3600，与 `scrollRing`/`inputRing` 一致：30 秒 × 120Hz。
- `frameStats()` 仍只统计 `now - t <= 30000` 的帧；`p50/p95` 口径不变。
- `frameStats()` 返回值增加 `max`（同一窗口内的最大值），避免调用方再扫一遍环。
- 角标判定、悬停统计、`__lagfixDiag` 如需要“最近最差一帧”，必须使用 `frameStats().max`，不得再读 all-time 值。

### 2.2 样本字段

正常样本保留旧字段并新增：

| 字段 | 含义 | 兼容性 |
| --- | --- | --- |
| `frameMax` | 旧字段，等同 `frameMaxAll`（attach/切会话以来） | 保留，旧消费端不受影响 |
| `frameMaxAll` | 显式历史最大值 | 新增 |
| `frameMaxWindow` | 最近 30 秒窗口内最大值 | 新增；报告优先使用 |

- `paused` / `dead` / 异常样本同步输出 `frameMaxAll: null`、`frameMaxWindow: null`，保持 schema 稳定。
- `hist` 仍保留 `fmax`（历史值）；新增 `fmaxWin` 供后续使用，不改变现有 UI。
- `pane.switchMax`、`refocus.max` 已经是“每次开合/回前台窗口清空后”的窗口值，本版不新增累计字段；报告文案不得把它们描述成历史累计。

### 2.3 报告

- 「真实帧间隔」行的「单帧最长」优先使用 `frameMaxWindow`；旧样本没有该字段时回退到 `frameMax`，并标注「旧样本为历史最大值」。
- 另起一行显示「历史最长」时使用 `frameMaxAll`（旧样本用 `frameMax`）。
- 不把两个值混为同一个数；不得出现报告 285ms、最新样本 303ms 这种前后不一致。

## 3. S2 `loadAllOlder` 身份校验

安装：

1. marker 结构改为 `{ orig, wrapped }`，不再只存 `orig`。
2. 命中已有 marker 时，只有同时满足以下条件才复用：
   - `marker.wrapped` 是函数；
   - `target.loadAllOlder === marker.wrapped`。
3. 不满足时：删除 marker，不覆盖当前 `target.loadAllOlder`；把它当作新的 `orig` 重新包装。

释放：

1. 只有 `rec.wrapped` 是函数且 `target.loadAllOlder === rec.wrapped` 时，才写回 `rec.orig`。
2. 无论是否写回，都删除 marker。
3. 宿主已替换实现时，不覆盖；面板/`fixSnapshot()` 不得继续显示旧 guard 生效。

## 4. S3 `subscribe` marker 复用

- `target.__lagfixThrottle` 命中时，只有 `marker.wrapped` 是函数且 `target.subscribe === marker.wrapped` 才复用。
- 不匹配时：删除 marker，按当前 `target.subscribe` 重新包装；`fixState.orig` 更新为当前实现。
- 若重新包装失败（不可写/非函数），`fixState.applied=false` 并给出原因；不得假报已生效。
- `restoreTarget()` 现有 identity 规则不变，继续只还原本插件那一层。

## 5. S4 O3 旧 wrapper 代际门控

- `makeProbedLoadOlder()` 的 `wrapped` 在 `"use strict"` 后第一行检查 `gen !== loadOlderGen`；不匹配直接 `orig.apply(this, arguments)`。
- 失效 wrapper 不得：
  - 执行 O3 跳过（不得返回已结算 promise）；
  - 增加 `loadOlderCalls` / `callsInWrap`；
  - 写入 `loadOlderDetail` / 观测环；
  - 应用 O8b 页大小。
- `applyLoadOlderProbe()` 在检测到 marker 身份不匹配、需要丢弃旧 wrapper 时递增 `loadOlderGen`，让宿主缓存的旧引用立即失效。
- 正常 marker 复用分支不递增代际，避免看门狗每 5 秒制造漂移。

## 6. S5 T1 定时器 probe 失配

### 6.1 probe 生命周期

- `timerProbe` 增加 `active` 字段。
- wrapper 入口先检查 `probe.active && timerProbe === probe`；不满足时直接调用原始方法，不抓栈、不记录、不计数。
- `setTimerProbe(true)` 命中已有 probe 时，只有 `window.setTimeout === wrappedTimeout` 且 `window.setInterval === wrappedInterval` 才复用。
- 失配时：
  1. 旧 probe `active=false`，`timerProbe=null`，`timerLost=true`；
  2. 若某一侧全局仍指向旧 wrapper，先还原该侧到旧 `orig`，避免新包装套旧包装；
  3. 以当前全局方法为 `orig` 重新安装；成功后 `timerLost=false`。
- 宿主包裹了我们的 wrapper 时，不覆盖宿主；旧 wrapper 通过 `active=false` 直通，新 wrapper 包在宿主实现外层。
- `setTimerProbe(false)`：只在全局仍指向本插件 wrapper 时还原；旧 probe 一律 `active=false`；清 `timerLost` 并 `resetTimerStats()`。

### 6.2 内部定时器

- `lafSetTimeout` / `lafSetInterval` 只在 probe 有效（`active` 且全局 identity 匹配）时使用 `probe.timeout/interval`；否则使用当前 `window.setTimeout/setInterval`，尊重宿主新实现。
- 关闭/暂停/自禁用/`__lagfixOff()` 四条路径必须清 `active`、`timerProbe`、`timerLost`，并恢复原引用。

### 6.3 样本与报告

- `timer` 样本新增 `lost: 0|1`：
  - `supported=1` 仅在 probe 有效时输出；
  - probe 失配或丢失时 `supported=0`、`lost=1`；
  - 全局不可写导致从未装上时 `supported=0`、`lost=0`。
- 报告 `timer` 段：
  - `lost=1` 打印「归因包装已失效（全局定时器被替换/包裹），计数不可用」；
  - 不把 `lost` 当成「没有慢定时器」。

## 7. S6 报告一致性

### 7.1 滚动/输入关闭态

- 取最新样本的设置：
  - `scrollDiagOn === false`：打印「滚动诊断已关闭」，不再向前回退旧 `scroll` 数据；`loadOlder` 明细段同样按关闭处理。
  - `inputLagOn === false`：打印「输入延迟观测已关闭」。
- 最新样本 `scroll`/`input` 为 `null` 但设置仍开（暂停/dead）：允许回退到最近一次有效样本，并加「（最近一次有效样本）」。

### 7.2 detail epoch

- observer 新增：
  - `timer.epoch`：`resetTimerStats()` 时递增。
  - `laf.epoch`：清空 `lafDetail` 时递增。
  - `scroll.loadOlderEpoch`：清空 `loadOlderDetail` 时递增。
- 报告取最新样本的 epoch；向前找明细时：
  - 候选 epoch 与最新一致才使用；
  - epoch 不同立即停止回退，并打印「本轮没有明细（上一轮已清空）」；
  - 旧样本没有 epoch 字段时，沿用现有回退逻辑，不把缺失当 0。
- 关闭滚动诊断/自禁用/换 store 的清理路径必须递增对应 epoch。

### 7.3 时间戳

- 新增安全时间格式化：只接受 2000-01-01 至 2100-01-01 的毫秒值；`localtime()` 异常时返回 `-`。
- `timer` 明细的 `t` 使用该格式化，`1e300` 等结构合法但语义越界的值不得让报告抛出异常。
- 旧样本缺少 `t` 时显示 `-`，不显示 1970 年。

## 8. 状态所有权与清理

- 设置仍以渲染端 `localStorage["lagfix.settings.v1"]` 为唯一事实；本版不新增键。
- 包装器 marker 仍挂在对应 store/target 上，不写入业务 store 状态。
- `__lagfixOff()`、暂停、自禁用三条路径：
  - 清 `timerProbe.active`、`timerLost`、timer/LAF/loadOlder epoch 计数；
  - 按 identity 规则还原 `loadAllOlder` / `subscribe` / `loadOlder`；
  - 不删除宿主的新实现。
- 本版不新增全局监听器、DOM 属性或定时器。

## 9. 验收场景

| 编号 | 场景 | 期望 |
| --- | --- | --- |
| A1 | 120Hz 下注入 >300 帧，含一条 10 秒前 300ms 尖峰 | `frameP95` 覆盖 30 秒窗口并计入尖峰；`frameMaxWindow` 与 `frameMaxAll` 分开 |
| A2 | 历史 800ms 尖峰已超出 30 秒，随后帧正常 | 角标/悬停不再显示高值；报告「窗口最长」正常、「历史最长」单独标注 |
| A3 | 装好大会话保护后宿主替换 `loadAllOlder`，再关保护/`__lagfixOff()` | 宿主新实现保持不变；marker 清除；面板不显示旧 guard 生效 |
| A4 | 宿主替换 `subscribe` 后看门狗重试 | 不把旧 wrapper 当已生效；围绕新实现重装或如实标未生效 |
| A5 | 缓存旧 O3 wrapper，换 store/释放后在滚动派发栈调用 | 原方法被调用；不跳过、不计数、不写 detail |
| A6 | T1 开启后宿主替换 `setTimeout`，再关闭 T1 | 不假报 `supported=1`；不覆盖宿主；不残留抓栈；重开以当前实现为 original |
| A7 | 关闭滚动/输入观测后打开报告；日志含 `t=1e300` | 明示「已关闭」；旧样本不冒充当前；报告不崩 |
| A8 | 全量回归 | 现有测试全 PASS；新增断言覆盖 A1–A7；版本四处同步 |

## 10. 测试矩阵

- `tests/observe_smoke.mjs`
  - frameRing 3600 / 30 秒窗口 / 窗口与历史最大值分离；
  - `loadAllOlder` 宿主替换后释放不覆盖、重新 apply 包新实现；
  - `subscribe` 宿主替换后不假报、重装；
  - 旧 O3 wrapper 在释放/换 store 后直通；
  - T1 失配 `supported=0/lost=1`、关闭不覆盖宿主、重开包当前实现；
  - `__lagfixOff` 清理新增状态。
- `tests/report_session_diag.py`
  - 关闭滚动/输入观测的文案；
  - 旧样本后缀；
  - timer/LAF/loadOlder epoch 跨代际停止回退；
  - `t=1e300` 不抛异常；
  - 旧样本缺少新字段时向后兼容。
- 全量：`node --check`、`py_compile`、现有 8 个测试套件。

## 11. 回滚

- 任一修复无法在合成夹具稳定断言，就不进入本版；不用实机“感觉”验收。
- `frameRing` 扩容若导致每秒统计成本明显（先量），退回“保留 300 帧 + 文案改为真实窗口”，不硬上。
- 包装器 identity 修复若导致看门狗反复重装，优先标未生效/`lost`，不引入超时兜底。
- 报告 epoch 对旧样本始终向后兼容；缺字段按旧逻辑显示。
