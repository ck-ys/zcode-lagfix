## 1. 产品规则

### 1.1 P0 卡顿来源定位（LoAF 归因）

1. 只读。数据源是浏览器 `PerformanceObserver` 的 `long-animation-frame` 条目，与 v0.3.1 已有的 `lafCount`/`lafMax` 计数共用同一个 observer：
   - observer 的安装条件从「`scrollDiagOn && observe`」放宽为「`(scrollDiagOn || lafDiagOn) && observe`」；关闭两个诊断开关后 observer 断开。
   - `lafCount`/`lafMax` 随 `scrollDiagOn`，每采集周期一起清零（本口径自本版起与 `lafCount` 统一；v0.3.1–v0.3.3 的 `lafMax` 跨周期保留，属本版修正——报告的「本周期最长」不再拿到陈旧值）。
2. `lafDiagOn=true` 且 `observe=true` 时，把**时长 ≥ 100ms** 的长帧条目写入 `lafDetail` 环（最多 10 条，超出淘汰最旧）：
   - `t`：宿主墙钟时间（Date.now()）；
   - `ms`：该帧总时长（四舍五入）；
   - `styleMs`：该帧**所有脚本**的 `forcedStyleAndLayoutDuration` 之和（四舍五入，缺省 0）——强制同步布局/样式时长。注意该属性在 `PerformanceScriptTiming`（scripts[] 条目）上，帧对象没有此字段，读帧级会恒为 0；
   - `scripts`：按耗时降序取前 5 个脚本，每项 `{src, invoker, ms}`。
3. 隐私约束：`src` 只保留 `sourceURL` 去掉查询串后的**最后一段文件名**（如 `index-a1b2.js`），空则 `""`；`invoker` 截断到 120 字符。不记录 URL 全路径、函数源码位置、任何消息内容。
4. 环是**窗口级**口径：LoAF 是整个渲染窗口的事件，不随会话切换清空（帧指标同样是窗口级）。样本里的 `sid` 只代表采集时刻的活动会话，报告端如实标注。
5. 采集与回传：
   - 样本新增 `laf` 字段：`lafDiagOn=false` 或 `observe=false` 时为 `null`；
   - `laf = {supported, count, max, detail}`：`supported` 为 0/1（浏览器不支持 `long-animation-frame` 时为 0，此时 count/max/detail 恒为空）；`count`/`max` 是本采集周期 ≥50ms 长帧的次数与最大值（复用既有 laf 口径）；`detail` 未变化时发 `[]`，报告端向前找最近一次非空（与 `loadOlderDetail` 同一套约定）；
   - `lafDiagOn` 从开到关：环清空、样本 `laf=null`；observer 仅在 `scrollDiagOn` 也关闭时才断开。
6. 还原：`__lagfixOff()` / observer 自禁用时断开 LoAF observer（若 `scrollDiagOn` 也不再需要）、清空 `lafDetail`。

### 1.2 O3 大会话翻页降频（触发降频，不是合并）

机制依据（ZCode v3.17.2 源码，见拍板页第 07 节）：宿主 `loadOlder` 自带 `loadingOlder` 单飞防重入，页大小 60 行是协议定的，「合并请求」不成立；时间线触发是 fire-and-forget（`ConversationTimeline.tsx` `loadOlder.onLoadOlder?.()`），触发阈值约 2 个视口，锚点在**每次触发事件**时重新捕获。因此可做的缓解是：大会话窗口下，把过密的触发**跳过**，让后续滚动事件带更新的锚点重试。

1. 生效条件：`loadOlderPaceOn=true` 且 observer 未自禁用。与 `scrollDiagOn` 独立（观测关、降频开时仍生效）。
2. 规则（在既有 loadOlder 包装的**最前段**判断，包装只装在主 store 实例上，沿袭 v0.3.2 的实例级口径）：
   - **只对滚动触发的调用降频**。宿主还有非滚动补拉：`SessionPane` 检测到首 turn 缺 header 时
     `void lease.store.loadOlder()`，并用 `cursorKey` 去重——跳过它不会重试，首 turn header 会
     一直缺失。因此降频门额外要求「调用发生在时间线 scroll 事件的派发栈内」：`document`
     capture 阶段置 `paceInScrollDispatch=true`，微任务里清掉。滚动触发（`handleScroll`）是同步
     发生的，落在窗口内；宿主 effect 里的自动补拉已经出栈，不受影响。
     不能用「最近 N ms 有滚动」的时间窗：宿主前插锚定后会在微任务里
     `dispatchEvent(new Event("scroll"))` 补发通知，合成 scroll 会污染时间窗。
   - 读取调用时的 `rows.window.length`（即既有 `rowsBefore`）；
   - `rowsBefore <= 3000`（`PACE_MIN_ROWS`）：放行，不计时；
   - `rowsBefore > 3000` 且距上次放行 **≥ 600ms**（`PACE_INTERVAL_MS`）：放行，记放行时刻；
   - `rowsBefore > 3000` 且距上次放行 < 600ms：**跳过本次调用**——不调用原方法、不进任何观测环/明细、不计 `loadOlderCalls`，直接 `return Promise.resolve()`（fire-and-forget 调用方不使用返回值；返回已结算 promise 防御任何 await/then 链）。
3. 跳过的安全性：只作用于滚动触发（见上），宿主自己的 cursor 去重补拉不受影响；不写 store、不动 `loadingOlder`/`canLoadOlder`，宿主状态机视角本次触发从未发生；用户继续滚动时下一次滚动事件自然重触发（宿主在每次触发时重新捕获锚点，重试的锚点反而更新）。
4. 计数：样本新增 `pace` 字段，`loadOlderPaceOn=false` 时为 `null`；开启时 `pace = {minRows: 3000, intervalMs: 600, allowed: N, skipped: N}`，自本次包装建立起累计（换主 store 重建包装时归零，与 `callsInWrap` 同口径）。
5. 还原：
   - 开关关闭：所有调用原样放行（包装若仍在，只余观测语义）；
   - `__lagfixOff()`：既有 `releaseLoadOlderProbe` 恢复原方法，降频随包装一起消失。
6. 已知边界（写进 README 与报告）：
   - 用户停在触发区内不再滚动时，被跳过的那次补页不会自动重试，需要再滚动一次才会补上——A/B 时用「顶部空白时间」指标衡量；
   - 宿主后端单次调用的全量过滤成本不变，O3 只减少次数；
   - 行数读不到（`rows.window` 非数组）时不做降频、只放行——宁可少优化，不能凭猜测跳调用；
   - 非滚动触发的补页（宿主首 turn header 补齐、分享/查找补拉）永不被降频；`pace.allowed/skipped` 只统计滚动触发的那部分；
   - 参数（3000 行 / 600ms）是拍板值，如需调整必须重新 A/B 并更新本规格。

### 1.3 O4 长回合渲染减负（turn 内行级 content-visibility）

机制依据：虚拟化以**整轮 turn** 为单位（`ROW_OVERSCAN=2`），单个超长 turn 可挂数千 DOM 且部分在屏外仍参与布局/绘制；宿主在分享只读时间线已有 `content-visibility:auto` 先例。活时间线的 turn wrapper 被 virtualizer 测高（`ref={measureElement}`，absolute+translateY），不能加 CV；可加的是 wrapper 内部的行级块。

1. 生效条件：`turnContentVisOn=true` 且 `observe=true` 且未自禁用。生效方式：给 `documentElement` 加 `data-lagfix-cv="1"`；所有效果只通过这条属性选择器生效。
2. CSS（注入既有 `ensureStyle()`，常驻但被属性门控）：

   ```css
   [data-lagfix-cv="1"] [data-v4-turn-unit="true"]:not([data-v4-running-live-tail]) [data-row-id]{
     content-visibility:auto;
     contain-intrinsic-size:auto 160px;
   }
   ```

   - 只作用于 turn 单元内部的 `[data-row-id]` 行块；正在生成的 live tail（`data-v4-running-live-tail`）整轮排除；
   - `contain-intrinsic-size:auto 160px`：`auto` 让浏览器记住该块**上次真实渲染高度**，屏外跳过绘制时高度占位不变——已渲染过一次的块对 virtualizer 测高完全无扰动；从未渲染过的块首次占位 160px，进入屏幕附近后按真实高度校正（与 virtualizer 自身的初始估算同一性质）。
3. 属性生命周期（`syncCvAttr()`，与 P1/P2 的 `data-lagfix-pane-*` 同一套模式）：
   - 每次设置变化（面板开关、跨窗口 `storage` 事件）、初次挂载、恢复时同步：want 为真且当前无属性 → 加；want 为假且有 → 移除；
   - `__lagfixOff()` / 自禁用 / 暂停路径：与 `data-lagfix-scroll`、`data-lagfix-pane-switch`、`data-lagfix-pane-open` 一并移除。
4. 无新增 MutationObserver、无新增全局监听器；纯 CSS，宿主重渲染不受影响。
5. 已知边界：长 turn 首次滚入时，其中没渲染过的行块会经历一次 160px→真实高度的校正，可能表现为一次较明显的跳动（virtualizer 随之重测该段）；「找到/选中/复制」等宿主功能依赖的 `[data-row-id]` 元素仍在 DOM 中，CV 只影响绘制。锚点漂移验收沿用以现有 E2E 的 48px 为底线。
6. 还原：开关关闭或 `__lagfixOff()` → 移除属性，行为回到 v0.3.3。

## 3. 样本与接口

样本（`__lagfixCollect()` 周期回传）新增两个字段，均为可缺省（旧读取端可忽略）：

```jsonc
{
  "laf": {            // lafDiagOn=false 或 observe=false 时为 null
    "supported": 1,   // 浏览器不支持 long-animation-frame 时为 0，其余字段恒空
    "count": 3,       // 本周期 ≥50ms 长帧次数（既有口径）
    "max": 812,       // 本周期最大长帧 ms
    "detail": [       // 未变化时为 []；最多 10 条 ≥100ms 的记录
      { "t": 1762867200123, "ms": 812, "styleMs": 143,
        "scripts": [ { "src": "index-a1b2.js", "invoker": "…", "ms": 402 } ] }
    ]
  },
  "pace": {           // loadOlderPaceOn=false 时为 null
    "minRows": 3000, "intervalMs": 600, "allowed": 4, "skipped": 9
  }
}
```

主进程不做新决策，只把字段原样落盘（`lagfix-main.cjs` 无需理解语义）。`lagfix_report.py` 新增「卡顿来源定位」段：近期长帧表（时间/时长/强制布局占比/脚本 top3）与窗口内脚本耗时聚合；`supported=0` 时显示「当前浏览器不支持该诊断」；样本缺 `laf` 字段（旧版本）时跳过该段。展示名按「`src` → `invoker` → `?`」回退：实机里宿主脚本的 `sourceURL` 常为空，若只认 `src` 会让明细与聚合整片塌成 `?`，归因失去意义（2026-11-11 首轮 449 条脚本条目全空）。

设置面板「观测」页新增一行（卡顿来源定位），「性能」页新增「实验（默认关闭）」组两行（沿袭「会做什么/不会做什么/代价」结构，不出现 P95、DOM、loadOlder 等内部词）：

- 卡顿来源定位（默认开）
- 大会话翻页降频 · 实验（默认关）
- 长回合渲染减负 · 实验（默认关）

## 4. 验收场景

自动化（`tests/observe_smoke.mjs` / `tests/report_session_diag.py`）：

1. 默认值：`lafDiagOn=true`、`loadOlderPaceOn=false`、`turnContentVisOn=false`。
2. P0：`lafDiagOn` 关 → 样本 `laf=null`；喂 ≥100ms 假条目 → `detail` 记录且 `src` 是文件名、无路径；环上限 10；重复采集未变化 → `detail=[]`。
3. O3：行数 ≤3000 连发两次 → 原方法各执行一次；行数 >3000 且 600ms 内连发 → 第二次跳过、返回已结算 promise、原方法只执行一次、`loadOlderCalls` 只 +1、明细环不新增；开关关 → 连发全部放行；`pace.skipped` 计数正确。
4. O4：开关开 → `documentElement` 有 `data-lagfix-cv="1"`；关 → 移除；`__lagfixOff()` → 移除；CSS 规则存在于样式表且含 `:not([data-v4-running-live-tail])`。
5. 报告：`laf` 缺失/`supported=0`/空明细回退/坏行不炸。

实机 A/B（用户执行，路线页第 05 节口径，不放宽）：

- O3：同一超长会话同段历史同路径上翻，对比开/关的补页次数、滚动 P95、长任务与顶部空白；保留门槛：滚动 P95 或长任务下降 ≥20%，且顶部空白不劣化超过可感知范围；**另需验证会话打开时首 turn header 正常出现**（非滚动补拉不被降频影响）。
- O4：DOM>4000 或 3 秒长任务 >6 的场景，对比开/关的 DOM 峰值、长任务、滚动 P95；锚点漂移 ≤48px；「找到/选中/复制」抽查可用；**长 turn 首次滚入与 turn 导航跳转各抽查一次**（CV 会改变首次滚入时的测高）。
- 两项任一不达门槛：开关保留但默认关闭，README 如实标注「未达门槛，默认关闭」。

## 5. 与既有行为的兼容

- `scrollDiagOn` 关闭不再使 loadOlder 包装消失（只要 `loadOlderPaceOn` 开）；看门狗的挂载条件同步加上 `loadOlderPaceOn`。`scrollDiagOn` 与 `loadOlderPaceOn` 同时关时包装卸载，行为与 v0.3.3 一致。
- 既有 `loadOlderDetail`/`loadOlderRing` 的记录口径不变；被 O3 跳过的调用不进任何观测记录（没发生的调用不能被记成成功或失败）。
- `maskOffOnScroll`、P1/P2/P3 侧栏与回前台保护不受影响；`data-lagfix-cv` 与 `data-lagfix-scroll` 可同时存在，作用于不同元素。
- 版本号同步八处（`plugin.json`、`marketplace.json`、`install.py`、`hooks.json`、README badge、面板版本行、`docs/releases/v0.3.4.md`、本规格）。
