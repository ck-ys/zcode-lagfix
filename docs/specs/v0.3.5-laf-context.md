## 1. 产品规则

### 1.1 P0 长帧上下文归因（`lafCtxOn`，默认开，只读）

1. 生效条件：`lafCtxOn=true` 且 `lafDiagOn=true` 且 `observe=true` 且 observer 未自禁用。`lafDiagOn` 是父开关：父关时本项不记录、不更新时间戳（样本 `laf=null` 已覆盖整段）。
2. 时间戳（全部 `performance.now()`，`0` 表示尚未发生）：
   - `lastNotifyAt`：宿主 store 通知进入插件的 `subscribe` 包装（仅在「合并刷新」开启、包装已安装时有值）；
   - `lastFlushAt`：插件真正把合并后的通知交给宿主（`fire()`）；
   - `lastLafScrollAt`：时间线滚动容器（`[data-v4-timeline-scroll="true"]`）的 scroll 事件；即使 `scrollDiagOn=false`，只要 P0 开启也更新。它**独立于滚动诊断的 `lastScrollAt`**，两者不得互相复用，避免关闭滚动诊断时把旧滚动误判成 `loadOlder` 的滚动触发；
   - `lastCommitAt`：活动 pane 的 `data-projection-seq` 发生变化（含 attach 后的首次基线变化）；暂停观测期间不更新；attach / 切会话时清零（旧 pane 的提交不能当新会话的上下文）。
3. 每条 ≥100ms 长帧（沿用 `lafDiagOn` 的明细条件）新增：
   - `sinceNotify` / `sinceFlush` / `sinceScroll` / `sinceCommit`：信号相对该帧的**滞后**（四舍五入）。信号在帧开始前 = `startTime - ts`；信号发生在帧内（`startTime <= ts <= startTime + duration`，滚动/通知/补发/提交回调的常态）= `0`；晚于帧结束（不属于这一帧）或未发生 = `null`；
   - `src`：`flush` / `notify` / `scroll` / `other` 四选一。判定：在 `flush/notify/scroll` 三个候选中取**滞后最小**者；滞后必须 ≤ `LAF_CTX_WINDOW_MS`（1000ms）才可归类，否则 `other`。帧内候选（滞后=0）按信号发生时间取**更早**者（滚动处理里同步触发的通知/补发，根因仍是滚动；真正的延迟补发会让 flush 晚于 notify）；完全同一毫秒时按 `flush → notify → scroll`。`commit` 只作上下文，不单独成类（拍板页口径）。
4. 周期计数：`laf.ctx = {flush, notify, scroll, other}`，每次采集后清零；`lafCtxOn=false` 时 `ctx=null`，明细不带第 3 条的五个字段；关闭瞬间把环里旧条目的五个字段一并删除（避免下次明细重发又带出旧来源）。
5. 样本新增窗口级字段：
   - `paneOpen`：侧栏被检测到时为布尔值，未检测到为 `null`；
   - `panelQuiet`：O5 当前是否生效（`panelQuietOn && paneOpen && observe && !dead`），0/1。
   两者在 dead / 暂停样本中分别为 `null` / `0`，保持 schema 稳定。
6. 环仍是窗口级口径（LoAF 与帧指标一致），不随会话切换清空；样本里的 `sid` 只代表采集时刻的活动会话。
7. 还原：
   - `lafCtxOn=false`：清空 `lafCtxCounts` 与 notify/flush/commit 时间戳，样本 `ctx=null`、明细不带上下文字段；`lafDiagOn` 仍开时 LoAF 观察器继续工作；
   - 暂停 / 自禁用 / `__lagfixOff()`：同时清空时间戳与计数；观察器按既有规则断开；
   - 关 `scrollDiagOn` 但 P0 开着：scroll 监听必须保留（P0 需要滚动时间戳）；两者都关才按原有条件卸载。

### 1.2 O5 面板期进一步合并（`panelQuietOn`，默认关，实验）

机制依据：拍板页第 01 节——面板打开且内容持续绘制时，通知/角标这类插件侧小定时器与宿主渲染叠加，长帧明显增多；P0 先量来源，O5 只在判定为插件侧成本时提供更激进的合并。

1. 生效条件：`panelQuietOn=true` 且侧栏已检测到且 `paneOpen=true` 且 `observe=true` 且未自禁用。与 `paneHoldOn` 独立：O5 只改通知窗口与角标频率，不碰渐隐/mask，也不新增 DOM 属性。
2. 生效期间：
   - 通知节流下限从 P2 的 300ms 抬到 **400ms**（`PANEL_QUIET_FLOOR_MS`）；若「合并刷新」关闭，则本项不产生节流效果（没有可合并的通知）；
   - 角标定位上限从 P2 的 1.8s 放宽到 **3s**（`PANEL_QUIET_BADGE_MS`）；角标仍在，只是移动更少。
3. 面板关闭或 O5 关闭：**之后进入包装的通知**立即回到上一版行为（面板仍开且 P2 开：300ms/1.8s；面板关闭：基础 `throttleMs`（默认 120ms，可调），无 1.8s 配额）。400ms 下限在 1s 缓存之外计算，不再多拖；角标判定每次都读实时 `paneOpen`。已经在等待中的那一次通知仍按原定窗口送达（最多约 400ms），不重排定时器。
4. 不新增监听器：复用 P2 的 pane 探针；即使 `paneDiagOn` / `paneSwitchGuardOn` / `paneHoldOn` 全关，只要 O5 开启，pane 探针仍需保留（`paneWatchNeeded()` 加入 O5）。
5. 实验门槛（拍板页第 06 节）：同一会话、面板打开、快速滑动，O5 关/开各一轮；长帧数或 `frameP95` 下降 ≥20% 才算过线。未过线则保持默认关闭并在 README/发布说明如实标注，不得写成已解决。
6. 已知代价：面板常开时刷新间隔取「用户设置的最短间隔」与 400ms 的较大者（可能远超 400ms）；角标位置最多每 3s 同步一次（面板开合保护窗口内本来就不动）。

### 1.3 U1 上游证据文档

只新增/更新文档（本规格、发布说明、README 边界段），把「右侧面板是 `<webview>` guest、像素合成落在宿主 renderer」的证据与实测数据列清楚，供上游评估；不新增运行时行为、不改 `lagfix-main.cjs` 的注入链。

## 3. 样本与接口

`laf` 字段扩展（旧读取端可忽略新键）：

```jsonc
{
  "laf": {
    "supported": 1,
    "count": 3,
    "max": 812,
    "ctx": { "flush": 2, "notify": 0, "scroll": 1, "other": 0 },
    "detail": [
      {
        "t": 1762867200123, "ms": 812, "styleMs": 143,
        "src": "flush",
        "sinceNotify": 3, "sinceFlush": 0, "sinceScroll": 240, "sinceCommit": 18,
        "scripts": [ { "src": "index-a1b2.js", "invoker": "…", "ms": 402 } ]
      }
    ]
  },
  "paneOpen": true,
  "panelQuiet": 1
}
```

- `ctx` 为 null（`lafCtxOn=false`）或缺省（旧样本）时，报告跳过来源分布段；
- 明细未变化时仍发 `[]`；指纹包含 `src` 与四个差值，上下文变化会触发一次完整明细；
- 主进程不解析新字段，只原样落盘。

`lagfix_report.py` 卡顿段新增：

1. 当前面板状态行：`面板：打开/收起`；`panelQuiet=1` 时注明「面板期进一步合并已生效」；
2. 来源分布行：`本周期长帧来源：节流补发 X / 通知到达 Y / 滚动 Z / 其它 W`；取**最新样本**的 `laf.ctx`，不能用旧明细样本冒充本周期；最新样本 `lafCtxOn=false` 时只提示「已关闭」，不打印旧分布/旧来源；`ctx` 缺失时提示「本版本未记录来源细分」；
3. 明细行追加 `来源=<中文>` 与「距通知/补发/滚动/提交」上下文（只打印非空值）；
4. `other` 且 `sinceCommit` 很小（≤50ms）时追加「（紧跟宿主提交）」提示，帮助判断是否宿主渲染成本。

展示名仍按 `src → invoker → ?` 回退；报告不打印路径、消息内容或工具参数。

设置面板（用户语言，不出现 flush/notify/DOM 等内部词）：

- 观测页「诊断」组新增：**卡顿来源细分**（默认开）——「在卡顿记录里补上距上次刷新、滚动、消息更新的时间，用来判断卡顿由哪类操作引起。」
- 性能页「实验（默认关闭）」组新增：**面板常开时进一步合并 · 实验**（默认关）——「面板打开时把刷新间隔至少放到 400ms、角标最多每 3 秒移动一次；面板一关立即恢复。」

## 4. 验收场景

自动化（`tests/observe_smoke.mjs` / `tests/report_session_diag.py`）：

1. 默认值：`lafCtxOn=true`、`panelQuietOn=false`。
2. P0：
   - 样本 `laf.ctx` 存在且四类计数非负；明细带 `src` 与四个 `since*`；
   - 滚动后立刻投递长帧 → `src=scroll` 且 `sinceScroll` 很小；
   - 长帧 `startTime` 距所有信号 >1000ms → `src=other`；
   - 通知立即送达后投递长帧 → `src=flush`；延迟窗口内的第二次通知 → `src=notify`（时间戳可控时）；
   - `lafCtxOn=false` → `ctx=null`、明细无 `src`；重开后计数从 0 开始；
   - 暂停/dead/`__lagfixOff()` → 时间戳与计数清空，样本字段按 §1.1.5 返回。
3. O5：
   - 面板打开 + O5 开 → `collect().fix.eff >= 400`；O5 关 → 回落到 P2 的 300ms；P2 也关 → 120ms；
   - 角标：O5 开时 1.9s 内不移动、3.1s 后移动；关掉立即恢复 1.8s 配额；
   - `panelQuiet` 字段随 O5 与 paneOpen 变化；`paneOpen` 在未检测到侧栏时为 null。
4. 报告：`ctx` 分布、来源中文名、上下文字段、`ctx` 缺失/坏形状/旧样本不炸。

实机 A/B（用户执行，拍板页第 06 节口径，不放宽）：

- 段 1：长会话 + 面板打开 + 快速滑动，O5 关；段 2：同路径 O5 开。记录长帧数、`frameP95`、`longTasks`、`maxLongTask`。
- 过线：长帧数或 `frameP95` 下降 ≥20%；未过线则保持默认关闭并在发布说明标注。
- 同时观察 P0 输出的来源分布：`flush` 高 → O5 继续加严/重评；`other` 且 `sinceCommit` 小 → 宿主渲染，转 U1；`scroll` 高 → 后续再评估 O3b。

## 5. 与既有行为的兼容

- v0.3.4 的 `lafDiagOn` / `loadOlderPaceOn` / `turnContentVisOn` 语义不变；`lafCtxOn` 只增加字段与时间戳更新，不改变 `lafCount`/`lafMax`/`lafDetail` 的既有口径。
- `scrollDiagOn=false` 时，P0 仍会挂滚动监听；`scrollDiagOn` 的统计字段仍为 `null`，互不污染。
- O5 与 P2 叠加时取更严格值（400ms / 3s）；O5 关闭后 P2 原值不变。
- `__lagfixOff()` 必须把 `lafCtxOn` / `panelQuietOn` 置 false，并清空时间戳、计数、`paneOpen`/`panelQuiet` 输出。
- 版本号同步八处（`plugin.json`、`marketplace.json`、`install.py`、`hooks.json`、README badge、面板版本行、`docs/releases/v0.3.5.md`、本规格）。
