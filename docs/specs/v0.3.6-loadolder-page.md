## 1. 产品规则

### 1.1 O8 补页批量（`loadOlderPageLimitOn`，默认关，实验）

1. 生效条件：`loadOlderPageLimitOn=true` 且 observer 未自禁用（`!state.dead`）。与 `observe` / `scrollDiagOn` / `loadOlderPaceOn` 独立：暂停观测或关闭滚动诊断时，本项仍可生效；`__lagfixOff()`、自禁用会关闭并还原。
2. 只包装当前主 store **实例**的 `loadOlder`（沿用 v0.3.4 的包装与还原机制），不碰共享原型；重复 `attach` / 看门狗重试必须幂等，不能套两层。
3. 替换规则只有一条：
   - 开关开、未自禁用、且调用方**没有传任何参数**（`arguments.length === 0`）时，调用原方法并把 `limit` 设为 `LOAD_OLDER_PAGE_LIMIT = 200`；
   - 其它情况（开关关、调用方显式传参、已自禁用）原样 `orig.apply(this, arguments)`，一个字节都不改。
4. 必须保持：`this` 语义、返回值（Promise）、异常、`loadingOlder`/`canLoadOlder` 状态、游标与返回行内容全部由原方法决定。插件不伪造、不跳过、不合并、不缓存任何补页。
5. 与 O3 叠加：O3 的 600ms 限流先执行；若被 O3 跳过，则不调用原方法，本项自然不生效；未被跳过时再按第 3 条替换页大小。两项都关时包装器按原条件卸载（若 `scrollDiagOn` 也关）。
6. 包装器安装条件扩展为：`scrollDiagOn || loadOlderPaceOn || loadOlderPageLimitOn`（且 `!state.dead`）。只开 O8 时也必须能找到并包装主 store；找不到时降级为不生效，不影响宿主。
7. 计数（仅内存，随包装器生命周期）：记录 `applied`（实际替换为 200 的次数）、`passthrough`（开关开但调用方显式传参、原样放行的次数）。每次从关到开、换主 store、自禁用、`__lagfixOff()` 时清零；暂停观测不重置（替换仍生效，计数继续累计）。样本字段 `page` 只在开关开时上报（即使包装器因 O3 或滚动诊断仍在），关闭后为 `null`；`installed` 表示包装器当前是否真的装上。
8. 还原：关闭 O8 开关后下一次无参调用必须回到宿主默认 60 行；若 `scrollDiagOn`/`loadOlderPaceOn` 也都关，包装器卸载并恢复原方法。`__lagfixOff()`、观察器自禁用、锚点丢失/换 store 都必须移除替换效果。

### 1.2 参数依据（实现前已核对）

- ZCode v3.17.2 源码：`ConversationProjectionStore.loadOlder(limit = PROTOCOL_V4_LIMITS.snapshotTailWindowRows)`；`snapshotTailWindowRows = 60`，`rowsRangeMaxLimit = 200`；宿主 `loadAllOlder()` 自身按 200 行分页。
- 安装版 v3.18.1 的 `app.asar` 已复核：`loadOlder(e=yt.snapshotTailWindowRows)` 仍存在，`snapshotTailWindowRows:60, rowsRangeMaxLimit:200`；宿主调用点为无参 `store.loadOlder()`。
- 若未来宿主把 `loadOlder` 改成不接受参数、或把上限降到 60，本实验必须停用并在报告里提示，不得猜参数。实现不自动探测宿主契约变化：传 200 若被忽略或截断，行为会自然退回，但需要按报告中的补页次数与宿主版本人工复核。

## 3. 样本与接口

设置快照新增：

```jsonc
{ "loadOlderPageLimitOn": false }
```

样本新增（旧读取端可忽略）：

```jsonc
{
  "page": { "limit": 200, "installed": true, "applied": 12, "passthrough": 3 }
}
```

- `page` 只在开关开时上报，关闭为 `null`（即使包装器因 `scrollDiagOn`/`loadOlderPaceOn` 仍存在）；
- `installed` 为 `false` 表示开关开着但包装尚未装上（找不到主 store、冻结 store 或尚未挂载），此时计数不可用；
- `applied` 只统计真正替换为 200 的无参调用；`passthrough` 统计有显式参数的调用（开关开但调用方自己传了 limit）；
- 不记录任何行内容、rowId、消息 id 或工具参数。

`lagfix_report.py` 补页段新增：

1. 开关状态行：`补页批量（实验）：每页最多 200 行，已生效 N 次；显式参数放行 M 次` / `补页批量已关闭（实验项，默认关闭）` / `本版本未记录补页批量（旧样本）`；
2. 与现有 `loadOlder` 明细并列，不改变明细口径；`installed=false` 时提示「包装尚未装上，计数不可用」；`applied=0` 时提示「开关开着但本文件内还没有无参补页调用」；遇到 dead 或显式 `page=null` 样本时停止回退，不回显更早的旧计数；
3. 旧样本无 `page` 字段时只提示，不报错。

设置面板（用户语言，不出现 `loadOlder`/`DOM`/`P95` 等内部词）：

- 性能页「实验（默认关闭）」组新增：**补页批量 · 实验**（默认关）——
  「每次自动加载更多历史，减少重复加载的次数。会做什么：加载更早消息时一次多取一些（最多 200 行）。不会做什么：不跳过、不删除任何消息，也不改变顺序。代价：单次加载内容更多，个别情况下滚动到更早历史时位置可能轻微调整。」

## 4. 验收场景

自动化（`tests/observe_smoke.mjs`）：

1. 默认值：`loadOlderPageLimitOn=false`；关闭时无参调用不传 limit。
2. 开启后无参调用 → 原方法收到且只收到 `200` 一个参数；返回 Promise 与 `this` 保持；`applied` 增加。
3. 开启后显式传参（如 `60` / `120`）→ 原方法收到原参数，不被替换；`passthrough` 增加。
4. 只开 O8（`scrollDiagOn=false`、`loadOlderPaceOn=false`）→ 包装器仍安装并生效；样本 `pace=null`，但 `page` 有值。
5. O3 开启且触发跳过 → 原方法不被调用，O8 不计数；未跳过时按 200 调用。
6. 暂停观测但开关仍开 → 替换仍生效（缓解与观测独立），计数继续累计；自禁用/`__lagfixOff()` → 恢复原方法、下一次无参调用回到原参数。
7. 重复 apply / 重订阅 / store 切换 → 不套两层；换 store 后 `applied/passthrough` 归零；从关到开也重新计数。
8. 样本字段 `page` 生命周期与设置快照；面板行存在、版本行 v0.3.6。
9. 关闭 O8 后包装器在 `scrollDiagOn`/`loadOlderPaceOn` 都关时卸载，行为回到 v0.3.5。

自动化（`tests/report_session_diag.py`）：

1. `page` 正常形状显示开关、页大小与生效次数；
2. `page=null` / 缺字段 / 坏形状 / 负值不炸；
3. 开关开着但 `applied=0` 的提示；
4. 旧样本无该字段时提示「本版本未记录」。

实机 A/B（用户执行）：

- 同一会话、同一段历史、同一滚动路径，O4 保持固定，做「O8 关 → 开 → 关」至少 3 轮；
- 记录：同一段历史的 `loadOlderCalls` 增量、所有调用耗时之和、`scroll.p95`、3 秒长任务、`laf.count`、`domPeak`、顶部空白、锚点漂移；
- 过线：补页次数下降 ≥50%（目标约 -66%），且补页总阻塞或滚动 P95/长任务下降 ≥20%；顶部空白 ≤300ms、锚点漂移 ≤48px、DOM 峰值不增加 >20%；
- 未过线：保持默认关闭，并在 README/发布说明如实标注，不写成已解决。

## 5. 与既有行为的兼容

- O3 的 `loadOlderPaceOn` 语义与默认值不变；O8 只在其后追加参数替换。
- `scrollDiagOn` 关闭时，O8 仍可生效；`loadOlderDetail` 仍按原条件不记录。
- 暂停观测时 O8 的替换不关闭、计数不重置；若暂停期间宿主重建 projection store，替换要等恢复观测或下一次 `applyThrottle`（设置变更、切会话等）才装到新 store。
- `__lagfixOff()` 必须把 `loadOlderPageLimitOn` 置 false，并释放包装器/清零计数。
- 版本号同步八处（`plugin.json`、`marketplace.json`、`install.py`、`hooks.json`、README badge、面板版本行、`docs/releases/v0.3.6.md`、本规格）。
