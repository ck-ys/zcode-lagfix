## 1. 产品规则

### 1.1 S1 多会话归因

1. 遍历宿主已有的会话 pane（`[data-session-id]`），按 `data-session-id` 建桶；**最多 5 个桶**，按 `lastActive` 降序输出。发现阶段满 5 个后不再为额外 pane 建桶（这些 pane 仍被观察，以便识别真实活动）；只有额外 pane 出现真实提交/滚动时，才淘汰最久未活跃的旧桶并接管名额。
2. 隐藏 pane 同样记录，`visible=false` 单独标记；窗口整体不可见（`document.hidden`）不改变单会话的 `visible` 判定，仍以 pane 自身的 CSS/几何可见性为准。
3. 每个桶记录：
   - `sid`：`data-session-id` 原值。宿主未分配会话 id 时写 `"draft"`（`sessionId ?? "draft"`），过渡态也可能为空字符串；两者都按占位 sid 处理，pane 切成真实 sid 后删除占位桶。
   - `visible`：`checkVisibility({checkOpacity:false, checkVisibilityCSS:true})`（存在时）且 `getBoundingClientRect()` 宽高均 > 0；否则 `false`。只代表 CSS/几何可见，不代表“最前台”。
   - `lastActive`：最近一次观察到该 pane 的投影提交或时间线滚动的本地时间（epoch ms）；暂停观测不改写它。新发现的空闲 pane 初始为 0。
   - `frames`：自上次成功采样以来该 pane 的 `data-projection-seq` 属性**值真的变化**的次数；同值重写不计。
   - `commitRate`：`frames / 采样间隔秒数`，保留 1 位小数；采样间隔 <1s 时为 `null`，且不重置 `frames`（避免把毫秒级间隔放大成巨大速率）。
   - `mountedTurns`：pane 子树内 `[data-v4-turn-unit="true"]` 的数量。
   - `dom`：pane 子树节点数（含 pane 根）。
   - `scrollP95`：该 pane 时间线滚动后 200ms 内的帧间隔 P95；30s 窗口内无样本时为 `null`。
4. 桶不写入宿主 store；仅存在 observer 内存。
5. `sessionDiagOn=false`、观测暂停、observer 自禁用时 `sessions` 为 `null`；开启但没有任何 pane 时为 `[]`。
6. 切会话只换桶，不重置其它会话的桶；pane 暂时不在 DOM 时保留桶，但 `visible=false`，`mountedTurns`/`dom` 置 0，直到再次出现或桶被淘汰。
7. 超过 5 个桶时淘汰 `lastActive` 最小的桶；从未活跃的桶 `lastActive=0`，同分时先淘汰最早发现（`firstSeenAt`）的。淘汰只发生在新桶创建时，避免每轮同步反复重建/淘汰。
8. `mountedTurns`/`dom` 固定每 60s 采样一次（新桶立即采一次），不跟随采集周期遍历 pane 子树。

### 1.2 S2 loadOlder 调用明细

1. 仅在 `scrollDiagOn=true` 时采集；与 v0.3.1 的“只观测、不拦截、不延迟、不改参数/返回值/`this`”完全一致。只包装**当前主 store 实例**（宿主的 `loadOlder` 在原型上，但调用点是 `lease.store.loadOlder()`），不修改共享原型，隐藏会话的补页不会进入本明细。
2. 环形窗口保留**最近 10 次**调用，按 promise 结算顺序追加（同步返回则在返回时立即记录）；超过 10 条丢弃最旧。
3. 每条记录字段固定为：

   ```json
   { "t": 1760000000000, "ms": 210, "ok": true,
     "rowsBefore": 60, "rowsAfter": 120, "trigger": "scroll" }
   ```

   - `t`：调用开始时的 epoch ms。
   - `ms`：从调用开始到 resolve/reject/同步返回/同步抛错的耗时，四舍五入为整数。
   - `ok`：promise 正常结算或同步返回为 `true`；reject 或同步抛错为 `false`。**宿主 `loadOlder` 内部 `rowsRange` 失败会打日志后正常 resolve**，所以 `ok=true` 只表示“promise 没有异常”，不代表补页成功；行数未变可能是 no-op 或宿主内部失败。
   - `rowsBefore` / `rowsAfter`：`this.state.snapshot.rows.window` 的数组长度；不是数组或读取失败时为 `null`。只读长度，不读行内容。
   - `trigger`：`scroll | initial | unknown`，判定见 1.3。
4. 不记录分页内容、消息 id、工具参数或任何正文。
5. 关闭 `scrollDiagOn`、`__lagfixOff()`、observer 自禁用时清空明细；在途 promise 的回调按 generation 丢弃，不写回已清空的窗口。
6. 观测暂停期间原样放行、不计数、不写明细，也不消耗 `initial` 判定；恢复后继续。
7. 明细只在发生变化时随样本携带完整数组；未变化的样本发 `[]`，避免每 5s 重复最多 10 条记录。报告端向前找最近一次非空数组。

### 1.3 trigger 判定（时间启发式）

调用开始时按顺序判断：

1. 最近 2000ms 内发生过时间线滚动（`lastScrollAt` 非 0 且 `performance.now() - lastScrollAt <= 2000`）→ `scroll`。
2. 否则，若这是本次包装后的第一次调用，或距离最近一次 `attach`（锚点挂载/切会话）不超过 5000ms → `initial`。
3. 其余 → `unknown`。

说明：这是时间相关性，不是宿主内部归因；`initial` 只表示“没有近期滚动、且在挂载后不久”，不等于确认是首屏 hydrate。规格与发布说明必须保留这句。

### 1.4 S3 面板

1. 观测页「诊断」组新增一行「多会话归因」，默认开。
2. 行说明：按会话记录提交/帧、DOM、挂载轮数与滚动 P95，用来判断切会话后谁在拖慢。
3. 「!」影响说明分两段：
   - 影响：只读统计；最多 5 个会话桶；隐藏 pane 也记录并标 `visible=false`。
   - 不影响：不读消息正文、不写 store、不改补页与渲染；关闭后 `sessions` 为 `null`，不再遍历会话 pane。
4. 关闭后立即断开 `session` 的 MutationObserver、清空桶；重新开启时只挂一份观察。

### 1.5 S4 报告

`/lagfix report` 在滚动/输入诊断之后新增：

1. **多会话归因**：最近一条带 `sessions` 数组的样本，逐桶打印 `sid / 可见性 / frames / commitRate / dom / mountedTurns / scrollP95 / lastActive`；空数组明确写“0 个会话桶”。暂停/dead 的 `null` 样本向前回退到最近一次数组，并标注“最近一次有效样本”；开关关闭时明确写“已关闭”。
2. **补页明细**：向前找最近一条非空 `loadOlderDetail` 数组（未变化样本是 `[]`），打印最近最多 10 条（时间、耗时、结果、行数变化、触发来源），并汇总“Top 慢补页”和 `scroll/initial/unknown` 计数；`rowsBefore==rowsAfter` 标“无变化”，`ok` 显示为“正常/异常”。非 dict/坏的 trigger 值归入 unknown，不崩溃。
3. 旧样本没有这两个字段时打印 `[i]` 提示，不报错。

## 2. 状态所有者

| 状态 | 所有者 | 生命周期 |
| --- | --- | --- |
| `sessionDiagOn` | `localStorage["lagfix.settings.v1"]` | 跨窗口/重启持久 |
| `sessionBuckets`（≤5） | observer 内存 | observer 启动 → 关闭/自禁用 |
| `loadOlderDetail`（≤10） | observer 内存 | `scrollDiagOn` 开启期间 |
| `sessionMO` | observer 内存（一个 MutationObserver，多目标） | `sessionDiagOn` 开启且至少一个 pane；目标集合不变时不重挂 |
| `data-projection-seq` 观察 | pane 元素属性 | 不修改，只读；同值重写不计提交 |
| `loadOlder` 包装 | 主 store 实例上的 `__lagfixLoadOlder` | 与 v0.3.1 相同；不修改共享原型 |

不写入宿主 store、不写会话数据、不碰 `db.sqlite`。

## 3. 接口

### 3.1 设置字段

```js
DEFAULTS = {
  // ...原有字段
  scrollDiagOn: true,
  sessionDiagOn: true,   // v0.3.2 多会话归因
  inputLagOn: true,
  maskOffOnScroll: true,
}
```

`mergeStored` 只接受布尔值；非布尔不覆盖默认。

### 3.2 `settingsSnapshot()`

新增 `sessionDiagOn`。

### 3.3 `__lagfixCollect()` payload

正常样本新增：

```json
{
  "sessions": [
    { "sid": "abc", "visible": true, "lastActive": 1760000000000,
      "frames": 42, "commitRate": 8.4,
      "mountedTurns": 12, "dom": 4123, "scrollP95": 38 }
  ],
  "loadOlderDetail": [
    { "t": 1760000000000, "ms": 7298, "ok": true,
      "rowsBefore": 60, "rowsAfter": 120, "trigger": "initial" }
  ]
}
```

- `sessions`：`sessionDiagOn=false` / 暂停 / dead 时为 `null`；否则数组（可为 `[]`）。
- `loadOlderDetail`：`scrollDiagOn=false` / 暂停 / dead 时为 `null`；否则数组。明细未变化时发 `[]`，变化时携带最近最多 10 条完整数组。
- dead / paused / 异常 payload 固定带 `sessions: null` 与 `loadOlderDetail: null`，保持 schema 稳定。
- 不改变原有 `scroll` / `input` 字段语义。

### 3.4 控制台入口

`__lagfixDiag()` 增补：

- `sessionBuckets`：当前桶数。
- `sessionPanes`：当前被观察的 pane 数。
- `loadOlderDetail`：明细条数。

## 4. 事件顺序

### 4.1 桶发现与提交计数

```
collect / attach / watchdog(5s)
  → syncSessionPanes()
      → document.querySelectorAll("[data-session-id]")
      → 每个 pane：按 sid 取/建桶，记录 pane，observe(data-projection-seq, data-session-id)
      → 未出现的旧桶：pane=null, visible=false, turns=0, dom=0
      → 超过 5 个：淘汰最久未活跃的桶
MutationObserver(sessionMO)
  → attributeName=data-projection-seq：桶 frames++、lastActive=Date.now()
  → attributeName=data-session-id：把 pane 从旧桶解绑，按新 sid 取/建桶
collect
  → 每个桶：visible、frames、commitRate、mountedTurns、dom、scrollP95
  → frames/采样时间按规则重置
```

### 4.2 按会话滚动帧

```
scroll (capture, target 命中时间线容器)
  → 若 sessionDiagOn && observe：
      找到 target.closest("[data-session-id]")（找不到则用当前主 pane）
      对应桶 lastScrollAt=performance.now()、lastActive=Date.now()
rafTick
  → 对每个桶：若 lastScrollAt 非 0 且 t-lastScrollAt<=200，push 一帧
collect
  → scrollP95 取该桶最近 30s 环形窗口
```

### 4.3 loadOlder 明细

```
调用 loadOlder
  → 暂停/dead：原样 orig.apply(this, arguments)，不计数不写明细
  → 读 rowsBefore、判定 trigger、calls++
  → orig.apply(this, arguments)
  → 同步抛错：错误++、写 ok=false 明细、原样抛
  → thenable：挂 then/catch 记录耗时与 rowsAfter，返回原 promise
  → 其它：记录耗时与 rowsAfter，原样返回
采集周期
  → 明细指纹变化：完整数组随样本发出
  → 未变化：发 []（报告端向前找最近一次非空）
```

## 5. 关闭与清理路径

| 触发 | 必须完成 |
| --- | --- |
| 面板关闭 `sessionDiagOn` | 断开 `sessionMO`；清空桶与 pane 映射；`sessions` 变 `null`；不再遍历 pane；若滚动监听无其它用途则移除 |
| 面板关闭 `scrollDiagOn` | 释放 `loadOlder` 包装；清空 `loadOlderRing`/`loadOlderDetail`；`loadOlderDetail` 变 `null` |
| 观测暂停 | `sessions`/`loadOlderDetail` 为 `null`；停止累计（含 `loadOlder` 明细）；不改写 `lastActive`；清空 pane 引用但保留桶与包装；恢复时重新同步 pane 并从当前时刻起算采样窗口 |
| `__lagfixOff()` | `sessionDiagOn=false` 落盘；断开 `sessionMO`；清空桶、明细；移除监听；不停止 rAF（沿用 v0.3.1 口径） |
| observer 自禁用 | 同 `__lagfixOff()` 的清理；`sessions`/`loadOlderDetail` 为 `null` |
| 跨窗口 `storage` | 与面板同一套应用逻辑；关闭/重开不叠层 |
| 页面卸载 | 不新增属性；`sessionMO` 随页面销毁，无需额外清理 |

重新开启后每个 pane 只观察一次；`loadOlder` 包装仍按 `__lagfixLoadOlder` 标记复用，不套两层。

## 6. 宿主契约与前提

| 用途 | 选择器/接口 | 失效表现 |
| --- | --- | --- |
| 会话 pane | `[data-session-id]` | `sessions=[]` |
| 投影提交序号 | `[data-projection-seq]` | 该桶 `frames=0`、采样间隔 ≥1s 后 `commitRate=0`，首样本可能为 `null`（未观察到提交，也可能是选择器失配；需对照界面判断） |
| turn 单元 | `[data-v4-turn-unit="true"]` | 该桶 `mountedTurns=0` |
| 时间线滚动容器 | `[data-v4-timeline-scroll="true"]` | 该桶 `scrollP95=null` |
| 补页方法 | 主 store 实例上的 `loadOlder` | `loadOlderCalls=0` |
| 行窗口 | `this.state.snapshot.rows.window` | `rowsBefore/rowsAfter=null` |

如果 `sessions=[]` 且界面上确实有会话，先跑 `/lagfix report` 判断是宿主改版还是 pane 未挂载，不要猜。

## 8. 已知边界

- `visible` 只代表 CSS/几何可见，不代表“最前台”；分屏时两个 pane 可以同时 `visible=true`。
- 最多 5 个桶；发现阶段第 6 个及以后只观察不建桶，等它有真实提交/滚动才淘汰最久未活跃的旧桶，历史数字随之丢失。多个会话同时活跃且超过 5 个时，仍可能发生名额竞争。
- `frames`/`commitRate` 依赖宿主继续更新 `data-projection-seq`；隐藏 pane 若被宿主停止渲染，会如实显示 0，这不等于“隐藏 pane 不耗资源”。
- `mountedTurns`/`dom` 是 pane 子树口径；`scroll.mountedTurns`/`domPeak` 仍是整窗口径，两者不能直接相加对比。
- 每会话 DOM/turn 计数固定每 60s 遍历一次 pane 子树（新桶立即采一次）；首采在大会话下仍可能产生一次 >5ms 成本。
- `loadOlderDetail` 只覆盖当前主 store 实例（主 pane），不是所有会话 store；`trigger` 是时间启发式，不能证明宿主内部调用原因。
- 宿主 `loadOlder` 内部失败会被吞掉并正常 resolve，因此 `ok=true` 只表示“promise 正常结算”；结合 `rowsBefore/rowsAfter` 是否变化判断 no-op。
- 不记录分页内容、消息 id、正文；`rowsBefore/rowsAfter` 只是数组长度。
- 本版不改变任何渲染/补页行为，因此不应期待帧率变化；它的价值是让 v0.3.3 的缓解项有数据依据。
