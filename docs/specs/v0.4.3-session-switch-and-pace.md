# v0.4.3 行为规格：会话切换归因 + 修复失灵的翻页降频

日期：2026-11-13
状态：实现完成（feat/v0.4.3-session-switch-pace 分支；8 套件通过，待实机 A/B）
关联拍板页：`docs/decisions/v0.4.3-session-switch.html`（v2 修订版）

## 0. 一句话目标

切换会话是最重、最高频的卡顿场景，但插件对它零归因；同时插件手里唯一能直接砍补页成本的 O3 翻页降频在 ZCode 3.18.2 上已因触发口径失灵而永不生效。本版：**P0 切换归因（只读，默认开）＋ 修复 O3 触发口径 ＋ O8b 退役 ＋ O3 计数跨切换累计**。不改默认行为路径：所有缓解项默认值不变，默认开启的只有只读观测。

### 1.2 `loadOlder` 真实触发链（O3 修复依据）

3.18.2 主渲染包中（偏移为该 bundle 内字符位置）：

- store 定义：`async loadOlder(e=yt.snapshotTailWindowRows)`（@337266）。
- 无参调用点：`gee=useCallback(()=>Ze?.store.loadOlder(),[Ze])`，作为 `onLoadOlder:gee` 传入时间线。
- 滚动阈值触发在 React 合成 `onScroll` 回调 `Xt` 内（@4679743 定义，@4680556 阈值块）：
  `PDn({scrollTop,canLoadOlder,loadingOlder,triggerPx})` 为真时捕获 prepend 锚点、打 `[v4-timeline] 接近历史窗口顶部，自动预取更早行` debug、调 `r.onLoadOlder?.()`。
- 另有两条触发路径：
  - `Wt=useCallback(e=>{wOn(()=>{B.current===e&&e.dispatchEvent(new Event('scroll'))})},[])`：宿主在测量/补页后**异步重派生合成 scroll 事件**（`new Event('scroll')` 不冒泡），再走同一个 `Xt`。
  - SessionPane 冷快照修复补拉：useEffect「冷快照首 turn 不完整，自动补拉更早行」异步调 `Ze.store.loadOlder()`——这是数据完整性补拉，**必须豁免降频**（宿主不会重试被跳过的游标拉取）。

**为什么同步门控 `paceInScrollDispatch` 永不命中**：插件滚动监听器（capture、`documentElement`）先置位并在微任务里清零；事件派发在两个监听器之间 JS 栈瞬间清空，浏览器执行 microtask checkpoint，清零微任务先于 React 根上的 `Xt` 跑完；叠加 `Wt` 的 `wOn` 异步合成派生，3.18.2 上同步门控两条路径都不可能命中。实机佐证：同一样本 O8b `downgraded=4`（时间口径）vs O3 pace `0 放行 / 0 跳过`（同步口径）。

**结论**：O3 跳过判定改用与 `classifyLoadOlderTrigger()` 相同的时间口径；判定为 `initial`（首调/挂载窗口内）的一律放行，保护 SessionPane 修复补拉。

## 3. P0 会话切换归因

### 3.1 开关与信号

- 新增设置 `switchDiagOn`（默认 `true`，归入「观测」分区，只读）。
- 切换信号复用现有两处，不新增宿主包装：
  - `attach(anchor)` 且锚点元素或 sid 与上次不同（首次挂载记 `from:""` 的一条，供首屏归因；暂停后恢复/重挂同一 pane 不算切换）；
  - MutationObserver 回调里 `sidNow !== state.sid` 的原地切换。
- 150ms 去重：距上一条记录 <150ms 且未冻结时，只刷新 `to`、两个时间戳并重置 2 秒帧切片，不新增条目（attach 与 MO 对同一次切换的双信号归并）。
- `from/to` 只保留 sid 短串（前 8 字符）；空串/`"draft"` 原样记录。被淘汰的会话桶不影响记录——记录只存短串，不引用桶对象。

### 3.2 双窗口采集

每次切换记录一条（公开字段，`_` 前缀为内部状态）：

```
{ t, from, to, settled,
  afterMax2s, afterP95,            // 切换后 2 秒帧切片 max/p95
  lafN2s, styleMs2s,               // 2 秒窗口 ≥100ms 长帧次数 / 强制布局合计
  lafN30s, styleMs30s,             // 30 秒窗口同口径
  loadOlderN30s, loadOlderMs30s,   // 30 秒窗口成功补页次数 / 耗时合计
  domBefore, domAfter, turnsBefore, turnsAfter, blockedLoadAll }
```

- **live 累加，不回头扫环**：`lafDetail`/`loadOlderDetail` 都是 10 条 FIFO，切换后最早（往往最重）的条目会在结算前被挤出环；因此在三个记录点旁路累加——`rafTick`（2s 帧切片存原始毫秒数组，冻结时算 max/p95）、`recordLafDetail`（长帧）、`recordLoadOlderDetail`（补页）。
- **dom/turns 取缓存值**：`domBefore/turnsBefore` 取切换瞬间的缓存（DOM 为 60s 缓存、turns 为每采集周期刷新），**不在切换瞬间做 O(DOM) 扫描**——那会在最重的时刻插入几十毫秒长任务，违背「不影响用户体验」；`domAfter/turnsAfter` 冻结时同样取缓存，两侧新鲜度同量级，差值才有意义。任一侧无缓存时为 `null`。
- `blockedLoadAll`：冻结时 `bigBlocked - 记录时刻基线`（负数按 0）。
- 结算时机：懒结算——每次样本采集（`switchSnapshot()` 入口）对已过 30 秒的条目冻结（`settled=1`，补 after 值，停止累加）；未冻结条目样本里照常输出当前值，`settled=0`、`domAfter/turnsAfter/blockedLoadAll` 为 `null`。
- 依赖说明（均默认开）：`lafN*/styleMs*` 依赖 `lafDiagOn`（LoAF 观察器）；`loadOlderN30s/loadOlderMs30s` 依赖 `scrollDiagOn`（补页明细只在滚动诊断开时记录）。父开关关时对应字段为 0，不伪造。

### 3.3 环与样本

- `switchRing` 上限 10 条（FIFO），内容指纹（版本计数）不变时样本发 `[]`。
- 样本字段 `switch`：`switchDiagOn && !state.dead` 时为 `{ on:1, items:[…] }`（`items` 未变化为 `[]`）；关闭/自禁用/暂停时 `null`。旧样本无 `switch` 字段按「v0.4.3 前无此观测」处理，报告不回退。
- 切会话时（MO sid 变化）不清 `switchRing`（跨会话归因正是本观测的意义）；`resetWindow()` 不触碰它。

### 3.4 清理路径

- `switchDiagOn` 关闭：不再记录新切换，样本 `switch=null`；已有环保留在内存（重开可续用，不补录空白期）。
- 暂停观测：同上，`switch=null`。
- observer 自禁用 / `__lagfixOff()`：清空 `switchRing` 与去重时间戳。
- 不写任何 store、不加 DOM 属性、不挂新全局监听器（复用既有 rAF/MO/laf 环）。

## 4. O3 触发口径修复

### 4.1 门控替换

`makeProbedLoadOlder()` 的包装器内，O3 跳过判定改为：

```
isPaceScrollTrigger =
  !initialHit                               // 首调/挂载窗口豁免（见 4.2）
  && lastScrollAt > 0
  && performance.now() - lastScrollAt <= LOAD_OLDER_SCROLL_WINDOW_MS  // 与 classifyLoadOlderTrigger 同口径（2000ms）
```

- 删除 `paceInScrollDispatch` 同步标志及其赋值/清零点（scroll 监听器、自禁用、`applyScrollSettings`、`__lagfixOff()`）。
- `lastScrollAt`（performance.now 域）在滚动监听器里的刷新条件从「仅滚动诊断开」扩为「滚动诊断或 O3 任一开启」；`applyScrollSettings` 里滚动诊断关闭时，只有 O3 也关（或自禁用）才清 `lastScrollAt`。
- 其余不变：`rowsNow > PACE_MIN_ROWS` 才计时；`PACE_INTERVAL_MS` 内的滚动触发返回已结算 promise（不调原方法）；非滚动触发、小窗口原样放行。
- 代际门控（v0.4.2 S4）保留在最前。

### 4.2 首次调用豁免

- 豁免条件 = 包装器视角的首次调用（`callsInWrap === 0`，即本次调用前）或挂载窗口内（`attached && now - attached <= LOAD_OLDER_INITIAL_WINDOW_MS`），与 `classifyLoadOlderTrigger` 判 `initial` 的口径一致。
- 豁免的调用放行（调原方法）并照常计数为 `allowed`，不跳过——SessionPane 冷快照修复补拉依赖它补齐首 turn，宿主不重试被跳过的游标拉取。

### 4.3 计数双口径

- `paceStats`（store 生命周期口径，现状保留）：`{ allowed, skipped, lastAllowedAt }`，换 store/关→开/自禁用/`__lagfixOff()` 清零。
- 新增 `paceTotal`（全天累计）：`{ allowed, skipped }`，只在 observer 自禁用 / `__lagfixOff()` 清零；换 store、暂停观测、关→开实验开关都不清。
- 样本 `pace` 扩展：`{ minRows, intervalMs, allowed, skipped, totalAllowed, totalSkipped }`；旧样本无 `total*` 字段时报告回退只显示单口径并标注「旧样本无累计口径」。

### 4.4 A/B 门槛（不变，沿用 v0.3.4）

- 补页次数下降 ≥30%，滚动 P95/长任务不退化 >10%，顶部空白 ≤300ms，锚点漂移 ≤48px。
- `loadOlderPaceOn` 默认仍为关；口径修复后若实机 A/B 仍不达门槛，如实标注「已修口径仍未达门槛」，不默认开启。

## 5. O8b 补页批量退役

- 移除 `loadOlderPageLimitOn` 的行为实现：设置默认值、读写迁移、包装器内 O8b 分支（`LOAD_OLDER_PAGE_LIMIT` 常量与页大小改写）、`pageStats`/`resetPageStats`/`pageSnapshot`、面板「补页批量 · 实验」行、`applyScrollSettings`/`applyThrottle` 的安装条件项。
- `loadOlder` 包装器安装条件收敛为 `scrollDiagOn || loadOlderPaceOn`。
- 旧设置 `localStorage["lagfix.settings.v1"]` 含 `loadOlderPageLimitOn:true`：读入时忽略该键（不报错、不迁移、不写回 true→false 的迁移记录；下次保存自然消失）。
- `__lagfixOff()` 不再触碰该键。
- 报告兼容：旧日志样本含 `page` 计数的照常显示（前缀「已退役（v0.4.3）」）；新样本无 `page` 字段不显示该段。
- 测试断言更新：面板无该行；旧设置含该键不报错；包装器安装条件只剩两项。

## 6. 状态所有权与清理

- 设置仍是渲染端 `localStorage["lagfix.settings.v1"]` 唯一事实；新增键 `switchDiagOn`，退役键 `loadOlderPageLimitOn`（忽略）。
- `switchRing`/`paceTotal` 常驻 observer 内存，不进任何业务 store。
- `__lagfixOff()`、自禁用路径清理：
  - 清 `switchRing`、`lastSwitchRecAt`；
  - 清 `paceTotal`；
  - `paceInScrollDispatch` 相关代码已删除，无残留；
  - 其余还原边界沿用 v0.4.2（identity 规则、代际门控）。
- 暂停观测路径：`switch=null`、pace 计数不清（仅样本停发）。
