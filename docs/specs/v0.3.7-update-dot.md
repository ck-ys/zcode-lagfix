# v0.3.7 行为规格：更新提醒（小红点 + 可选自动检查）

- 版本：0.3.7
- 日期：2026-11-12
- 范围：检查更新的展示与触发时机；不改注入链、不改宿主数据、不改其他缓解项
- 拍板：用户在会话中选定「自动检查（默认关）」+「角标 + 维护页」两处红点；本页记录最终规则

## 1. 产品规则

### 1.1 手动检查（保持 v0.3.1 行为）

- 维护页「检查更新」按钮点击后置内存标记 `updateCheckRequested`，`updateCheckAuto=false`；下一个采集样本带 `updateCheck=1`、`updateAuto=0`，主进程据此请求一次公开 GitHub Releases。
- 手动检查不受自动检查开关影响；自动检查关闭时仍可手动检查。
- 点击后 15 秒内没有结果会恢复按钮文字，避免永久停在「检查中」；结果晚到仍会展示。
- 手动检查成功后同样刷新本机的 24 小时计时，并写入更新缓存；24 小时内的自动检查直接复用该结果，不再联网。

### 1.2 自动检查（`autoUpdateCheckOn`，默认关）

- 只有用户显式打开开关才会自动请求；默认关闭时插件不会因更新检查产生任何网络请求。
- 开启后，ZCode 启动或窗口打开后的第一个采集周期检查一次；本机 `lagfix.update.v1` 里的 `checkedAt` 在 24 小时内时不再自动请求。
- 任何一次检查（手动或自动）发出时都会写 `checkedAt`；因此手动失败后，自动检查也不会立即重试，用户可再次手动点击。
- 自动检查与「暂停观测」独立：暂停只停指标采集，不撤销用户对自动检查的开启；主进程仍按采集周期收到暂停样本里的 `updateCheck`。关闭开关或 `__lagfixOff()` 才会停止。
- 自动检查失败只影响维护页那一行提示，不弹窗、不改变其他开关、不影响角标统计。
- 请求"在途"标记最长保留 15 秒：面板关着时 `renderUpdateStatus` 不一定运行，超过 15 秒视为本轮丢失，下一次到期检查允许重试，不能让一个没送达的请求永久堵住自动检查。

### 1.3 小红点

- 显示条件（全部满足）：
  1. 缓存 `newer === true`；
  2. 缓存 `current === VERSION`（当前运行的插件版本）；
  3. 缓存 `latest` 非空且 `latest !== VERSION`。
- 位置：
  - 角标内、指标文字与齿轮之间；
  - 维护页「检查更新」行的标题右侧。
- 两处红点同源同显隐；缓存更新或跨窗口 `storage` 事件到达时立即同步。
- 以下情况一律不显示：`newer=false`、`latest` 与当前版本相同、缓存版本与当前版本不一致（例如刚升级后旧缓存未刷新）、缓存不存在或解析失败。
- 红点只表示「检查到新版本」，不表示已下载、已安装或已重启；插件不自动下载/安装。

## 2. 状态所有者

| 状态 | 所有者 | 生命周期 |
| --- | --- | --- |
| `autoUpdateCheckOn` | `localStorage["lagfix.settings.v1"]`（渲染端唯一事实） | 用户开关；`__lagfixOff()` 置 false |
| 检查结果缓存 | `localStorage["lagfix.update.v1"]` | 检查成功/发出时写入；`__lagfixOff()` 删除；升级后由 `current` 条件自然失效 |
| 在途标记 | observer 内存 `state.updateCheckRequested/updateCheckWaiting/updateCheckAuto/updateCheckSentAt` | 样本发出后清请求标记；结果到达或 15 秒后清等待标记 |
| 主进程去重 | 主进程内存 `lastAutoUpdateAt/lastUpdateInfo` | 进程生命周期；主进程重启后允许再查一次 |
| 红点 DOM | 角标 span + 维护页行内 span | 跟随面板重建；不写 React 树 |

`lagfix.update.v1` 只允许包含：`checkedAt`、`resultAt`、`current`、`latest`、`newer`、`url`。不得写入会话 id、提示词、回复、工具参数或任何用户数据。

## 3. 接口与样本

### 3.1 采集样本

- 新增/保持字段：
  - `updateCheck`: `1` 表示本样本请求检查一次，`0` 表示不请求；
  - `updateAuto`: `1` 表示本次请求由自动检查触发，`0` 表示手动或未请求；
  - `settings.autoUpdateCheckOn`: 当前开关值，便于报告排查。
- 暂停样本同样携带 `updateCheck` / `updateAuto`，语义与正常样本一致；`dead` 样本固定 `updateAuto=0` 且主进程不触发检查。
- 请求只随一个样本发出：发出后 `updateCheckRequested` 清零，后续样本为 0。

### 3.2 主进程注入结果

`window.__lagfixUpdate` 结构保持：

```json
{ "status": "ok", "current": "0.3.7", "latest": "0.4.0", "newer": true, "url": "https://github.com/...", "at": 1794444000000 }
```

失败时为 `{ "status": "error", "message": "...", "at": ... }`。

- 渲染端按 `at` 去重：`at <= resultAt` 的结果不再应用，避免跨窗口旧结果覆盖新结果。
- 错误结果只更新 `resultAt`，不清空已有的 `current/latest/newer`；已知有新版本的红点不会因一次临时失败而消失。
- 主进程缓存回放时把 `at` 标记为回放时刻（内容不变），避免接收端把旧结果误判成「本次请求还没回来」；渲染端仍按 `at` 去重。

### 3.3 主进程去重

- 自动请求（`updateAuto=1`）：
  - 24 小时内已有成功缓存 → 直接回放缓存，不联网；
  - 24 小时内已尝试但失败（无缓存）或另一次请求在途 → 静默跳过，不注入错误；
  - 否则联网一次，并开始 24 小时计时。
- 手动请求：保留 5 秒防连点；手动成功也刷新 24 小时计时并写入缓存，使后续自动检查复用。
- 网络边界保持：只允许 `https://api.github.com/repos/ck-ys/zcode-lagfix/releases`；重定向逐跳校验、最多 2 跳；总时限 10 秒；响应体上限 2MB；不带 Authorization/token。

## 4. 面板与文案

- 维护页新增「自动检查更新」开关，默认关。
- 说明按「会做什么 / 不会做什么 / 代价」组织：
  - 会做什么：启动或窗口打开时最多检查一次，24 小时内不重复；有新版本时角标与维护页出现小红点。
  - 不会做什么：不自动下载、不自动安装、不上报本机数据；只请求 GitHub Releases 的公开版本列表。
  - 代价：开启后会产生一次网络请求；失败只影响提示。
- 「检查更新」行状态文案：
  - 自动开启且从未检查：「尚未检查。自动检查已开启，24 小时内最多检查一次。」
  - 有缓存且版本匹配：显示上次结果（发现新版本 / 已是最新）；
  - 手动请求在途：显示「正在检查…」。
- 更新说明行的「复制安装口令」按钮保持原样；本版不实现下载/安装。
- 维护页新增「反馈问题」按钮：打开 `https://github.com/ck-ys/zcode-lagfix/issues/new?template=bug_report.yml`；优先调用宿主 `window.zcode.openExternal`，失败时退回 `window.open(..., "_blank", "noopener")`。不自动附带、上传或读取任何日志内容，日志由用户按模板检查后自行附加。
- README 新增「遇到问题」章节，说明先跑 `/lagfix report`、附 `main.log` 与最近一个 `observe-YYYYMMDD.jsonl`，并提示日志只含指标、不含消息正文；仓库新增 `.github/ISSUE_TEMPLATE/bug_report.yml`，把上述材料设为必填/确认项。

## 5. 清理与还原

以下三条路径必须生效：

1. 关闭「自动检查更新」开关：停止后续自动请求，保留已有缓存与红点（用户仍能看到上次结果），手动检查可用。
2. observer 自禁用（`state.dead`）：不排队自动检查，不再更新红点；不新增网络请求。
3. `__lagfixOff()`：
   - `settings.autoUpdateCheckOn=false` 并持久化；
   - 删除 `lagfix.update.v1`；
   - 清空 `window.__lagfixUpdate`；
   - 清空 `updateCheckRequested/updateCheckWaiting/updateCheckAuto/updateCheckSentAt`；
   - 置 `updateOffAt`：还原前已发出的在途结果即使晚到，也不写缓存、不显示红点/新版本文案；用户再次手动检查或重新开启自动检查时清零；
   - 角标与维护页红点立即隐藏；
   - 手动检查按钮仍可用（一键还原只关自动检查，不拆手动入口）。

面板重建、跨窗口设置同步、切换会话不得清空更新缓存或把红点状态重置为隐藏（除非缓存本身不满足显示条件）。

## 6. 验收场景

自动化（`tests/observe_smoke.mjs`）：

1. `autoUpdateCheckOn` 默认 false；默认关闭时样本 `updateCheck=0`、`updateAuto=0`。
2. 开启后 `checkedAt` 在 24 小时内不请求；超过 24 小时样本带 `updateCheck=1/updateAuto=1`；同一轮后续样本归零。
3. 手动检查样本带 `updateCheck=1/updateAuto=0`。
4. 注入 `newer=true/current=当前版本/latest=更高版本` 后，角标与维护页红点都显示；维护页显示新版本文案。
5. `newer=false`、`latest===current`、`current!==VERSION` 三种缓存都不显示红点。
6. 跨窗口 `storage` 事件到达时红点即时更新，无需重建面板。
7. `__lagfixOff()` 后自动检查关闭、缓存删除、两处红点隐藏。
8. 默认值快照、面板版本行、设置持久化与 localStorage key 白名单同步更新。
9. 「反馈问题」按钮存在；点击时优先调用宿主 `openExternal`，URL 为固定 issue 模板地址；无宿主桥时退回 `window.open`，不抛错。

自动化（`tests/update_check.mjs`）：

10. `updateAuto=1` 的到期请求正常发出并注入结果。
11. 手动成功后 24 小时内的自动请求复用缓存，请求数不增加。
12. 自动检查失败后 24 小时内不重复联网，也不重复注入错误。

实机验收（需要用户确认后安装）：

13. 开启自动检查，完全退出并重开 ZCode；维护页显示检查结果，有新版本时角标出现红点。
14. 关闭自动检查后重开，确认不再自动请求（GitHub 无新请求），手动检查仍可用。
15. 点击齿轮 → 维护，确认红点位置不遮挡文字/齿轮，面板窄宽度下不溢出；「反馈问题」能打开 issue 模板。

## 7. 明确不做

- 不自动下载、不自动安装、不自动重启 ZCode。
- 不后台常驻轮询，不做每小时/每次启动多次检查。
- 不把更新结果写进 `observe-*.jsonl`、会话、消息或工具结果；缓存只在本机 `localStorage`。
- 不改注入链、不改 `loadOlder` / `subscribe` / `loadAllOlder` 包装、不新增宿主 DOM 属性。
- 反馈入口只打开外部页面；不自动读取、打包或上传日志，不在插件内抓取会话内容。
- 不因为「有红点」就声称升级已完成；升级仍由用户执行安装口令并完全重开 ZCode。
