# v0.4.0 行为规格：第三方定时器归因（T1，默认关闭）

状态：已拍板（2026-11-12，用户确认 v0.4.0 推荐 A「T1 + U2 + O8b」后开始实现）。

## 1. 目标

回答「卡顿是不是外部插件的定时器心跳造成的」。只记录运行时间 ≥50ms 的
`setTimeout` / `setInterval` 回调，带上请求延迟、实际耗时、回调函数名和调用位置；
不改定时器时机，不拦截回调，不读回调参数或内容。

## 2. 开关与状态

| 项 | 值 |
| --- | --- |
| 设置键 | `timerDiagOn` |
| 默认 | `false` |
| 生效条件 | `timerDiagOn && observe && !state.dead` |
| 状态所有者 | 渲染端 `localStorage["lagfix.settings.v1"]`；不写 store |
| 报告字段 | 样本 `timer` |

关闭 `observe` 或开关关闭时，必须恢复原始 `setTimeout` / `setInterval`，
并清空计数与明细；重新开启从空开始。

## 3. 包装规则

1. 只包装函数类型的 handler；字符串 handler、非函数值原样放行。
2. 保存原始 `setTimeout` / `setInterval`，包装函数只调用原始方法；不得递归调用自身。
3. 保留调用参数（第三个及之后的参数）与 `this`；返回值必须是原始定时器 id。
4. `clearTimeout` / `clearInterval` 不包装；原始 id 直接可用。
5. 回调同步抛错时先记录耗时，再把原异常抛给宿主。
6. 包装器自身不得抛错；记录逻辑全部 try/catch。
7. 由 lagfix 自己调度的定时器（调用栈命中 `lagfix-observe` / `lagfix-main`）不包装、
   不记录，避免观测器测量自己。实现上插件内部调度统一走安装前的原始方法
   （`lafSetTimeout` / `lafSetInterval`）；调用栈检查只在回调确认 ≥50ms 后执行，
   避免每次调度定时器都解析调用栈。
8. 幂等：重复开启不能套两层；恢复时只还原仍指向本插件包装的全局方法。
9. 全局方法不可写 / 被宿主替换时降级：不生效，样本 `supported=0`，不得覆盖宿主实现。

## 4. 记录规则

- 阈值：同步执行耗时 `>= 50ms`。
- 每条明细字段：
  - `t`：回调开始时的 `Date.now()`；
  - `ms`：实际耗时（四舍五入）；
  - `delay`：请求的延迟/间隔（四舍五入，负数按 0）；
  - `kind`：`timeout` / `interval`；
  - `src`：回调函数名（`handler.name`），空则 `anonymous`；不含路径与源码；
  - `invoker`：调度调用点（函数名 + 文件名:行:列），去掉目录与协议，
    截断 120 字符；不含完整路径、查询串或源码。
- 明细环最多 10 条，超出丢最旧。
- `count` / `max` 是采集周期口径：每次 `__lagfixCollect` 后清零；`max` 为本周起最长。
- 明细未变化时样本发 `[]`；变化时发完整最近 10 条（与 `loadOlderDetail` 同约定）。

## 5. 样本

开关开启且观测中：

```json
"timer": {
  "supported": 1,
  "count": 2,
  "max": 96,
  "detail": [
    {"t": 179447..., "ms": 96, "delay": 100, "kind": "interval",
     "src": "bridgeTick", "invoker": "bridgeTick (overlay.js:13440:5)"}
  ]
}
```

- 开关关闭、观测暂停、自禁用：`timer=null`。
- 包装未装上：`supported=0`，`count/max` 为 0，`detail=[]`。
- 旧样本没有该字段：报告只提示，不推断。

## 6. 面板

观测页「诊断」组新增一行：

- 名称：**第三方定时器归因 · 实验**
- 说明：会做什么 / 不会做什么 / 代价，用户语言，不写 `setTimeout` 等内部词。
- 默认关闭；打开后立即安装，关闭后立即还原。

## 7. 报告

`/lagfix report` 新增一段：

- 关闭：提示「已关闭（实验项，默认关闭）」；
- 暂停：提示已暂停；
- 不支持/未装上：明确提示，不把 0 条说成没有卡顿；
- 开启：本周期次数/最长；最近 10 条明细（时间、耗时、请求延迟、类型、
  回调名、调用点）；按回调名聚合耗时 top 3。

## 8. 清理路径

以下三条路径必须恢复原始定时器并清空 `timerDetail`、`count`、`max`、明细版本：

1. 面板 / 跨窗口关闭 `timerDiagOn`；
2. `__lagfixOff()`；
3. observer 自禁用（`disable()`）。

暂停观测：恢复原始定时器并清空当前计数；恢复观测时按开关重新安装。

## 9. 明确不做

- 不修改、延迟、取消任何定时器；
- 不读回调参数、闭包内容、消息正文或会话数据；
- 不记录完整源码、完整路径、堆栈全文；
- 不联网、不写 `db.sqlite`、不开 CDP；
- 不把「抓到 ≥50ms 定时器」直接等同于「已找到卡顿根因」。

## 10. 验收

`tests/observe_smoke.mjs` 至少覆盖：

1. 默认 `timerDiagOn=false`，样本 `timer=null`；
2. 打开后 `setTimeout` / `setInterval` 被替换，关闭后恢复原引用；
3. 函数 handler 的参数、`this`、返回值、异常语义不变；
4. 回调 <50ms 不记录；≥50ms 记录 `ms/delay/kind/src/invoker`；
5. 字符串 handler 原样放行；
6. lagfix 自己的定时器不进入明细；
7. 明细最多 10 条，未变化发 `[]`；
8. 暂停、`__lagfixOff()`、自禁用三条路径都恢复并清空；
9. 样本 schema 在 dead/paused 路径仍带 `timer:null`。
