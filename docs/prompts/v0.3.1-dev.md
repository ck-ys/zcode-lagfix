## 0. 目标与边界

v0.3.1 只做两件事，路线 A：

1. **O1 滚动窗口观测**：把“滚动时到底慢在哪”变成日志里的数字。新增 `scrollP95`、滚动事件数、`loadOlder` 调用次数/耗时、挂载 turn 数、DOM 峰值、可选 long-animation-frame。
2. **O2 滚动期临时关闭消息层遮罩**：滚动时给 `documentElement` 加 `data-lagfix-scroll="1"`，180ms 无滚动后移除；CSS 只覆盖 `[data-v4-timeline-message-layer="true"]` 的 `mask-image`。这是可 A/B 的缓解项，默认开、可单独关。

明确不做：

- 不做 O3 `loadOlder` 合并/延迟（有分歧，默认关，留给后续分支）。
- 不做 O4 turn 内部 `content-visibility`（实验项，默认关，留给后续分支）。
- 不做 O5 轻量模式、O6 turn 内部再虚拟化、O7 多会话调度。
- 不修改消息、会话、工具卡内容，不折叠/隐藏任何用户可见内容。
- 不读写 `db.sqlite`，不开 CDP，不联网上报，不碰真实安装目录。

## 2. 先写 spec

新增 `docs/specs/v0.3.1-scroll.md`，写清：

- 产品规则：O1 只观测；O2 只在滚动期间临时去掉消息层 mask，停止滚动 180ms 后恢复；两项都可单独关闭。
- 状态所有者：`localStorage["lagfix.settings.v1"]` 仍是唯一设置事实；滚动诊断状态只存在于 observer 内存；不写 store、不写会话。
- 接口：`__lagfixCollect()` 新增 `scroll` 对象；`settingsSnapshot()` 新增 `scrollDiagOn`、`maskOffOnScroll`；设置面板新增两行。
- 事件顺序：scroll capture → 更新 `lastScrollAt`/计数 → rafTick 把 200ms 内的帧计入 scrollRing → collect 输出；scroll → 加属性 → 180ms idle 定时器 → 移除属性。
- 失败/关闭路径：设置关闭、observer 自禁用、`__lagfixOff()`、页面卸载都要移除属性、清定时器、还原 `loadOlder` 包装。
- 验收场景：见第 7 节。

## 3. 实现 O1：滚动窗口观测

文件：`plugins/zcode-lagfix/lagfix-observe.js`

### 3.1 设置

在 `DEFAULTS`（约 67 行）增加：

```js
scrollDiagOn: true,   // v0.3.1 滚动窗口观测
maskOffOnScroll: true,// v0.3.1 滚动期临时关闭消息层 mask
```

在 `mergeStored()`（约 93 行）增加两个布尔合并：

```js
if (typeof o.scrollDiagOn === "boolean") s.scrollDiagOn = o.scrollDiagOn;
if (typeof o.maskOffOnScroll === "boolean") s.maskOffOnScroll = o.maskOffOnScroll;
```

在 `settingsSnapshot()`（约 2351 行）加入这两个字段。

### 3.2 滚动采样

新增模块级状态：

```js
var scrollRing = [];        // {t, ms}，只保留最近 30s
var scrollEvents = 0;       // 当前采集周期内的合格滚动事件数
var lastScrollAt = 0;       // performance.now()
```

在 `rafTick(t)`（约 284 行）记录帧时，如果 `settings.scrollDiagOn && lastScrollAt && t - lastScrollAt <= 200`，把这一帧的 `ms` 推进 `scrollRing`，并限制长度（可复用 `RING_MAX` 或单独 600）。注意：

- 只统计“最近 200ms 内有滚动”的帧，不要把所有帧都算进 `scrollP95`。
- `document.hidden` 时仍按现有逻辑不采样。
- 不要为此新增第二个 rAF 循环。

新增一个 capture 阶段的 scroll 监听（只装一次）：

```js
document.addEventListener("scroll", onTimelineScroll, true);
```

`onTimelineScroll` 必须过滤目标：

```js
var el = ev && ev.target;
if (!el || typeof el.matches !== "function") return;
if (!el.matches('[data-v4-timeline-scroll="true"]')) return;
lastScrollAt = performance.now();
scrollEvents++;
```

不要用 `closest()` 向上找，滚动事件的 target 就是滚动容器；不要监听 window 的 scroll 冒充时间线滚动。

### 3.3 loadOlder 观测包装

新增 `applyLoadOlderProbe(store)`，参考 `applyLoadAllGuard`（约 2063 行）的写法，但**只观测、不拦截、不延迟**：

- 找目标：`hasOwnProperty(store, "loadOlder") ? store : Object.getPrototypeOf(store)`。
- 已经有 `target.__lagfixLoadOlder` 就复用，不能套两层。
- 包装函数必须保留 `this` 和原始返回值：

```js
function makeProbedLoadOlder(orig) {
  return function () {
    var t0 = performance.now();
    loadOlderCalls++;
    var ret;
    try {
      ret = orig.apply(this, arguments);
    } catch (e) {
      loadOlderErrors++;
      throw e;
    }
    if (ret && typeof ret.then === "function") {
      ret.then(
        function () { recordLoadOlder(t0); },
        function () { loadOlderErrors++; recordLoadOlder(t0); }
      );
      return ret; // 必须返回原 promise，不要用 .then 包一个新 promise
    }
    recordLoadOlder(t0);
    return ret;
  };
}
```

`recordLoadOlder(t0)` 把 `performance.now() - t0` 推进 `loadOlderRing`（30s 窗口），更新 `loadOlderMax`。

- 在 `attach()` 或现有 store 发现路径里调用 `applyLoadOlderProbe(store)`；如果 `settings.scrollDiagOn` 为 false，不包装。
- 释放函数 `releaseLoadOlderProbe()`：遍历所有被包装的 target，恢复 `orig`，删除 `__lagfixLoadOlder`；在设置关闭、自禁用、`__lagfixOff()` 时调用。
- 不要改 `loadOlder` 的参数、页大小、返回值或异常。

### 3.4 挂载 turn / DOM 峰值

在 `__lagfixCollect()` 里：

- `mountedTurns = document.querySelectorAll('[data-v4-turn-unit="true"]').length`。
- 现有 `domCount` 在大会话下降频到 60s；开启 `scrollDiagOn` 时改为每个采集周期统计一次（默认 5s）。如果实测这次全量计数本身超过 5ms，在注释里说明，并考虑只数 message layer 子树；不要为了观测制造新的长任务。
- 维护 `domPeak`：当前采集周期内见过的最大 DOM 数，collect 后重置。
- 可选：`PerformanceObserver` 支持 `long-animation-frame` 时，统计滚动窗口内的 `lafCount`/`lafMax`；不支持就静默跳过，不要报错。

### 3.5 payload

`__lagfixCollect()` 的正常 payload 增加：

```js
scroll: {
  p95: <scrollRing 30s P95>,
  max: <scrollRing 30s 最大>,
  events: scrollEvents,
  frames: <scrollRing 长度>,
  loadOlderCalls: loadOlderCalls,
  loadOlderP95: <loadOlderRing P95>,
  loadOlderMax: loadOlderMax,
  loadOlderErrors: loadOlderErrors,
  mountedTurns: mountedTurns,
  domPeak: domPeak,
  lafCount: lafCount,
  lafMax: lafMax
}
```

- dead / paused 的廉价 payload 也带 `scroll: null`，保持 schema 稳定。
- `scrollEvents`、`domPeak`、`lafCount` 在 collect 后重置；`scrollRing`/`loadOlderRing` 用 30s 时间窗，不要每次 collect 清空。
- 如果 `scrollDiagOn` 为 false，`scroll` 返回 `null`，不要做额外 DOM 扫描。

### 3.6 面板

- 观测页新增一行“滚动诊断”，开关绑定 `scrollDiagOn`，说明写：只记录滚动帧 P95、补页次数/耗时、挂载 turn 数；不改变滚动行为。
- 修复页新增一行“滚动期关闭消息层遮罩”，开关绑定 `maskOffOnScroll`，说明写：滚动时临时去掉消息层上下渐隐遮罩，停止 180ms 后恢复；不影响消息内容和滚动位置。
- 两行都要有现有的「!」说明入口，文案写“影响什么 / 不影响什么”。
- 面板底部版本行改成 `v0.3.1`。

## 4. 实现 O2：滚动期关闭消息层遮罩

### 4.1 CSS

在 `ensureStyle()`（约 597 行）追加：

```css
[data-lagfix-scroll="1"] [data-v4-timeline-message-layer="true"] {
  -webkit-mask-image: none !important;
  mask-image: none !important;
}
```

只覆盖 `mask-image`，不要覆盖整个 `mask` 简写，避免把宿主的其它 mask 属性一起重置。不要改 `[data-v4-timeline-scroll]` 容器本身。

### 4.2 属性生命周期

新增：

```js
var scrollMaskTimer = null;
function setScrollMaskActive(active) {
  try {
    var root = document.documentElement;
    if (!root) return;
    if (active && settings.maskOffOnScroll && !state.dead) {
      root.setAttribute("data-lagfix-scroll", "1");
      if (scrollMaskTimer) clearTimeout(scrollMaskTimer);
      scrollMaskTimer = setTimeout(function () {
        scrollMaskTimer = null;
        try { root.removeAttribute("data-lagfix-scroll"); } catch (e) {}
      }, 180);
    } else {
      if (scrollMaskTimer) { clearTimeout(scrollMaskTimer); scrollMaskTimer = null; }
      root.removeAttribute("data-lagfix-scroll");
    }
  } catch (e) {}
}
```

在 `onTimelineScroll` 里调用 `setScrollMaskActive(true)`。设置关闭时调用 `setScrollMaskActive(false)`；`__lagfixOff()`、observer 自禁用、页面 `pagehide`/`beforeunload` 也要清理。

注意：

- `maskOffOnScroll` 关闭时，即使还在滚动也不能加属性；已经加了要立刻移除。
- 180ms 是 idle 恢复时间，不要用 debounce 把整个滚动过程拖到停止才第一次生效；第一次滚动就要立刻加属性。
- 不要用 `requestAnimationFrame` 每帧写属性；只在 scroll 事件里写一次，然后靠 180ms 定时器移除。
- 如果宿主未来把 mask 改成 CSS 变量/伪元素，这个选择器会失效；在注释里标注依赖 `data-v4-timeline-message-layer` 与内联 `mask-image` 的现状。

## 5. 清理与开关

必须覆盖四条路径：

1. 用户在面板关掉 `scrollDiagOn`：释放 `loadOlder` 包装，清空滚动计数；如果 `maskOffOnScroll` 还开着，滚动遮罩仍可工作。
2. 用户关掉 `maskOffOnScroll`：立刻移除 `data-lagfix-scroll`，清定时器。
3. `__lagfixOff()`：把 `scrollDiagOn`、`maskOffOnScroll` 设为 false，保存设置，释放 `loadOlder` 包装，移除属性，清定时器；不要影响已有的 throttle/bigSession 还原逻辑。
4. observer 自禁用 / `state.dead`：移除属性，清定时器，释放包装，停止 scroll 监听（或让监听 early-return）。

不要新增无法释放的全局监听器；scroll 监听只装一次，用 `settings.scrollDiagOn || settings.maskOffOnScroll` 判断是否工作。
